## ⚠️ Первым делом: утвердить цены (без этого продукты не создать)

Артём назвал 27.08 ориентир **2 890 ₽ в год и 399 ₽ в месяц**. Базовыми их поставить НЕЛЬЗЯ —
проверено 27.08 по справке Google:

- **Валюта разработчика у аккаунта из Беларуси — USD** (справка «Поддерживаемые страны для
  регистрации разработчиков и продавцов»: Беларусь — регистрация продавца ✔, валюта по умолчанию USD).
  Базовая цена задаётся в USD, цены в остальных странах Google пересчитывает сама.
- **В России подписки через Google Play не работают вообще** — ни покупок, ни продлений
  (справка «Изменения в платёжной системе Google Play для пользователей из России и Беларуси»).
  То есть рублёвая цена никому в России выставлена не будет: рубли — только мысленный ориентир.
- **В Беларуси подписка внутри БЕСПЛАТНОГО приложения работает** — блокируются платные приложения,
  а покупки и подписки внутри бесплатных не блокируются. Arcanum бесплатный, значит белорусы купить
  смогут.

**Пара, сохраняющая задуманную скидку.** Отношение Артёма: 2890 / (399 × 12 = 4788) = 0.604, то есть
годовая дешевле месячной ×12 на **39 %**. В долларах ту же пропорцию даёт **$4.99 в месяц и
$35.99 в год** (1 − 35.99/59.88 = 39.9 % → бейдж покажет «−39 %»). Ориентир мастер-плана для месяца
был как раз $4.99.
⚠️ Бейдж скидки в приложении считается из ФАКТИЧЕСКИХ цен магазина и округляется вниз; если пара
в какой-то стране разъедется по пропорции, бейдж просто изменится или не покажется — врать не станет.

**Спроси Артёма и зафиксируй ответ, прежде чем что-то создавать:** берём $4.99 / $35.99 или он
называет другую пару. Заодно спроси про страны продаж (по умолчанию — все страны трека, 177).

## Что сделать, по порядку

### 1. RevenueCat

- Аккаунт на `revenuecat.com` (Артём), проект `Arcanum`, приложение Google Play с идентификатором
  `app.arcanum.tarot`.
- Service-account JSON для проверки покупок — по мастеру RevenueCat: Google Cloud → сервисный
  аккаунт → в Play Console «Пользователи и разрешения» выдать ему права на финансовые данные
  и управление заказами. Мастер RevenueCat проведёт по шагам; JSON загружается в RevenueCat.
- RTDN (Pub/Sub) — RevenueCat рекомендует, но не блокирует; если мастер предложит, включить.

### 2. Продукты в Google Play Console

Монетизация с Google Play → Подписки → создать подписку:
- идентификатор подписки: `premium`;
- базовые планы: `year` (годовой, автопродление) и `month` (месячный, автопродление);
- цены по утверждённой паре; **без вводных предложений и пробного периода** — решение Артёма 27.08;
- активировать оба плана.

### 3. Связать в RevenueCat

- entitlement `premium` ← продукты `premium:year` и `premium:month` (формат Google «подписка:план»);
- offering `default` (сделать current) с пакетами `$rc_annual` → `premium:year`,
  `$rc_monthly` → `premium:month`.
⚠️ Код НЕ знает идентификаторов продуктов: он берёт `offering.annual` / `offering.monthly` и право
по имени `premium`. Ошибиться можно только в этих трёх именах.

### 4. Лицензионный тестер

Play Console → Настройки → Лицензионное тестирование → добавить аккаунт Артёма (и второй, если
появится). Тестовые подписки продлеваются ускоренно: месячная каждые 5 минут, годовая каждые 30,
после шести продлений гаснут сами.

### 5. Ключ в сборку

```
npx eas-cli@latest env:set --name EXPO_PUBLIC_RC_ANDROID_KEY --value goog_… \
  --environment production --environment preview --visibility plaintext
```
Ключ берётся в RevenueCat → Project → API keys (публичный ключ Android, начинается на `goog_`).
Локально в `.env` он не нужен: в Expo Go SDK не конфигурируется намеренно.
Проверить: `npx eas-cli@latest env:list --environment production` показывает переменную.

### 6. Анкета «Безопасность данных» — ДО заливки сборки с SDK

Play Console → Контент приложения → Безопасность данных. Новая собираемая категория —
**«История покупок»**: собирается — да, цель «Работа приложения», третьим лицам как продавцу
НЕ передаётся (RevenueCat — поставщик услуг по своему же гайду «Google Play's Data Safety»).
Формулировки — `docs/release-checklist.md`, пункт про подписку.
⚠️ Это обязано быть сделано ДО отправки сборки с SDK в любой трек: сейчас в треке лежит сборка
без покупок, и анкета честно говорит «данные не собираются».

### 7. Сборка и заливка

```
npx eas-cli@latest build -p android --profile production --non-interactive
```
До заливки проверить, что ключ доехал в бандл:
```
python -c "import zipfile,sys; print(b'goog_' in zipfile.ZipFile(sys.argv[1]).read('base/assets/index.android.bundle'))" <файл.aab>
```
Ожидается `True`. Без ключа сборка честно деградирует в «Оформить подписку пока нельзя» — то есть
релиз, который НЕ умеет продавать, выглядит рабочим. Это главная ловушка захода.
AAB кладёт в консоль Артём руками: артефакт EAS отдаётся без CORS.
⚠️ Заливать в тот же трек Alpha можно смело: **новая сборка НЕ сбрасывает 14-дневный отсчёт**
закрытого теста (Google считает дни подписки тестировщиков, а не версию сборки) — проверено 27.08.

### 8. Лайв-проверка 6в

Сценарий целиком — в конце `docs/specs/53b-revenuecat.md`, раздел про лайв. Коротко: два тарифа
с ценами магазина → покупка месячного тестовой картой → панель «Месячная подписка · Продлится …»
→ М3 открыт, «Ещё N» работает → «Управлять подпиской» ведёт в подписки Play → отмена там → через
≤5 минут после сворачивания панель говорит «Действует до …» → после ~30 минут право снимается само
→ удалить/поставить → «Восстановить покупки» вернуло право → в авиарежиме приложение живёт.
Отдельно проверить: **бессрочное промо-право** (выдаётся из консоли RevenueCat) показывает
«Подписка активна», а не «DEV-режим», и что **оба базовых плана доступны** в целевых странах —
витрине нужна пара, иначе экран покажет «скоро».

После зелёного лайва — влить `feat/53b-revenuecat` в main и закрыть задачу 53 в бэклоге.
