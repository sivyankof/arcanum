**Как работать:**
- Все четыре задачи — в `main` (мелкие/контентные/аудит), коммиты поимённым `git add <путь>`.
- Subagent-driven: механические шаги — **sonnet**-сабагенты с явной моделью (скрипт иконки, тесты,
  съёмка скриншотов, парсер store-listing); разбор 35 вопросов 28р и вынесение вердиктов — opus
  (эта сессия) или sonnet по модулю целиком с контекстом урока; слепой решатель 28р — свежий sonnet
  без доступа к репо (только текст вопроса и варианты). Ревью после каждой задачи — сверка с спекой.
- После каждого шага с кодом — `npx tsc --noEmit`; перед push — `npm test` зелёный. Новый тест
  обязан краснеть на сломанном коде — мутации из спек выполнить и описать в коммите.
- 55: после `npx expo install …` прочитать `git diff package.json app.json`; `app.json` меняется
  только блоком `plugins` (шаг 3). Сказать Артёму: «нужен `npm install` и перезапуск `--tunnel`».
- 28р: **сначала** `scripts/check_quiz_guess.py` и его калибровка на HEAD (0 сигналов), потом
  вердикты, потом правки. Правка списком запрещена; правятся только дистракторы ru/en; es/pt не
  трогать; JSON писать python-скриптом (indent 1, `ensure_ascii=False`), PowerShell к файлам не
  подпускать; после правок — `merge_quiz.py`, оба слоя, `check_canon --scope course` (≤233),
  `check_edits.py` по `docs/specs/28r-changed-addresses.md`, `npm test`. Промт Cowork
  `docs/prompts/28r-es-pt.md` и задача 28с в бэклоге — обязательный выход.
- 56: dev-сервер заново с `--clear`; Playwright из кэша npx (команда в `AGENTS.md`); сид через
  `goto → evaluate → reload`; `click({ force: true })` на качающихся элементах; красный прогон
  скрипта съёмки (неверный маршрут обязан уронить, а не отснять пустоту). Чинить по макету — только
  сверив с product-spec/design-system (6а-0); порог «чиним здесь» ≤30 строк; остальное — задачи 58+.
- 57: факты о приложении — только из кода/product-spec, с источником у каждого; запрещённые слова

- Коммиты русские, без упоминаний ИИ, по шагу плана: `chore:`/`refactor:`/`feat:`/`content:`/`docs:`
  с `(спека NN)`. Push после зелёных тестов.
- Документы по закрытии каждой задачи: backlog (`[~]` до лайва Артёма, затем `[x]`), changelog,
