⚠️ **Дефект уровня корпуса не видит ни один автор и ни один редактор отдельного текста.**

разных имени одной карты на одном экране.

«станьте той», «понял(а)», «мамой команды», «мыслите как хозяин», «обнимите первой», «я рада, что

агентов. Оба слоя нужны, ни один не заменяет другой (подтверждение урока задачи 25).

125. `рак` без границ слова ловил «брак», `illness` — «stillness», «обеща» — «обещания звучат
красиво» вместо «карта обещает». Отрицание при этом законно и даже полезно: «Крупных сумм карта
НЕ обещает» снимает рамку предсказания, а не ставит её.

нарушением 73 нормальных русских текста — русский короче английского на 20–25% (медиана `career`:
ru 36 слов, en 45). Нормы разведены по языкам в content-guide. Оставшиеся 49 отклонений настоящие:

(титулы уровней остаются женскими — это звание игрока, другой жанр); **зачин-указатель сферы**

## 59 · Настройки: строки «Имя» и «Дата рождения» (23.08)

Пробел против `product-spec` §5, найденный аудитом 56: спека требовала строку «Имя и дата
рождения (редактирование)», а в приложении её не было. Имя не менялось нигде — экшена `setName`

один раз и только пока она пустая (тап карточки аркана на профиле занят переходом на страницу
карты). Спека — `docs/specs/59-name-birthdate.md`.

**Сделано.** Две строки настроек между «Напоминаниями» и «Экспортом»: «Имя» (значение — имя
или «Не указано») и «Дата рождения» (дата или «Указать»). Имя правится новым общим компонентом
`TextPrompt` (ModalPanel + поле + «Отмена»/«Сохранить» в геометрии `ConfirmDialog`) — диалога
с текстовым полем в проекте не было, `TextInput` жил только инлайн внутри экранов. Дата —
существующий `DatePicker`: у него уже был проп `value`, то есть режим «сменить заданную дату»
был поддержан и просто нигде не использовался.

**Решение по входам.** Второго входа к смене даты из профиля не делали: тап карточки аркана
уже занят навигацией, а два входа к одному действию — лишняя развилка. Так закрылся вопрос,
записанный в бэклоге при заведении задачи.

**Две строки вместо одной — расхождение со спекой продукта по 6а-0.** `product-spec` §5
перечисляет пункт одной строкой; у строки настройки справа ровно одно значение, поэтому
объединённая показывала бы половину состояния. Решение Артёма 23.08, формулировка в product-spec
переписана под две строки.

**Общее, что выросло из задачи.** `NAME_MAX = 40` и `normalizeName` живут в `birthArcana.ts`
рядом с `Profile`, сама нормализация — вызов существующего `normalizeText` из `journal.ts`,
своего `trim().slice()` не появилось. `buildProfile` начал звать её же: до этого онбординг длину
имени не ограничивал вовсе — та же дыра, просто с другой стороны.

⚠️ **Пустое имя обязано УДАЛЯТЬ ключ, а не писать пустую строку.** Заголовок профиля читает
`name ?? tr('profile.title')`, и `''` показал бы пустоту вместо «Профиль». Спред `{...profile,
name: undefined}` этого не делает — ключ остаётся; экшен собирает объект заново. Тест проверяет
`'name' in profile`, а не сравнение с `undefined`: на сравнении реализация со спредом прошла бы.

**persist не поднимался** (поля уже в схеме `Profile`), валидатор бэкапа не трогали: добавить
туда `NAME_MAX` значило бы отвергать целиком бэкап пользователя со старым длинным именем.

**Проверки.** `tsc` чист, `npm test` — **1695 тестов в 46 сьютах** (+12: `setName`, `normalizeName`,
`buildProfile`, смена уже заданной даты). Красный прогон юнитов — три мутации, каждая красит
свои проверки: спред вместо пересборки ключа, `normalizeName` без обрезки длины, `buildProfile`

## 64 · `ACTIVITY_RECOGNITION` в манифесте Android — 27.08.2026 (в работе)

При закрытии задач Play Console единственным открытым остался пункт «Здоровье». Форма
объяснила причину сама: «Ваше приложение использует разрешение `android.permission.ACTIVITY_RECOGNITION`
и должно соответствовать правилам для приложений для здоровья. Если функций нет — удалите
разрешение из манифеста». Разрешение приносит `node_modules/expo-sensors/android/src/main/AndroidManifest.xml`
(одна строка, ради `Pedometer`); в коде из `expo-sensors` используется только `DeviceMotion`
(`useDeviceTilt`). Ответ «функций нет» сдать нельзя — «Далее» без выбранных функций неактивна.

Правка: `expo.android.blockedPermissions: ["android.permission.ACTIVITY_RECOGNITION"]` в `app.json`
(по докам SDK 54 — `tools:node="remove"` при prebuild). Страж `src/lib/__tests__/androidPermissions.test.ts`
держит три факта: разрешение заблокировано; `expo-sensors` действительно его добавляет (иначе строка
мёртвая); `Pedometer` в `src/`/`app/` не используется (иначе блокировка ломала бы фичу молча).
Проверка результата — манифест нового AAB (`zipfile` → `base/manifest/AndroidManifest.xml`, регулярка
по `android.permission.*`): в сборке `versionCode` 2 было 13 разрешений, среди них лишнее.

⚠️ Урок: декларации контента консоль включает **по манифесту сборки**, а не по описанию приложения —
поэтому список «что сдавать» из release-checklist полон только после первой залитой сборки.
Попутно в том же манифесте: `SYSTEM_ALERT_WINDOW`, `DUMP`, `READ/WRITE_EXTERNAL_STORAGE` —
декларации не требуют, разобрать отдельно.

**Итог 27.08 (вечер): задача 64 ЗАКРЫТА.** Сборка `production` №3 (id `f7ee427c`, 16 мин,
`versionCode` 3, коммит `cc2d2c8`): манифест — 12 разрешений, `ACTIVITY_RECOGNITION` отсутствует
(проверено `zipfile` до заливки); в логе «Uploading to EAS Build (0 / 28.7 MB)» — `.easignore`
подтверждён на живой сборке (заливка 7 с вместо 37). Артём положил AAB руками, выпуск 3 (1.0.0)
опубликован во внутреннем треке, «Контент приложения» → **«Все декларации заполнены»**, пункт
«Здоровье» исчез с панели. Следующий шаг консоли по её же подсказке — закрытое тестирование.
