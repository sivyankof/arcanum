## Цель

Сборки приложения делаются одной командой из репозитория: Android APK для проверки на
устройстве и AAB для закрытого тестирования Google Play; iOS — как только Apple одобрит
аккаунт разработчика (кейс поддержки, release-checklist).

## Что делаем

- Expo-аккаунт `art9` (регистрация через GitHub, пароль задан для CLI). Проект EAS
  `@art9/arcanum` создан `eas init --account art9 --non-interactive --force`: в `app.json`
  появляются `owner` и `extra.eas.projectId` — это привязка репозитория к проекту в облаке,
  без неё `eas build` не знает, куда класть сборку.
- `eas.json` с двумя профилями:
  - **`preview`** — `distribution: internal`, Android → **APK** (ставится на телефон файлом,
    без магазина), iOS → устройство (ad hoc, нужен Apple-аккаунт и UDID iPhone через
    `eas device:create`). Это профиль лайв-проверок на сборке — там, где Expo Go слеп
    (иконка приложения, иконка пуша Android, виджеты, покупки).
  - **`production`** — Android → **AAB** (Google Play принимает только его), `autoIncrement`
    поднимает номер сборки сам. Профиль закрытого тестирования и релиза.
  - `appVersionSource: remote` — `versionCode`/`buildNumber` живут в EAS, а не в `app.json`:
    номер растёт с каждой сборкой без коммита, `version` 1.0.0 в `app.json` остаётся ручным.
  - `cli.version >= 22.4.0` — версия, на которой конфигурация написана; более старый CLI
    откажется собирать вместо того, чтобы молча понять поля иначе.
- Первая Android-сборка `preview`: `npx eas-cli build -p android --profile preview`.
  ⚠️ **Только интерактивно и только Артёмом**: при первой сборке EAS генерирует keystore
  подписи Android и в `--non-interactive` это запрещено (`Generating a new Keystore is not
  supported in --non-interactive mode`). Keystore хранится в EAS, в репозиторий не попадает;
  последующие сборки сессия запускает сама с `--non-interactive`.

## Что НЕ делаем

- **`development`-профиль (dev client)** — требует пакет `expo-dev-client` (правка
  `package.json`), а пока в проекте нет нативных модулей вне Expo Go, он не нужен. Появится
  вместе с RevenueCat в 53б, где без него не обойтись.
- **EAS Update / `runtimeVersion`** — OTA-обновлений в v1 нет; `runtimeVersion` без
  `expo-updates` бессмыслен. Решение можно пересмотреть в v1.1.
- **`eas submit`** — нужны сервисный аккаунт Google Play и App Store Connect API key,
  их выдают одобренные аккаунты магазинов. Секция `submit.production` оставлена пустой
  как место для них.
- Глобальная установка `eas-cli` — команды идут через `npx eas-cli@latest`, чтобы не менять
  окружение машины; Артём может поставить глобально по своему желанию.

## `.easignore` — что уезжает в архив сборки (добавлено 26.08.2026)

Первая сборка показала в логе: «Compressed project files 23s (305 MB)». Архив тащил всё
рабочее дерево — 130 МБ скриншотов веб-проверок в `docs/screenshots/`, 67 МБ кэша сканов
Commons в `.cache/`, спеки, планы, python-конвейер. На размер APK это не влияет (Metro
бандлит только то, что импортируется), но каждая сборка платит этим временем на сжатие
и заливку.

Заведён `.easignore` в корне. Сборке нужны ровно `app/`, `src/`, `assets/`, `content/`
и корневые конфиги — проверено грепом: код приложения импортирует только `assets/`
и `content/`, ссылок на `docs/`, `site/`, `scripts/` из рантайма нет, хуков сборки
(`postinstall`, `eas-build-pre-install`) в `package.json` тоже нет.

⚠️ **Главная ловушка файла.** Если `.easignore` существует, EAS **перестаёт читать
`.gitignore` вообще** — не дополняет, а заменяет целиком
(`https://expo.fyi/eas-build-archive`: «if it is present, none of the existing .gitignore
files will be respected by EAS CLI»). Значит все секретные шаблоны — `*.jks`, `*.p8`,
`*.p12`, `*.key`, `*.pem`, `*.mobileprovision`, `.env`, `.env*.local` — обязаны быть
продублированы в нём, иначе keystore и переменные окружения уедут на серверы сборки.
Правишь `.gitignore` — проверь, не нужно ли то же правило здесь. `node_modules` из рабочей
папки EAS не копирует никогда; про `.git` это НЕ так — см. «Подтверждение 27.08» ниже.

**Замер.** Было 1203 файла / 229.7 МБ на диске → уедет 300 файлов / 31.7 МБ, то есть
исключено 903 файла (198 МБ). Целостность проверена поимённо: `assets/cards` 78 из 78,
`assets/fonts` 1 из 1, `assets/images` 5 из 5, `content` 10 из 10, `app` 19 из 19,
`src` 176 из 176; обязательные корневые конфиги на месте.

**Как проверять.** Матчер брать у самого git, а не писать свой: поднять пустой временный
репозиторий, положить туда `.easignore` под именем `.gitignore` (ровно схема EAS — один
файл правил в корне) и спросить `git check-ignore --stdin -z` про пути проекта. Рабочее
дерево при этом не трогается: `check-ignore` работает со строками путей, файлам
существовать не обязательно. ⚠️ Обмен только через `-z`/`\0`: на Windows Python подменяет
`\n` на `\r\n` при записи в stdin, git принимает `\r` за часть имени файла и начинает
экранировать пути кавычками — проверка молча перестаёт находить совпадения.
⚠️ `git check-ignore` НЕ понимает `--exclude-from` (это опция `ls-files`) — с ней он
исключает ноль файлов и прогон выглядит успешным.

**Красный прогон.** Три мутации, все пойманы: `content/` в правилах → «потеряны
обязательные файлы, потери в content»; `assets/cards/` → «потери в assets/cards»; снятая
строка `*.jks` при подложенном в корень файле-приманке → «утечка секретов».

**Подтверждение 27.08 — расчёт не сошёлся с логом.** Первая `production`-сборка
(id `62152db3`) показала «Your project archive is 180 MB» при расчёте 31.7. Разбор по
исходнику `eas-cli` 22.6 (`build/vcs/clients/git.js`, `build/vcs/local.js`,
`build/build/utils/repository.js`): у архива **два источника**, а страж моделировал один.
EAS делает `git clone --no-checkout --no-hardlinks --depth 1` рабочего репозитория (файлов
в копии нет, но есть `.git` с упакованным деревом HEAD — у нас **152 МБ**, потому что 119 МБ
tracked-скриншотов в `docs/screenshots/` не сжимаются), затем копирует рабочую папку по
правилам `.easignore` через npm-пакет `ignore`, и `tar.create('.')` без фильтра берёт всё.
`.git` клона удаляется **только если правила исключают строку `.git` буквально** — eas-cli
спрашивает `ignores('.git')` без слэша, и правило `.git/` (только каталоги) её не матчит;
`git check-ignore` в нашем матчере `.git/` принял бы, поэтому эта строка проверяется
разбором файла правил (`git_metadata_rule`), а не через git. Пакет `ignore` 5.3 обратные
слэши Windows понимает — файлы внутри `docs/`, `.cache/`, `scripts/` он отсеивал верно,
«лишние» 150 МБ были целиком `.git`.

**Воспроизведение без траты сборки** — функцией самого eas-cli `makeProjectTarballAsync`
(`resolveVcsClient(false)`), то есть ровно тем кодом, что идёт перед заливкой: без строки
`.git` — **181.0 МиБ** (из них `.git` 152.3, `assets` 27.4, `content` 2.6), со строкой —
**28.7 МиБ**. Правка: одна строка `.git` в `.easignore` (без слэша) + исправлен ложный
комментарий «`.git` EAS исключает сам». Страж дополнен: печатает «.git shallow-клона:
исключён / УЕДЕТ ~N МБ» (N = размер дерева HEAD, 162.4 МБ) и «ИТОГО архив ≈ …»; красные
прогоны — правила без `.git` (ИТОГО ≈ 194 МБ, код 1) и с `.git/` (та же ошибка, названа
поимённо). Сборка 62152db3 от лишних 150 МБ не пострадала — они лежат рядом с проектом
и в бандл не попадают. **Подтверждено логом сборки №3 (тот же день): «Uploading to EAS Build
(0 / 28.7 MB)», заливка 7 с вместо 37; предупреждение «Your project archive is …» исчезло.**

иконку пуша и — главное — русские числительные и даты, потому что Hermes там тот же самый,
с урезанным ICU. Не показывает хаптику и настоящую резкость на плотном экране: финальным
судьёй телефон остаётся.

**Что дальше по задаче:** установка APK (эмулятор или телефон, когда появится) → лайв-проверка
