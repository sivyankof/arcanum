## Цель

Уроки М1–М2 полностью проходимы: теория → разбор карт → викторина 5 вопросов → результат с XP
и конфетти. XP-система становится настоящей: поле `xp` в сторе, три источника начисления, пилюля
уровня на «Сегодня» перестаёт быть моком. В справочнике появляется бейдж «Изучено ✓».

## Решения брейншторма (13.08)

1. **Викторины М1+М2** (10 уроков, 50 вопросов). Черновики уже лежат в `content/quiz-m1-m2.json`
   (Cowork, статус draft); вычитка редактора идёт параллельно, правки придут пачкой — файл остаётся
   в репо как staging, слияние в `course.json` повторяемо скриптом.
2. **Повтор пройденного урока: +2 XP, раз в день на урок** — конфликт доков решён в пользу
   logic-spec §4; строку «(без XP)» в product-spec §2 поправить.
3. **Три источника XP сразу**: урок (10 − 2×ошибки, мин 4), карта дня +5, ответ рефлексии +3
   (только первый ответ дня — смена ответа до полуночи повторно не начисляет). Расклад +5 ждёт
   своего этапа.
4. **Финал показывает прогресс модуля** («ПРОЙДЕНО N ИЗ M УРОКОВ МОДУЛЯ» + полоса) — формулировка
   «серия уроков» из product-spec §2 умерла: уроки серию дней не двигают, путать нельзя.
5. **Шаг «разбор карт» — да**: у уроков с `cards` после теории по странице на карту, собирается
   из уже готового `cards.json` (изображение + название + 4 keywords), новых текстов не нужно.
   Конфликт product-spec §2 (нет шага) ↔ master-plan (есть шаг) решён в пользу master-plan.

## Что делаем

### 1. Контент: `quiz` в course.json + скрипт слияния

Схема урока в `course.json` дополняется двумя полями:

```jsonc
"quiz": [            // 5 вопросов на урок (М1–М2); у М3+ поля нет
  {
    "type": "single",          // или "card" — вопрос с изображением карты
    "q": {"ru": "…", "en": "…"},
    "options": [{"ru": "…", "en": "…"}, …],   // ровно 3
    "correct": 1,              // индекс в options
    "explain": {"ru": "…", "en": "…"},        // пояснение после ответа
    "cardId": "magician"       // только у type: "card"
  }
],
"quizStatus": "draft"          // workflow как у блоков карт: draft → reviewed → final
```

- **`scripts/merge_quiz.py` (новый)**: сливает `content/quiz-m1-m2.json` → `content/course.json`
  по образцу `build_cards.py` (переносит, не затирает: трогает только `quiz`/`quizStatus`, theory
  и остальное не касается). Валидация до записи: каждый lessonId существует в course.json, ровно
  3 варианта, `correct` в 0..2, `cardId` есть в cards.json. Идемпотентен — правки редактора
  вносим в quiz-файл и перезапускаем.
- **Тест-контракт на контент** (`src/lib/__tests__/courseContent.test.ts`): у каждого урока М1–М2
  ровно 5 вопросов, 3 варианта, `correct` в диапазоне, у card-вопросов `cardId` существует
  в cards.json (⚠️ НЕ обязан входить в `lesson.cards`: у m2l6 карт нет, а card-вопрос есть).
  Опечатки после вычитки редактора ловит `npm test`, а не пользователь.
- `src/lib/content.ts`: типы `QuizQuestion`, `quiz?`, `quizStatus?` у `CourseLesson`.

### 2. Чистая логика: `src/lib/lesson.ts` и `src/lib/xp.ts`

**`lesson.ts`** — шаги урока, ни одного импорта react/expo, целиком под тестами:

- `LessonStep = {kind: 'theory', text} | {kind: 'card', cardId} | {kind: 'quiz', question}`.
- `lessonSteps(lesson, lang, rng)`: страницы теории (режем по `\n\n`, жадно группируем абзацы
  в страницы с бюджетом ~700 символов — получается 2–3 страницы на урок) → по странице на каждую
  карту из `lesson.cards` → 5 вопросов в порядке файла (порядок педагогический, вопросы НЕ мешаем).
  Язык фиксируется при входе в урок (шаги строятся один раз): смена языка посреди урока
  не пересобирает шаги и не сбивает индекс — увидится со следующего входа.
- **Варианты ответов перемешиваются** — функция с инжектируемым rng (тесты детерминированы),
  `correct` переиндексируется. В приложении rng создаётся один раз при входе в урок: в полёте
  варианты не прыгают, при следующем входе порядок другой.
- `hasLesson(lesson)`: есть непустая theory И quiz → урок проходим; иначе экран «Урок готовится»
  (все М3+ упираются сюда до этапа 3).

**`xp.ts`** — XP и уровни (logic-spec §4):

- `lessonXp(errors) = max(10 − 2×errors, 4)`; `REPEAT_XP = 2`; `XP_DRAW = 5`; `XP_REFLECT = 3`.
- `levelFromXp(xp) → {level, progress}`: пороги накопительные 0 / 50 / 150 / 300 / 500, дальше
  каждый +250 (750, 1000, …); `progress` — доля пути до следующего уровня 0..1. Титулы уровней
  уже в i18n (`level.t1..t6`), XpPill их уже показывает.

**Состояние прохождения** (текущий шаг, ошибки, выбранный ответ) — локальный state экрана,
НЕ стор: product-spec §2 «выход посреди урока → прогресс шага не сохраняется». Вариант «шаг
в сторе с персистом» отвергнут на брейншторме.

### 3. Стор: persist version 5

- Новое поле верхнего уровня **`xp: number`** (деф. 0). Как и `lessonsProgress` в v4, верхний
  уровень доливается поверхностным слиянием сам — отдельная ветка миграции не нужна, версию
  поднимаем по правилу logic-spec §7. **Следующая задача, меняющая схему, поднимает до 6.**
- **`completeLesson(lessonId, errors)`** — единственная точка записи прогресса и урочного XP:
  - первое прохождение: `{done: true, errors, ts}` + `lessonXp(errors)`;
  - повтор: обновить `errors`/`ts` (ошибки последнего прохождения, как в схеме §7), `done`
    остаётся true; +2 XP только если `repeatDate ≠ сегодня`, тогда `repeatDate = сегодня`
    (новое опциональное поле `LessonProgress`, вглубь объекта миграция не нужна).
- `drawToday`: после записи карты дня `xp + 5` (повторный вызов в тот же день и так отсекается).
- `setOutcome`: `xp + 3` только если у записи ещё не было `outcome` (смена ответа — без XP).
- XP задним числом за прошлые карты/рефлексии НЕ начисляется — счёт с нуля у всех.
- DEV-строки настроек (`setLessonDone`, `resetCourse`) остаются как есть (XP не трогают:
  это отладка пути, не прохождение).

### 4. Экран урока `app/lesson/[id].tsx`

Нативная шапка и композиция — как в заглушке 07 (headerBackTitle «Курс», вибрация возврата).
Шрифты ниже — по типографической сетке design-system §2 (значения макета × масштаб рамы ~1.11,
прецедент задачи 04в: `.block p` 14 макета = Body serif 16 кода). Постоянная часть: overline
«МОДУЛЬ N · УРОК M» + название (Cormorant 26 — Display L, как в заглушке 07; макетные 22 —
условность рамы) + **прогресс-бар**: высота 7, radius 4, фон `line`, заполнение — градиент
accent→accent2, ширина X/N по шагам (timing ~300мс), подпись «X/N» accent 11 bold справа
(ряд: gap 10, marginTop 6). Контент шага сменяется под шапкой (fade 130/350мс, как вкладки
страницы карты).

- **Шаг теории**: готовый `Block` — он и есть `.theory` (фон panel, бордер 1 line, radius 16,
  паддинг 16); текст **Body serif Cormorant 16/25** (design-system §2 прямо называет теорию
  уроков). Внизу CTA «Далее» (`CtaButton`).
- **Шаг карты** (`.lcard`): ряд gap 14 — изображение 74px (radius 8, бордер frame, boxShadow
  `0 8px 22px glow`) + колонка: overline «КАРТА УРОКА» (9, letterSpacing 2, accent), название
  Cormorant 20 head, строка «✦ слово · слово · слово · слово» (12, muted, 4 keywords из cards.json).
  Панель: фон panel, бордер 1 **frame** (не line), radius 16, паддинг 14. CTA «Далее».
- **Шаг вопроса**: текст вопроса Cormorant 19 head по центру; у card-вопроса над текстом —
  изображение карты (ширина 110, radius 12 — токен `radius.m`, бордер frame, по центру).
  Три варианта-панели
  (`.opt`): фон panel, бордер 1.5 line, radius 14, паддинг 13×16, шрифт 14 (Body), отступ между 9.
  - Тап по варианту (повторные тапы игнорируются): **верный** → бордер `success` + фон success
    с прозрачностью 0.12 + хаптика Light; **неверный** → бордер `danger` + opacity 0.6 выбранного,
    через 400мс подсвечивается правильный, хаптика Notification.Error; ошибка идёт в счёт,
    но не блокирует.
  - После ответа под вариантами появляется **`explain`** (Cormorant 15/1.5, text, по центру,
    marginTop 14) и CTA «Далее» (⚠️ в макете explain и кнопки нет — осознанное расхождение,
    контент Cowork их требует; дорисовка → задача 15).
- **Финал** (`.lresult` + motion-spec §16): панель по центру (фон panel, бордер 1 frame,
  radius 18, паддинг 20) въезжает fade+up 500мс → хаптика Success → счётчик «+N XP» (Cormorant 36,
  accent, 600) катится 55мс/шаг → подпись «ПРОЙДЕНО N ИЗ M УРОКОВ МОДУЛЯ» (11, muted,
  letterSpacing 1; ⚠️ плюрализация «уроков» по M — помнить «из 1 дней») → полоса модуля
  (высота 6, radius 3, margin 12/30/0) заполняется пружиной 800мс от прежней доли к новой →
  **конфетти**: 20–24 частицы ✦ ✧ ❖ · (8–18px, цвета accent/accent2 через один) веером вверх
  из-за панели (сектор верхней полуокружности, разлёт 90–220px, подъём −60), 1.1с, затухание.
  Реализация — **расширение `Sparks`** (пропсы: сектор углов, вертикальный сдвиг, набор глифов,
  чередование цвета), не второй компонент. CTA «ДАЛЬШЕ ПО ПУТИ →» → `router.back()` (курс сам
  покажет узел done и новый current; автоскролл к текущему уже есть с 07).
  - Повтор, когда +2 сегодня уже получены: та же панель без XP-счётчика (заголовок
    «Повторение пройдено», прогресс модуля остаётся).
  - Reduce motion: без конфетти, счётчик мгновенный (motion-spec §16).
- **Урок без контента** (М3+): как сейчас — EmptyState «Урок готовится», завершить нельзя.
- Вход с пройденного узла (уже работает с 07) — тот же экран, режим повтора определяется
  по `progress[id].done`.

### 5. Бейдж «Изучено ✓» и пилюля «Сегодня»

- `learnedCardIds(modules, progress)` в `courseProgress.ts`: множество карт пройденных уроков
  (уникальные id — та же ловушка, что у счётчика «M КАРТ»).
- Справочник (`app/(tabs)/cards.tsx`): на миниатюрах изученных карт бейдж по `.st2` — абсолют
  сверху-справа 6/6, текст «ИЗУЧЕНО ✓», шрифт 8, цвет accent2, фон rgba(0,0,0,.4), radius 8,
  паддинг 2×6, letterSpacing 0.5.
- «Сегодня» (`app/(tabs)/index.tsx`): `MOCK_LEVEL`/`MOCK_PROGRESS` удаляются, XpPill получает
  реальные `levelFromXp(xp)` — компонент к этому готов с задачи 01.

## Критерии приёмки («готово, когда…»)

- [ ] Каждый из 10 уроков М1–М2 проходится целиком: теория (2–3 страницы) → карты (если есть) →
      5 вопросов → финал; прогресс-бар X/N растёт по шагам.
- [ ] Верный ответ: рамка success + Light; неверный: рамка danger, подсветка правильного через
      400мс, Error; после ответа — explain + «Далее»; повторный тап по вариантам игнорируется.
- [ ] Финал по motion-spec §16: панель 500мс → Success → счётчик 55мс/шаг → полоса модуля
      пружиной → конфетти вверх 1.1с; CTA возвращает на курс, узел ✓, следующий — current,
      автоскролл к нему.
- [ ] XP: первое прохождение = 10−2×ошибки (мин 4), повтор +2 не чаще раза в день, карта дня +5,
      первый ответ рефлексии дня +3 (смена ответа не начисляет). Пилюля «Сегодня» показывает
      реальный уровень и прогресс (пороги 0/50/150/300/500/+250).
- [ ] Бейдж «ИЗУЧЕНО ✓» на миниатюрах карт пройденных уроков; после m2l1 (Дурак и Маг) — ровно
      на двух картах.
- [ ] Уроки М3+ — «Урок готовится», завершить нельзя; курс упирается в m3l1 и это ок.
- [ ] Выход посреди урока (шапка «назад») — свободный, шаг не сохраняется, прогресс/XP не пишутся.
- [ ] persist v5: у «старого» пользователя xp = 0, lessonsProgress/настройки/история целы.
- [ ] Reduce motion: без конфетти, счётчик мгновенный.
- [ ] `npx tsc --noEmit` чистый; `npm test` зелёный (≈30 новых тестов: xp, lesson, learnedCardIds,
      контракт контента); консоль веба без новых ошибок/warning.
- [ ] Скриншоты 390×844 в обеих темах в `docs/screenshots/08/`: теория, карта урока, вопрос
      (до/после верного и неверного ответа), финал, справочник с бейджем, «Сегодня» с пилюлей.
- [ ] Веб-проверка 6а+6б пройдена; лайв-проверка Артёма на iPhone (хаптика трёх видов, конфетти,
      счётчик) — финал задачи.

Известные веб-отличия (не баги): хаптики нет; системные тени слабее. Конфетти и счётчик в вебе
работают (Sparks/reanimated уже проверены задачами 01–07).

### Уточнение факта против спеки

Спека и план предполагали 2–3 страницы теории на урок. Фактически при бюджете 700 символов
получается **3–5 страниц**: m1l1 — 5 (10 шагов), m1l2/m1l4/m2l1–m2l5 — 4, m1l3/m2l6 — 3.
Отдельно `m2l5` содержит 8 карт разбора и потому насчитывает 17 шагов — самый длинный урок
курса. Поведение верное, неверным было предсказание.

### Открытый вопрос для Артёма (главный)

Пояснение `explain` показывается после ЛЮБОГО ответа, но 31 текст из 50 написан в расчёте на
верный и начинается с «Верно!», «Да!», «Точно!», «Именно!». На неверном ответе приложение
отвечает «Да! …», то есть поздравляет за ошибку. Это связка контента и поведения, а не ошибка
кода. Два пути, выбор за Артёмом: (а) редактор нейтрализует зачины в 31 тексте; (б) в код
добавляется префикс «Верно» / «Не совсем» из i18n, а зачины убираются из контента. Заведено
задачей в бэклог.
