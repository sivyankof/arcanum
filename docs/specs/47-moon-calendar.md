# Спека 47 — лунный календарь: фазы месяца, новолуние и полнолуние как события (этап 4 плана)

Статус: спека написана 19.08 (брейншторм: вопросы 8–10 бэклога и вопрос точности решены Артёмом
по рекомендациям Claude 19.08, остальные развилки — ниже в таблице «Решения»), ждёт «ок» Артёма
по тексту. Реализация — сессия на Opus 5 по детальному плану `docs/plans/47-moon-calendar.md`
(код по шагам отдаётся sonnet-сабагентам), ветка `feat/47-moon-calendar`, веб-проверка 6а/6б
и лайв-проверка Артёма на iPhone — как у любой UI-задачи.

Контекст: п. 11 master-plan §3.1-Р («Лунный календарь — новолуние/полнолуние как события:
специальные расклады лунного цикла, тематические пуши. 2–4 „праздника“ в месяц»), этап 4 плана,
третья задача этапа после флеш-карт (45) и коллекции (46). Макет — `v-moon` в
`design-reference.html` (Cowork, 15.08), нарисован «простейшим вариантом»: шапка месяца, строка
луны, сетка месяца с глифами событий, две строки событий. Вход со строки луны на «Сегодня»
в макете НЕ нарисован (к экрану ведёт демобар; кнопка «назад» подписана «СЕГОДНЯ») — вход
определяется здесь и дорисовывается в макет (правило 6а-0).

Пуши новолуния/полнолуния — ОТДЕЛЬНАЯ задача **47б** (решение 19.08, прецедент 06а→06б: пуши
в вебе не проверяются, смешивать циклы проверки значило бы держать половину задачи непроверенной).

## Решения

| Вопрос | Решение |
|---|---|
| 8 · Вход | **Только со строки луны на «Сегодня»**: строка становится нажимаемой, тап → `/moon`; «назад» подписан «Сегодня». Справа от текста строки — шеврон `chevron-forward-outline` 12 px `muted` (в макете его нет — дорисовать: без него не догадаться, что строка ведёт куда-то). Отдельного пункта в профиле/настройках нет. |
| 9 · Контент | **Минимум**: сетка фаз по дням + события новолуния/полнолуния с короткой подписью («Время задумывать новое» / «Время подводить итоги») — две UI-строки в `i18n.ts`, ru+en. Текстов на лунные дни и фазы нет. |
| 10 · Пуши | **Отдельная задача 47б** после экрана. Здесь — ничего про пуши; `pushPlan.ts` не трогаем. |
| Точность моментов | **Точные моменты новолуния/полнолуния по алгоритму Меюса, без зависимостей.** Нынешний `moon.ts` считает «среднюю луну» от эпохи 2000 (±14 ч к реальному моменту): для строки «Растущая луна» хватало, для календаря с ДАТАМИ — нет (формула приложения даёт новолуние 13.08.2026 07:46 UTC, реальное — 12.08.2026 17:37 UTC; примерно каждое третье событие оказалось бы на соседнем дне относительно любого другого лунного календаря). Ядро `moon.ts` переписывается; строка «Сегодня», календарь и будущие пуши 47б считают от одной правды. |
| День события | **Один день — локальный календарный день точного момента, с местным временем** («НОВОЛУНИЕ · 12 АВГУСТА · 20:37»), а не диапазон «12–13» из макета: макет рисовал окно фазы (±0.92 сут), точный момент — это момент. Строка «Новолуние» на «Сегодня» при этом живёт ~2 суток (окно фазы) — «период» против «момента», не баг; записано в logic-spec §6. |
| Прошедшие события месяца | **Показываем, приглушаем** (`opacity .45` на всю строку) — так же, как прошедшие дни в сетке (`.dim`). В макете «прошлых» строк просто не было (даты макета позже «сегодня»). |
| Начало недели | **По языку**: ru — понедельник; en/es/pt — воскресенье (CLDR для выбранных локалей en-US/es-MX/pt-BR). Таблица `WEEK_START: Record<Lang, 0 \| 1>` в `lang.ts` (0 = воскресенье, 1 = понедельник — нумерация `Date.getDay()`). |
| Подписи дней недели | `toLocaleDateString(LOCALES[lang], { weekday: 'short' })` → UPPERCASE, хвостовая точка срезается (pt-BR отдаёт «seg.»). Тот же механизм, что `formatEntryDate` дневника — на устройстве проверен лайв-проверками. |
| Глифы ● / ○ | **Рисуем `View`-кружками, а не символами шрифта**: 6×6 в ячейке (● — заливка `text`, ○ — кольцо `accent` border 1), 14×14 в строке события (border 1.5). Символ зависел бы от системного шрифта и платформы, кружок — нет. Правило 16 («если символ уже нарисован иконкой — побеждает иконка») не нарушено: таких глифов в приложении ещё нет. |
| ☾ в разделителе | У `Rule` появляется проп `glyph?: string` (по умолчанию ✦); на экране календаря — ☾, как в макете (`.rule span`). ☾ нет в Manrope — `Rule` и так рисует звёздочку системным `Text` без `fontFamily`. |
| Листание месяцев | **Не делаем** — только текущий месяц, как в макете. Если попросят на лайве — отдельной задачей (v1.1). |
| Обновление «сегодня» | Экран вычисляет `now` при монтировании и пересчитывает на возврате из фона (`useAppActive`) — правило 06а: всё, что зависит от текущего времени, слушает `AppState`. Переход через полночь при открытом экране — сетка обновится при следующем возврате из фона, таймера нет. |
| Хранение | **Ничего нового не храним**: всё выводится из времени. Persist version остаётся **10**, бэкап не меняется. |

## Цель

- Пользователь видит месяц луны одним экраном: какой сегодня лунный день и фаза, в какие дни
  новолуние и полнолуние (с местным временем), что прошло и что впереди. Это 2–4 «праздника»
  в месяц — крючок возврата (master-plan п. 11) и фундамент для пушей 47б.
- Одна правда о луне: строка на «Сегодня», календарь и будущие пуши читают один `moon.ts`
  с точными моментами; средней луны в коде не остаётся.
- Логика чистая и под тестами (против опубликованных эфемерид); экран — тонкий слой из общих
  компонентов.

## Что делаем

### А. Ядро `src/lib/moon.ts` — переписать на точные моменты (под юнит-тестами)

Публичный API (сигнатуры прежних функций не меняются — `app/(tabs)/index.tsx` продолжает звать
`moonInfo(now)`):

```ts
export type MoonPhase = 'new' | 'waxing' | 'full' | 'waning';
export type MoonEventKind = 'new' | 'full';
export interface MoonEvent { kind: MoonEventKind; at: Date }   // at — точный момент (UTC-инстант)

export const HALF_WINDOW = 0.92;                               // полуширина окна new/full, сутки (hf-01)
export function phaseInstant(k: number, kind: MoonEventKind): Date;   // Меюс: k целое → новолуние лунации k, kind 'full' → k + 0.5
export function moonEvents(from: Date, to: Date): MoonEvent[];         // все new/full в [from, to), по времени
export function lunationAround(date: Date): { prevNew: Date; full: Date; nextNew: Date };
export function moonAge(date: Date): number;      // сутки от prevNew, [0, ~29.83)
export function moonPhase(date: Date): MoonPhase; // 'new' если |date − ближайшее новолуние| < HALF_WINDOW; 'full' — то же для полнолуния; иначе waxing (до full) / waning (после)
export function lunarDay(date: Date): number;     // floor(moonAge) + 1, 1…30
export function moonInfo(date: Date): { age: number; phase: MoonPhase; day: number };
```

Убираются экспорты `MOON_EPOCH`, `SYNODIC_MONTH`, `PHASE_BOUNDS` (использовались только тестами;
средняя длина месяца остаётся внутренней константой для оценки номера лунации `k`).

**Алгоритм** — Meeus, *Astronomical Algorithms* (2-е изд.), гл. 49 «Phases of the Moon». Номер
лунации `k` (0 = новолуние 6 января 2000): оценка `k ≈ (год_дробный − 2000) × 12.3685`, для
новолуния `k` целое, для полнолуния `k + 0.5`. Далее `T = k / 1236.85` (юлианские столетия от J2000):

```
JDE = 2451550.09766 + 29.530588861·k + 0.00015437·T² − 0.000000150·T³ + 0.00000000073·T⁴
E   = 1 − 0.002516·T − 0.0000074·T²
M   = 2.5534   + 29.10535670·k − 0.0000014·T² − 0.00000011·T³                      (средняя аномалия Солнца)
M'  = 201.5643 + 385.81693528·k + 0.0107582·T² + 0.00001238·T³ − 0.000000058·T⁴      (средняя аномалия Луны)
F   = 160.7108 + 390.67050284·k − 0.0016118·T² − 0.00000227·T³ + 0.000000011·T⁴      (аргумент широты Луны)
Ω   = 124.7746 − 1.56375588·k + 0.0020672·T² + 0.00000215·T³                        (долгота восходящего узла)
```
(все углы в градусах, привести к [0, 360) перед синусами). Поправка к JDE (сутки) для **новолуния**:

Для **полнолуния** — тот же ряд с первыми семью коэффициентами `−0.40614, +0.17302, +0.01614,
+0.01043, +0.00734, −0.00515, +0.00209`, остальные совпадают. Плюс **планетные поправки** (обе фазы):

JDE — динамическое время (TD); в UTC переводим вычитанием ΔT ≈ 69 с (константа, для 2020–2030
меняется в пределах ±3 с — ниже нашей точности). `Date`: `ms = (JD − 2440587.5) × 86 400 000`.
Точность ряда — около 1–2 минут; допуск тестов — **±10 минут**.

`lunationAround(date)`: `k0 = floor((date − эпоха) / 29.530588861 сут)` по средней формуле, затем
новолуния для `k0 − 1 … k0 + 1` точным расчётом, из них — последнее ≤ date (`prevNew`) и первое
> date (`nextNew`); `full = phaseInstant(k_prev, 'full')`. `moonEvents(from, to)` — перебор `k`
от оценки для `from − 1 месяц` до `to + 1 месяц`, фильтр по диапазону, сортировка.

**Опорные моменты для тестов (UTC).** Формулы выше и таблица ниже сверены ДРУГ О ДРУГА пробным
скриптом 19.08 (транскрипция ряда — из книги по памяти, даты — из памяти об опубликованных
эфемеридах; два независимых источника ошибок сошлись на всех 18 моментах с расхождением ≤ 0.5 мин —

Семантика фаз с точными моментами (logic-spec §6 переписать): окно `new`/`full` — ±0.92 сут
вокруг точного момента (гарантия hf-01 сохраняется: в реальное новолуние строка говорит
«Новолуние»); между окнами — `waxing` (от новолуния к полнолунию) и `waning`. Лунный день —
`floor(возраст) + 1`; длина лунации 29.27–29.83 сут, поэтому день 30 бывает не в каждом месяце
(29 → 1) — это не дефект, так в любом лунном календаре.

### Б. Сетка и события месяца — `src/lib/moonCalendar.ts` (чистый, под тестами) + `dates.ts`/`lang.ts`

```ts
export interface MonthEvent { kind: MoonEventKind; at: Date; day: number }  // day — число месяца по ЛОКАЛЬНОМУ времени
export function monthEvents(year: number, month0: number, source = moonEvents): MonthEvent[];
// границы — ЛОКАЛЬНЫЕ полночь 1-го числа и полночь 1-го числа следующего месяца (new Date(y, m, 1));
// source подменяется в тестах синтетическими событиями, собранными локальным конструктором Date —
// иначе тест зависел бы от часового пояса машины (момент 17:37 UTC — это 12-е число в Москве и 13-е в Окленде)
export function monthGrid(year: number, month0: number, weekStart: 0 | 1): { leading: number; daysInMonth: number };
// leading = (getDay(1-е число) − weekStart + 7) % 7 — пустых клеток перед 1-м; хвост не нужен, сетка сама переносит
```
В `src/lib/lang.ts`: `WEEK_START: Record<Lang, 0 | 1> = { ru: 1, en: 0, es: 0, pt: 0 }`.
В `src/lib/dates.ts`: `weekdayLabels(lang): string[]` — 7 подписей начиная с `WEEK_START[lang]`,
`toLocaleDateString(locale, { weekday: 'short' })`, UPPERCASE, без хвостовой точки;
`formatTime(date: Date, lang): string` — `toLocaleTimeString(locale, { hour: '2-digit', minute: '2-digit' })`
(ru «20:37», en «08:37 PM»). Хелперы форматирования живут в `dates.ts`, а не в `moonCalendar.ts`:
тот остаётся числовым и про язык не знает.

Месяц всегда содержит 1–3 события: в феврале может не быть полнолуния, в длинном месяце бывает
два новолуния (1-го и 30/31-го). Ноль событий невозможен (интервал между соседними событиями
≈ 14.8 сут < 28). Порядок — по времени; кинды могут повторяться («новолуние, полнолуние,
новолуние»).

## Риски и ловушки для имплементера

- Ряд Меюса легко ошибиться знаком или коэффициентом — поэтому тесты против эфемерид пишутся
  ПЕРВЫМИ и обязаны быть красными на пустой реализации; одной опорной даты мало, нужны ≥12 на
  разные годы и оба кинда (ошибка в коэффициенте полнолуния при верном новолунии иначе пройдёт).
- Углы в градусах → перед `Math.sin` переводить в радианы; приведение к [0, 360) не обязательно
  для синуса, но полезно для отладки.
- `k` для полнолуния — `целое + 0.5`; `T` считать от ЭТОГО `k`, не от целого.
- Локальные границы месяца — `new Date(y, m, 1)`, не ISO-строки (ловушка H2 из `dates.ts`).
- Тесты `monthEvents` — только на синтетическом источнике (зависимость от часового пояса машины).
- `toLocaleTimeString` с `hour: '2-digit'` в en-US даёт «08:37 PM» — это ожидаемо, не «чинить».
- `Rule` с новым пропом не должен менять ни один из трёх существующих экранов (дефолт ✦).
