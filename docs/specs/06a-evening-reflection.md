# Спека 06а · Вечерняя рефлексия (без пушей)

Статус: ГОТОВО (веб-проверка пройдена), ждёт лайв-проверки Артёма на iPhone (11.08.2026) ·
Эталон: `docs/design-reference.html` (вкладки «Сегодня», «Профиль», «Настройки») ·
Значения: `docs/design-system.md` §5 · Поведение: `docs/product-spec.md`
§1, §5 · Данные и правила: `docs/logic-spec.md` §3, §7, §9 · Тон: `docs/content-guide.md`

## Цель

Вечер замыкает ежедневную петлю: карта не просто открыта утром, а вечером получает ответ — отозвалась
она или нет. Ответ ложится в ту же запись дневника, что и заметка, и сразу оживляет три места,
которые задача 05 оставила пустыми: отметку в строке записи, сводку месяца и счётчик на странице карты.

## Решения брейншторма (11.08)

1. **Задача 06 разделена на 06а и 06б.** Рефлексия и подсистема локальных пушей — независимые куски
   с разными циклами проверки: 06а проверяется в браузере целиком, 06б не проверяется в вебе НИКАК
   (`expo-notifications` веб не поддерживает) и требует ожидания реального времени срабатывания.
   Смешивать их в одну спеку — значит half-задачу держать непроверенной.
2. **Один блок, который вечером растёт.** В макете плашка заметки лежит внутри блока рефлексии,
   а в приложении задача 05 вынесла её отдельным блоком «Заметка о дне» (до 18:00 писать заметку
   иначе негде). Заметка в записи одна (`note`, logic-spec §3), двух плашек быть не может. Решение:
   это ОДИН блок — до 18:00 он «Заметка о дне» с плашкой, после 18:00 у него меняется заголовок
   и над плашкой появляются вопрос и три кнопки. Плашка остаётся на своём месте внизу блока.
3. **Формулировки — «Отозвалась / Отчасти / Не отозвалась».** Макет и product-spec §1 подписывают
   кнопки «Сбылось / Отчасти / Мимо», но content-guide и logic-spec §3 запрещают ровно это слово
   («карта отозвалась», а не «предсказание сбылось» — важно и для тона, и для ревью в сторах),
   а сводка месяца уже называется «Отозвалось X из Y». Прав документ, не макет (правило 6а-0):
   один глагол во всех четырёх местах — кнопки, отметка, сводка, страница карты.
4. **После ответа кнопки прячутся** (как в макете), остаётся строка «✓ Отозвалась · записано
   в дневник» и подпись-кнопка «изменить можно до полуночи», возвращающая кнопки. В макете эта
   строка не нажимаема — дорисовка.
5. **Тумблер «Вечерняя рефлексия» делаем здесь**, хотя пушей ещё нет: сейчас он управляет показом
   блока, 06б добавит к нему отмену вечернего пуша. Заводить его дважды смысла нет.
6. **Правило вариативности включается по-настоящему.** Вопрос над кнопками — ежедневно повторяющийся
   текст, а `content/phrases.json` до сих пор не читается кодом ни разу. Первое реальное применение —
   здесь, поэтому в задачу входит хелпер выбора варианта по logic-spec §9.
7. **Фильтр дневника сбрасывается на «Все» ещё и при исчезновении своего чипа** (найдено ревью
   задачи 9, в исходном плане пункта не было). Смены месяца недостаточно: запись, потерявшая
   заметку или ответ, могла увести с ленты активный чип прямо на текущем месяце (например,
   стёрли единственную заметку месяца при фильтре «С заметкой») — без этого правила пользователь
   оставался с пустым списком и без единого чипа, чтобы вернуться к «Все». Фикс — коммит 71386d7.

## Что делаем

### 1. Данные и стор (`src/store/useApp.ts`)

Новый тип и экшены:

```ts
export type Outcome = 'yes' | 'partly' | 'no';

setOutcome: (date: string, outcome: Outcome) => void
setReflectionOn: (on: boolean) => void
```

`setOutcome` пишет ответ в запись `history` за указанную дату. Условия те же, что у `setNote`:
запись существует И дата = сегодня (`canEditEntry`). Повторный вызов с тем же значением ничего
не меняет; снятия ответа (перевода в «не отвечено») НЕТ — см. «Что НЕ делаем».

Настройки появляются в схеме хранения:

```ts
settings: { reflectionOn: boolean }   // дефолт true
```

`version` persist поднимается с 1 до 2, миграция дописывает `settings` с дефолтами существующим
пользователям.

⚠️ **Ловушка вложенного объекта.** `zustand/persist` сливает состояние ПОВЕРХНОСТНО: сохранённый
`settings: { reflectionOn: false }` заменит объект-дефолт целиком, а не сольётся с ним по ключам.
Поэтому 06б, добавляя `pushMorning`/`pushEvening`/`pushesOn` (logic-spec §7), обязана поднять
`version` до 3 и дописать недостающие ключи миграцией — новые поля сами не появятся. Миграцию
пишем так, чтобы она заполняла пропущенные ключи, а не перезаписывала объект.

### 2. Модуль `src/lib/journal.ts` — арифметика ответов

`canEditNote` → **`canEditEntry`**: правило «правится только сегодняшняя запись» одно на заметку
и на ответ, двух функций с одним смыслом быть не должно (правки: стор, `app/note/[date].tsx`, тесты).

`DailyDraw.outcome` уже объявлен — тип меняется только на именованный `Outcome`.
`CardHistory` получает поле `resonated`.

Новое:

| Функция | Возвращает |
|---|---|
| `outcomeStats(history, month)` | `{ answered, resonated, yes, partly, no }` |
| `filterEntries(entries, filter)` | записи, попавшие под фильтр |
| `filterCounts(entries)` | `Record<JournalFilter, number>` — числа для чипов |
| `JOURNAL_FILTERS` | `['all', 'yes', 'partly', 'no', 'note']` |

Правила счёта (logic-spec §3, не «на глаз»):

- `answered` — записи, у которых `outcome` ЕСТЬ. Записи без ответа в знаменатель не идут:
  «Отозвалось 12 из 18» — это 18 дней с ответом, а не 18 записей месяца.
- `resonated = yes + partly`. Так же считается «отзывалась N» на странице карты.
- Месяц без единого ответа → `answered: 0`, и строка со сводкой не рисуется вовсе (не «0 из 0»).

### 3. Модуль `src/lib/reflection.ts` — когда показывать блок

```ts
export const REFLECT_HOUR = 18;
export function reflectionVisible(o: {
  drawn: boolean; hour: number; enabled: boolean; devForce?: boolean;
}): boolean;
```

Чистая функция, чтобы граничные случаи закрывались тестами, а не наблюдением за часами:

- карта дня не открыта → `false` всегда (рефлексировать не о чем), даже с `devForce`;
- `hour < 18` → `false`; `hour >= 18` → `true`;
- тумблер выключен → `false`, и `devForce` его НЕ обходит (dev-обход снимает только время);
- `devForce` (только `__DEV__`) → игнорирует час.

Экран пересчитывает видимость при рендере и при фокусе (`useFocusEffect`) — таймера на каждую
минуту нет: сидеть в приложении ровно в 17:59:59 — не тот случай, ради которого стоит держать
интервал, а при следующем открытии экрана блок появится сам.

### 4. Модуль `src/lib/phrases.ts` — правило вариативности (logic-spec §9)

```ts
export function pickPhrase(key: string, dateISO: string, lang: 'ru' | 'en',
                           vars?: Record<string, string | number>): string;
```

`key` — путь в `content/phrases.json` через точку (`'reflect.question'`, `'empty.filter'`).
Индекс варианта: `fnv1a32(`${dateISO}:${key}`) % variants.length` (`fnv1a32` уже есть
в `src/lib/content.ts`). `Math.random` запрещён. Плейсхолдеры `{card}`, `{name}`, `{n}`
подставляются после выбора варианта.

Применяем в этой задаче дважды: вопрос рефлексии и пустое состояние фильтра. Заодно существующее
пустое состояние дневника переводится с `tr('journal.empty')` на `pickPhrase('empty.journal', …)` —
иначе в приложении останутся две параллельные системы текстов, а `phrases.json` так и не начнёт
работать.

### 5. Контент (`content/phrases.json`)

Новый блок (черновик Claude, вычитывает редактор — как и остальные системные фразы):

```json
"reflect": {
  "question": [
    { "ru": "Как отозвалась {card} сегодня?",              "en": "How did {card} resonate today?" },
    { "ru": "{card} была с вами весь день. Что скажете?",   "en": "{card} was with you all day. How was it?" },
    { "ru": "Вечер — время оглянуться: {card} про ваш день?", "en": "Evening is for looking back — was {card} about your day?" }
  ]
}
```

Заодно правится третий вариант `push.evening_reflect` («Минутка перед сном: **сбылась** ли {card}?») —
это ровно та формулировка, которую запрещает content-guide. Замена: «Минутка перед сном: отозвалась
ли {card}?» / «A moment before sleep — did {card} resonate?». Текст пойдёт в дело в 06б, но
оставлять в бандле известное нарушение редполитики нельзя.

### 6. Экран «Сегодня» (`app/(tabs)/index.tsx` + `src/components/Reflection.tsx`)

Блок под «Значением дня» — один, с двумя состояниями:

| | до 18:00 | после 18:00 |
|---|---|---|
| Заголовок Overline | `ЗАМЕТКА О ДНЕ` | `КАК ПРОШЁЛ ДЕНЬ` |
| Над плашкой | — | вопрос + кнопки (или строка ответа) |
| Плашка заметки | есть | есть, на том же месте |

Вопрос — Cormorant 14.5 цветом `text` (макет: `.reflect p{font-size:14.5px}`), отступ сверху 6.

**Кнопки** (design-system §5 «Кнопки рефлексии» + `.rb` макета): три равные (`flex: 1`), зазор 7,
отступ сверху 10, бордер `line` 1px, radius 12, паддинг 9×4, текст по центру 11px цветом `text`.
Выбранная кнопка — как активный чип: бордер `frame`, фон `chipBg`, текст `accent` (в макете этого
состояния нет, потому что там кнопки не возвращаются, — дорисовка).

**Строка ответа** (макет `.done2`): по центру, 12.5px 700, letterSpacing 0.5, цвет `accent`,
паддинг 6/0/2 — текст «Записано в дневник · Отозвалась ✓». Под ней вторая строка «изменить можно
до полуночи»: 10.5px, цвет `accent`, пунктирное подчёркивание `frame` (тот же приём, что
у «Разложить заново» в design-system §5). Нажимаема вся связка — тап возвращает кнопки
с подсвеченным текущим ответом.

**Переходы.** Кнопки ↔ строка ответа — прозрачность 180 мс (значение из motion-spec §4, как
у возврата на таб); высота блока меняется мгновенно, без анимации layout — прыгающая высота
посреди скролла хуже мгновенной смены. Хаптика ответа — `hapticTap`, НЕ `hapticSuccess`:
Success бережём для настоящих побед (7-й день серии, завершённый урок).

Порядок появления при входе на таб не меняется: блок остаётся внутри `meanStyle` вместе
со «Значением дня».

### 7. Дневник в профиле (`app/(tabs)/profile.tsx`, `MonthCard`, `JournalRow`)

**Чипы-фильтры** над лентой записей, ниже карточки месяца: `Все N · ✓ N · ≈ N · ✗ N · С заметкой N`.
Разметка и значения — те же, что у чипов справочника (radius 20, паддинг 7×14, 10.5px 700,
letterSpacing 0.6, зазор 6; активный — бордер `frame`, фон `chipBg`, текст `accent`).

Это ВТОРОЕ появление чипов в проекте, значит по правилу «повторяется 2+ — выносим» разметка
переезжает из `app/(tabs)/cards.tsx` в общий компонент `src/components/FilterChips.tsx`
(лента + элемент), и справочник переводится на него. Дублировать `st.seg`/`st.segRow` нельзя.

Чип с нулевым счётчиком не показывается (тап в пустоту), «Все» — всегда первым. Смена месяца
сбрасывает фильтр на «Все». Пустой результат фильтра — `EmptyState` с текстом из
`pickPhrase('empty.filter', …)`.

⚠️ **Лента чипов идёт от края до края** (правило задачи 19, design-system §5), а у списка профиля
сейчас `paddingHorizontal: spacing.xl` на `contentContainerStyle` — он обрежет прокрутку за 24px
до края. Значит горизонтальный отступ снимается с контейнера и переезжает на сами элементы:
заголовок, ряд стат, `MonthNav`, `MonthCard`, строки записей, `EmptyState` получают
`marginHorizontal: spacing.xl`, а лента чипов держит отступ внутренним `contentContainerStyle`.
Отдельным шагом плана и с проверкой, что ничего не сдвинулось.

**Карточка месяца** (`MonthCard`): под строкой «18 записей · 5 с заметкой» добавляются
«Отозвалось 12 из 18 дней» (10.5px, `muted`) и трёхсегментная полоска: высота 4, radius 2,
отступ сверху 8, сегменты долями `yes`/`partly`/`no` цветами `success`/`accent`/`muted`, встык,
подложка `line`. Обе строки — только при `answered > 0`.

⚠️ Сейчас `MonthCard` возвращает `null`, если «карты месяца» нет (`topCount <= 1`) — тогда сводка
рефлексии в таком месяце не покажется никогда. Условие меняется: карточка рисуется, если есть
карта месяца **ИЛИ** есть хотя бы один ответ; без карты месяца мини-карта и строка «КАРТА МЕСЯЦА»
просто не рисуются.

**Строка записи** (`JournalRow`): отметка справа — `✓` цветом `success`, `≈` цветом `accent`,
`✗` цветом `muted`, 12px, прижата к правому краю (design-system §5 «Строка дневника»).
Без ответа места не занимает.

вместе с ним.

## Что НЕ делаем

Пуши целиком — разрешение с прелюдией, утренний 9:00, вечерний 21:00, экран «Напоминания»,
инвариант «2 пуша в день» (задача 06б). Начисление +3 XP за ответ (logic-spec §4) — движка XP
нет, пилюля уровня до сих пор мок, это задача 08. Снятие уже данного ответа: три состояния
плюс «передумала отвечать» — четвёртое, которого нет ни в макете, ни в спеках; передумать можно
только в пользу другого ответа. Правку ответов и заметок прошлых дней (запрещена logic-spec §3).
Аналитику `reflection_answered` — PostHog появится к запуску. Календарь-теплокарту и графики
трендов (этап 3+; «процент точности» не делаем никогда — product-spec §5).

## Расхождения с макетом → задача 15 (правило 6а-0)

1. Кнопки «Сбылось / Отчасти / Мимо» → «Отозвалась / Отчасти / Не отозвалась». Та же правка
   в product-spec §1, где формулировка продублирована.
2. Overline блока «ВЕЧЕРОМ · 21:00» → «КАК ПРОШЁЛ ДЕНЬ»: блок появляется в 18:00, и подпись
   про 21:00 обещает не то время.
3. Строка «Записано в дневник · … · изменить можно до полуночи» в макете не нажимаема — способа
   изменить ответ там нет вовсе, хотя logic-spec §3 его требует.
4. В макете нет состояния «кнопка выбранного ответа подсвечена» — оно нужно, когда кнопки
   возвращаются по тапу.
5. Плашка заметки в макете живёт только внутри блока рефлексии — в приложении это один блок,
   который вечером растёт (решение 2).

1. **Согласование рода в вопросе рефлексии.** Шаблон подставлял название карты в фразу женского
   рода («Как отозвалась {card}»), а карты бывают всех трёх родов («Туз Кубков», «Солнце»,
   «Звезда») — согласование ломалось на карте не женского рода. Исправлено привязкой согласования
   к слову «карта» (оно всегда женского рода): «Как отозвалась сегодня карта {card}?».

   окончанием вместо плюрализации i18next. Добавлены формы `_one`/`_few`/`_many` (ru) и
   `_one`/`_other` (en), переменная переименована в `count`, как того требует i18next для выбора
   формы.
