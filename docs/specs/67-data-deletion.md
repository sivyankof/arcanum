# 67 · Политика: как запросить удаление данных RevenueCat (Data Safety «удаление — Да»)

Статус: **ЗАКРЫТА 28.08 поздно вечером** (коммит `39c11e5`; срок 30 дней подтверждён Артёмом) — мелкая задача из промта сессии сабмита
(`docs/prompts/next-session-29-08-submit.md`, шаг 4). Согласование по процессу пропущено:
кода меньше 30 строк, тексты — политика, не значения карт.

## Откуда взялась

Анкета Data Safety в Play Console переписана 28.08 вечером, но вопрос «удаление данных по
запросу» отвечен **«Нет»**: ответ «Да» требует URL страницы с пошаговой инструкцией (название
приложения, что удаляется, сроки), а в `site/privacy.html` §8 сказано только «удалите
приложение» — про данные у RevenueCat (история покупок + анонимный идентификатор установки)
инструкции нет. App Privacy Apple такого поля не имеет, но текст политики один на оба магазина.

## Цель

Пользователь находит на странице политики, как удалить свои данные у RevenueCat, и по тому же
адресу Google получает инструкцию для Data Safety. Приложение и сайт остаются дословно равны
(контракт `site.test.ts`).

## Решения

- **Идентификация без аккаунта.** У записи RevenueCat нет ни имени, ни email — только
  анонимный `$RCAnonymousID`, который приложение не показывает. Запись ищется в дашборде
  RevenueCat по **номеру заказа магазина** (Apple Order ID из чека / Google `GPA.…`), поэтому
  инструкция просит приложить номер заказа. Показывать ID в приложении — отдельная задача,
  сейчас не нужна.
- **Срок — 30 дней** (норма GDPR «без неоправданной задержки, не позже месяца»). Подтверждено
  Артёмом 28.08; менять — в четырёх языках `dataText` и на странице.
- **Подписка не пропадает.** Удаление записи RevenueCat не отменяет подписку в магазине; право
  возвращается кнопкой «Восстановить покупки» на экране подписки (SDK создаёт запись заново
  из чека). Так и написано, чтобы пользователь не боялся запроса.
- **Где на странице.** Не новый раздел, а второй абзац существующего §8 «Ваши права и удаление
  данных» с якорем на заголовке: нумерация разделов не едет, `?lang=` работает как раньше.
- **Якорь и четыре языка.** `id` на странице обязан быть уникальным, а секций четыре → на
  каждом заголовке §8 свой `id="deletion-<lang>"`; `lang.js` после выбора языка ведёт
  `#deletion` к `#deletion-<lang>` (скрытая `hidden` секция браузером не скроллится).
  URL для Data Safety: `https://sivyankof.github.io/arcanum/privacy.html#deletion`.
- **Контракт.** `dataText` в приложении — четыре абзаца одним текстом, на странице абзацы 1–3
  лежат в §2, четвёртый — в §8. Проверка «страница содержит `dataText` дословно» становится
  **по абзацам** (`split('\n\n')`, каждый — `toContain`); порядок абзацев страница не держит,
  дословность каждого — держит. Плюс: якорь `deletion-<lang>` стоит внутри секции своего
  языка; `lang.js` несёт переход `#якорь → #якорь-<lang>` (контракт по исходнику).

## Что делаем — план по файлам

1. `src/lib/i18n.ts` — четвёртый абзац `about.dataText` на ru/en/es/pt (`\n\n` перед ним).
2. `src/lib/__tests__/site.test.ts` — проверка по абзацам; якорь в секции; контракт `lang.js`.
   Красный прогон: тест до правки страницы падает на всех четырёх языках (абзаца и якоря нет).
3. `site/privacy.html` — в каждой из четырёх секций: `id="deletion-<lang>"` на `<h2>` §8,
   второй абзац §8 = четвёртый абзац `dataText` (email — `mailto`).
4. `site/lang.js` — `jumpToAnchor(lang)`: если `location.hash` есть и элемент `hash-<lang>`
   найден — `scrollIntoView()`.
5. Зелёный прогон `site.test.ts`, мутации: убрать якорь одного языка / исказить слово в абзаце
   одного языка — по одному красному тесту на мутацию. `npx tsc --noEmit`, `npm test`.
6. Пуш → GitHub Pages деплоит сайт → Play Console → Data Safety → «удаление — Да» + URL.

## Что НЕ делаем

- Не показываем `$RCAnonymousID` в приложении и не строим форму запроса.
- Не трогаем §2 и нумерацию разделов; `terms.html`/`support.html` без изменений.
- Не пересказываем текст в App Privacy Apple — там поля «удаление по запросу» нет.

## Критерии приёмки («готово, когда…»)

- [ ] `about.dataText` четырёх языков заканчивается абзацем про удаление данных RevenueCat.
- [ ] `privacy.html` §8 каждого языка несёт тот же абзац и якорь `deletion-<lang>`.
- [ ] `privacy.html#deletion` на живом сайте открывает §8 на языке браузера.
- [ ] `site.test.ts` зелёный; красный прогон и две мутации зафиксированы в отчёте.
- [ ] Data Safety в Play Console: «удаление по запросу — Да», URL с якорем; анкета сохранена.
