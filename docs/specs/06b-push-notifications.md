# Спека 06б · Локальные пуши

Статус: на согласовании · Дата: 12.08.2026 · Задача: `docs/backlog.md` → 06б · Предшественник: 06а
Поведение: `docs/product-spec.md` §1, §5, §6 · Данные и правила: `docs/logic-spec.md` §7, §8, §9 ·
Тон: `docs/content-guide.md` · Значения: `docs/design-system.md` §5

## Цель

Ежедневная петля пока держится на том, что человек сам вспомнит про приложение. Пуши — единственное,
что работает, когда приложение закрыто: утром зовут вытянуть карту, вечером — ответить, отозвалась ли
она. Задача 06а сделала вечерний блок, но увидеть его можно, только зайдя в приложение вечером
по своей воле.

Вторая цель — техническая: все правила расписания из `logic-spec §8` должны стать проверяемым кодом,
а не пожеланием. «Максимум 2 пуша в день» — жёсткий инвариант, и он должен быть покрыт тестом.

## Решения брейншторма (12.08)

1. **Берём все четыре пуша сразу** (утренний, вечерний, спасение серии, возврат), а не два.
   Правила приоритета и инвариант «не больше 2 в день» имеют смысл, только когда претендентов
   больше двух; при реализации «на два пуша» эту логику пришлось бы переписывать в следующей задаче.
   Все четыре — одна таблица правил в одной чистой функции, кода прибавляется немного.

2. **Механизм — горизонт с перепланированием, а не повторяющийся `DAILY`-триггер.**
   `DAILY` ставится один раз и шлёт безусловно: карту открыл в 8:50 — в 9:00 всё равно прилетит
   «ваша карта уже ждёт»; рефлексию дал в 19:00 — в 21:00 всё равно спросят про день. Три правила
   из четырёх в `logic-spec §8` условные, а спасение серии и возврат на `DAILY` не выражаются вовсе.
   Решение: чистая функция считает конкретные «дата + время + текст» на горизонт вперёд, адаптер
   снимает всё запланированное и ставит заново в пяти точках (гидрация стора, возврат из фона,
   открытие карты дня, ответ рефлексии, смена настроек).

3. **Время — системное колесо на телефоне, список часов в вебе.** Артём выбрал родной жест и минуты
   (сравнение макетов — визуальный компаньон, 12.08). Своего колеса нет в react-native-web, поэтому
   список часов пишется всё равно; он же остаётся единственным способом прокликать экран в браузере
   на шаге 6а. Цена решения — два компонента вместо одного, оба за одним интерфейсом `TimePicker`.

4. **Отдельного экрана «Напоминания» не делаем** — строки живут прямо в `app/settings.tsx`
   (решение Артёма 12.08 против исходного предложения). Спасение серии и возврат своих тумблеров
   не получают, но и молчаливыми не остаются: под группой — приглушённая поясняющая строка.

5. **DEV-инструменты входят в задачу** (просьба Артёма 12.08). Без них проверка пуша означает
   ожидание до 9:00 следующего дня; с ними доставка проверяется за 10 секунд, а работа планировщика —
   мгновенно, списком запланированного.

6. **Тексты писать не нужно.** Все четыре ключа уже лежат в `content/phrases.json`
   (`push.morning_card` — 4 варианта, `push.evening_reflect` — 3, `push.streak_save` — 2,
   `push.winback` — 2) и согласованы по роду через слово «карта». Задача только подключает их
   через `pickPhrase` (правило вариативности, `logic-spec §9`).

7. **Слушатель `AppState` выносится в общий хук.** В 06а он написан прямо в `app/(tabs)/index.tsx`;
   планировщику нужен второй такой же. Второе появление — выносим в `src/lib/useAppActive.ts`
   (главное правило проекта), экран «Сегодня» переводим на общий хук без изменения поведения.

## Что делаем

### 1. Пакеты и конфигурация

```
npx expo install expo-notifications @react-native-community/datetimepicker
```

Оба есть в Expo Go SDK 54: локальные уведомления работают и на iOS, и на Android (удалённые
на Android с SDK 53 требуют dev-build — они нам не нужны, сервера нет). Веба нет ни у того,
ни у другого.

`app.json` **не трогаем**: config-плагин `expo-notifications` (иконка и цвет уведомления на Android)
в Expo Go не применяется, а в релизной сборке понадобится вместе с иконкой — это хвост
в `release-checklist`, не в эту задачу.

### 2. Данные и стор (`src/store/useApp.ts`)

```ts
export interface AppSettings {
  reflectionOn: boolean;
  /** Наше согласие на напоминания (системное разрешение — отдельно, у ОС). */
  pushesOn: boolean;
  pushMorning: string;   // 'HH:MM'
  pushEvening: string;   // 'HH:MM'
  /** Прелюдия показана — второй раз не спрашиваем (product-spec §1). */
  pushAsked: boolean;
}

const DEFAULT_SETTINGS: AppSettings = {
  reflectionOn: true,
  pushesOn: true,
  pushMorning: '09:00',
  pushEvening: '21:00',
  pushAsked: false,
};
```

Экшены: `setPushesOn(on)`, `setPushTime(kind: 'morning' | 'evening', hhmm: string)`, `setPushAsked()`.

⚠️ **`version: 3` + миграция обязательны.** `zustand/persist` сливает сохранённое состояние
с дефолтом только по верхнему уровню ключей: сохранённый `settings: {reflectionOn: true}` заменит
объект целиком, и четыре новых поля у уже установленного приложения не появятся. Существующий
`migrate` дописывает недостающие ключи руками — правило из `logic-spec §7`, поднимаем версию
и оставляем ту же строку слияния.

### 3. `src/lib/pushPlan.ts` — чистые правила (сердце задачи)

Ни одного импорта из `expo-*`, `react` или темы — как `journal.ts` и `reflection.ts`.

```ts
export type PushKind = 'morning' | 'evening' | 'streak' | 'comeback';

export interface PlannedPush {
  kind: PushKind;
  date: string;        // локальная дата 'YYYY-MM-DD'
  hour: number;
  minute: number;
  phraseKey: string;   // ключ в phrases.json, НЕ готовый текст
  cardId?: string;     // подстановка {card} у вечернего
  n?: number;          // подстановка {n} у спасения серии
}

export interface PlanInput {
  pushesOn: boolean;
  reflectionOn: boolean;
  morning: string;            // 'HH:MM'
  evening: string;
  streak: number;
  todayCardId?: string;       // карта дня открыта сегодня
  todayOutcome?: Outcome;     // ответ рефлексии уже дан
}

export function planPushes(input: PlanInput, now: Date): PlannedPush[];
```

Возвращается **ключ фразы**, а не текст: функция не знает ни про язык, ни про контент — тот же
принцип, по которому `journal.ts` хранит имя токена цвета, а не сам цвет. Текст собирает адаптер.

**Константы:** `MORNING_AHEAD_DAYS = 3`, `COMEBACK_AFTER_DAYS = 4`, `STREAK_SAVE_HOUR = 20`,
`STREAK_MIN = 3`, `MAX_PER_DAY = 2`, `PRIORITY = ['streak', 'evening', 'morning', 'comeback']`.

**Таблица правил.** Отсчёт идёт от **дня перепланирования**, то есть от сегодня: планировщик
работает только тогда, когда приложение открыли, — значит сегодня активность точно была.
Перебираем дни от сегодня до `сегодня + COMEBACK_AFTER_DAYS`; всё, что уже в прошлом
относительно `now`, отбрасывается.

| Пуш | Время | Условия |
|---|---|---|
| `morning` | `pushMorning` | `pushesOn`; на сегодня — только если карта дня НЕ открыта; на будущие дни — если `1 ≤ D − сегодня ≤ 3` |
| `evening` | `pushEvening` | `pushesOn` и `reflectionOn`; **только сегодня**; карта открыта (`todayCardId`); ответа нет (`todayOutcome` пуст) |
| `streak` | 20:00 | `pushesOn`; **только сегодня**; карта НЕ открыта; `streak ≥ 3` |
| `comeback` | время утреннего | `pushesOn`; ровно один, на день `сегодня + 4` |

Почему два правила «только сегодня»:

- **вечерний** называет карту по имени; карта завтрашнего дня детерминирована и известна, но откроет
  ли её человек — неизвестно, а пуш про неоткрытую карту обещает то, чего не было. Поэтому вечерний
  рождается в момент открытия карты — это одна из пяти точек перепланирования;
- **спасение серии** имеет смысл, пока день не кончился: не открыл сегодня — завтра серия уже
  сброшена, спасать нечего.

**Финальная обрезка.** После сборки список группируется по дате, каждый день сортируется по `PRIORITY`
и режется до `MAX_PER_DAY`. По построению спасение серии (карта закрыта) и вечерний (карта открыта)
несовместимы, а утренние и возвратный не попадают на один день — то есть обрезка почти всегда
холостая. Она всё равно нужна: инвариант `logic-spec §8` должен быть выражен в коде и покрыт тестом,
а не держаться на рассуждении.

**Тишина вместо спама.** Утренние ставятся максимум на три дня вперёд, на четвёртый приходит один
`comeback`, дальше — ничего до возвращения: перепланирование не случится, пока приложение не откроют.
Забросивший приложение человек получает три утренних и один возвратный — ровно то, что `logic-spec §8`
описывает как «3+ дня тишины → один пуш, не спамим». Всего в очереди максимум шесть уведомлений,
в лимит iOS (64 запланированных) не упираемся даже близко.

### 4. `src/lib/pushes.ts` — адаптер над `expo-notifications`

Единственный файл, знающий про Expo. Все функции на вебе — пустышки (`Platform.OS === 'web'` →
ранний выход), чтобы браузер не падал и экран настроек оставался живым.

- `initPushes()` — `setNotificationHandler` (`shouldShowBanner: true`, `shouldShowList: true`,
  без звука и бейджа) + канал уведомлений для Android (обязателен с Android 8). Идемпотентна.
  ⚠️ Без хендлера баннер не показывается, когда приложение открыто, — тестовый пуш выглядел бы
  сломанным.
- `getPermissionStatus()` / `requestPermission()` — обёртки над `getPermissionsAsync` /
  `requestPermissionsAsync`.
- `applyPlan(plan, lang)` — `cancelAllScheduledNotificationsAsync()`, затем на каждый пункт
  `scheduleNotificationAsync` с триггером `{ type: SchedulableTriggerInputTypes.DATE, date }`.
  Нет системного разрешения → снимает всё и выходит.
- `listScheduled()` — `getAllScheduledNotificationsAsync()` для DEV-строки.

**Сборка текста:** `pickPhrase(phrases[phraseKey], push.date, phraseKey)` → подстановка `{card}`
(название карты из `cardById` на текущем языке), `{n}` (длина серии) и `{days}` (та же длина
серии, но готовой плюрализованной строкой «N дней» — собрана i18next до подстановки, нужна там,
где сырое {n} дало бы неверное согласование вроде «Серия 3 дней»; появилась во второй волне
фиксов 06б, используется в `push.streak_save`). Заголовок — короткая i18n-строка по типу пуша,
тело — выбранная фраза.

Конкретный триггер `DATE`, а не `DAILY`, — сознательно: перевод часов и смена часового пояса
не ломают план, потому что он пересчитывается при каждом возврате из фона.

### 5. `src/lib/useAppActive.ts` + `src/lib/usePushScheduler.ts`

`useAppActive(cb)` — общий хук: подписка на `AppState` и вызов `cb` при переходе в `active`.
Выносится из `app/(tabs)/index.tsx` (второе появление), экран «Сегодня» переводится на него
без изменения поведения.

`usePushScheduler()` — вызывается один раз в `app/_layout.tsx`. Читает из стора срез
(`settings`, `streak`, сегодняшняя запись дневника), собирает `PlanInput`, вызывает
`planPushes` → `applyPlan`. Срабатывает на изменение любого из этих значений и на `useAppActive`.
Первый запуск после гидрации — там же.

### 6. Прелюдия разрешения (`app/(tabs)/index.tsx`)

После первого переворота карты дня, если `!settings.pushAsked` — `ConfirmDialog`:
«Напомнить о вашей карте завтра утром?» с кнопками «Напомнить» / «Не сейчас». `pushAsked`
ставится при любом ответе, «Напомнить» вызывает `requestPermission()`.

Прелюдия нужна потому, что системный диалог даётся один раз навсегда: показать его на пустом
экране — значит потерять согласие безвозвратно (`product-spec §1`, master-plan п. 18).

### 7. Настройки (`app/settings.tsx`) и `src/components/TimePicker.tsx`

Строки после «Вечерней рефлексии»:

- **«Напоминания»** — мастер-тумблер (`pushesOn`), значение «Вкл» / «Выкл».
- при включённом — **«Утреннее · 9:00»** и **«Вечернее · 21:00»**, тап открывает `TimePicker`.
- под группой — приглушённая строка: «Ещё напомним, если серия под угрозой, и один раз — если
  вы давно не заходили». Единственное место, где можно рассказать про два молчаливых пуша.
- если системное разрешение отклонено — значение строки «Напоминания» меняется на «Выключены
  в системе», тап открывает `Linking.openSettings()`; своим диалогом не переспрашиваем.

`TimePicker` — один интерфейс, две реализации: натив — `@react-native-community/datetimepicker`
в режиме `time`; веб — модалка со списком целых часов (утро 7:00–11:00, вечер 19:00–23:00)
в токенах темы. Наружу отдаёт `'HH:MM'`.

### 8. DEV-инструменты (`__DEV__`, рядом с уже существующими)

- **«DEV · тестовый пуш»** — ставит уведомление через 10 секунд (успеть свернуть приложение)
  с настоящим текстом утреннего варианта. Проверяет разрешение, доставку и вид баннера.
- **«DEV · план пушей»** — `ConfirmDialog` со списком запланированного: тип, дата, время.
  Проверяет планировщик целиком и мгновенно.

### 9. Тексты (i18n, ru + en)

Новые UI-строки: заголовки пушей по типам, названия строк настроек, подпись про молчаливые пуши,
кнопки прелюдии, «Выключены в системе», заголовки `TimePicker`, DEV-строки.
Тела пушей берутся из `content/phrases.json` — там всё уже написано, дописывать нечего.

## Что НЕ делаем

- **Удалённые пуши и токены** — сервера нет и в v1 не будет.
- **Веб-уведомления** — `expo-notifications` веб не поддерживает; в браузере проверяется только экран.
- **Настройку времени спасения серии и возврата** — фиксированные 20:00 и время утреннего.
- **Отдельный экран «Напоминания»** — решение 12.08.
- **Выбор звука, вибрации, тихие часы** — ни в одной спеке этого нет.
- **Иконку и цвет уведомления для Android-сборки** (config-плагин) — хвост в `release-checklist`.
- **Пуши по событиям луны** — `master-plan`, этап 3+.

## Расхождения с макетом → задача 15 (правило 6а-0)

- строка «Напоминания · 9:00 · 21:00» в макете выглядит переходом на отдельный экран, а в приложении
  это тумблер + две строки времени + поясняющая подпись под группой;
- прелюдии разрешения в макете нет вовсе — а это первый экранный момент, который видит новый
  пользователь после первой карты.

## Готово, когда

- [ ] `npx tsc --noEmit` чистый, `npm test` зелёный, новый сьют `pushPlan` (~12 кейсов):
      открытая карта убирает сегодняшний утренний; выключённый `pushesOn` даёт пустой план;
      выключенная рефлексия убирает вечерний; вечерний не ставится без открытой карты и при
      уже данном ответе; серия 2 не даёт спасения, серия 3 даёт; обрезка до двух в день
      на искусственном входе; `comeback` ровно один и на четвёртый день; прошедшее время
      сегодняшнего дня не планируется; детерминизм при одном и том же входе.
- [ ] В настройках есть тумблер «Напоминания», две строки времени и поясняющая подпись;
      выключение тумблера мгновенно снимает всё запланированное (видно в «DEV · план пушей»).
- [ ] Смена времени сохраняется, переживает перезапуск приложения и сразу меняет план.
- [ ] Старые данные не потерялись после `version: 3`: серия, история, заметки и ответы на месте,
      а новые поля `settings` появились у уже установленного приложения (проверка миграции).
- [ ] Прелюдия показывается ровно один раз после первого переворота карты; «Не сейчас» не спрашивает
      снова; отказ в системном диалоге переводит строку в «Выключены в системе».
- [ ] «DEV · тестовый пуш» доставляет уведомление за 10 секунд; баннер виден и при открытом
