## Цель

Закрыть три бага аудита: (H1) фаза луны врёт вблизи новолуния/полнолуния; (H2) день считается
по UTC — в UTC+3 до 03:00 карта «вчерашняя» и серия рвётся; (H3) seed=0 у всех — вся аудитория
видит одну и ту же карту дня.

## H1 · Луна: симметричные окна фаз (`src/lib/moon.ts`)

Заменить `PHASE_BOUNDS` (1.85 / 14.77 / 16.61 — окна лежат целиком ПОСЛЕ точных моментов)
на симметричные окна вокруг точек. Точки: новолуние — возраст 0, полнолуние — `SYNODIC_MONTH / 2`
(≈14.7653). Полуширина окна — константа `HALF_WINDOW = 0.92` суток. Границы выражать через
константы, магические числа не хардкодить:

- `new`: возраст < 0.92 ИЛИ возраст ≥ `SYNODIC_MONTH − 0.92` (≈28.6106)
- `full`: |возраст − `SYNODIC_MONTH / 2`| < 0.92 (≈13.8453…15.6853)
- `waxing`: 0.92 ≤ возраст < 13.8453 · `waning`: 15.6853 ≤ возраст < 28.6106

`moonAge` / `lunarDay` / `moonInfo` не меняются.

**Тесты** (`src/lib/__tests__/moon.test.ts`): describe «границы фаз» переписать под новые пороги —
пары (в сутках от эпохи): 0.91→new · 0.93→waxing · 13.84→waxing · 13.85→full · 15.68→full ·
15.69→waning · 28.60→waning · 28.62→new. Добавить describe «реальные даты (logic-spec §6)», UTC
(возрасты проверены расчётом): 2025-08-23T06:06Z (28.83)→new · 2025-08-09T08:00Z (14.91)→full ·
2025-08-28T00:00Z (4.04)→waxing · 2025-08-15T00:00Z (20.57)→waning. Остальные кейсы валидны
и остаются как есть (включая at(-1)→waning: 28.53 < 28.61).

## H2 · Границы дня — локальные (`src/lib/dates.ts` новый)

Дата-строка нужна в 3+ местах (useApp ×3, экран «Сегодня», далее дневник/рефлексия) → выносим
в общий модуль. Чистые функции:

- `localDateISO(d = new Date()): string` — `YYYY-MM-DD` из ЛОКАЛЬНЫХ `getFullYear/getMonth/getDate`
  с паддингом нулями. Никакого `toISOString` (он даёт UTC — это и есть баг).
- `daysAgoISO(n: number, from = new Date()): string` — `localDateISO(new Date(y, m, date − n))`;
  конструктор Date сам нормализует переход месяца/года, безопасно при переводе часов.

Замены: `src/store/useApp.ts` — удалить локальный `todayStr`, всюду `localDateISO()`;
`yesterday` → `daysAgoISO(1)`. `app/(tabs)/index.tsx:145` — `todayISO = localDateISO()`.
После правки `toISOString` в `src/` и `app/` не встречается нигде (проверить grep'ом).

**Тесты** (`src/lib/__tests__/dates.test.ts`) — от локальных компонентов (контракт не зависит
от TZ машины): `new Date(2026, 7, 9, 0, 0, 1)` → `'2026-08-09'` (сразу после полуночи);
23:59:59 → тот же день; паддинг: 5 января → `'2026-01-05'`; `daysAgoISO(1)` от 1 марта 2026 →
`'2026-02-28'`, от 1 марта 2024 (високосный) → `'2024-02-29'`, от 1 января → `'…-12-31'`;
`daysAgoISO(7)` — обычный случай внутри месяца.

## H3 · installSeed + FNV-1a + анти-повтор (`useApp.ts`, `content.ts`, `index.tsx`)

**Store (`src/store/useApp.ts`):**
- Поле `installSeed: number`, начальное значение 0 (маркер «ещё не назначен»).
- В persist-опции `onRehydrateStorage`: после гидрации, если `installSeed === 0` —
  `setState({ installSeed: 1 + Math.floor(Math.random() * (2 ** 31 - 1)) })` (диапазон 1…2³¹−1,
  0 исключён). Так сид сразу записывается в AsyncStorage; срабатывает и на свежей установке,
  и у существующих пользователей после обновления. Уже открытая сегодня карта не изменится —
  она читается из history.
- Persist-опция `version: 1` + `migrate: (s) => s` (данные не преобразуем, схема записей та же).
  Это `schemaVersion` из logic-spec §7 — отдельное поле состояния не дублируем.

**`src/lib/content.ts`:**
- `fnv1a32(s: string): number` — FNV-1a 32-bit: `h = 0x811c9dc5`; для каждого символа
  `h ^= code; h = Math.imul(h, 0x01000193) >>> 0`; вернуть `h >>> 0`.
- `cardOfDay(dateISO: string, seed: number, recentCardIds: string[] = []): TarotCard` —
  `index = fnv1a32(dateISO + ':' + seed) % 78`; анти-повтор: пока `cards[index].id` есть
  в `recentCardIds` — `index = fnv1a32(index + ':retry:' + n) % 78`, n = 1…10; после 10 попыток —
  как есть (logic-spec §1 дословно). Старый параметр `userSeed = 0` и простой хеш удалить.

**`app/(tabs)/index.tsx`:** `seed` из стора; `recent` = id карт history за последние 7 дней
(`h.date >= daysAgoISO(7)` и `h.date !== todayISO`); `cardOfDay(todayISO, seed, recent)`.

**`docs/logic-spec.md` §7:** дописать строку-уточнение «schemaVersion хранится как поле `version`
zustand persist (не в state)».

**Тесты** (`src/lib/__tests__/cardOfDay.test.ts`):
- детерминизм: seed 42 + `'2026-08-08'` → 100 вызовов, один и тот же id (кейс §1);
- разные сиды → разные последовательности: массивы id за 30 дней для сидов 1 и 2 не равны;
- анти-повтор: положить «естественный» id в recentCardIds → вернётся другой id; все 78 id
  в recentCardIds → не зависает, возвращает карту (лимит 10 ретраев);
- распределение (testing-strategy): 1000 сидов, одна дата → ни одна карта чаще 3% (≤30 из 1000).
