# Спека 42 — карта дня: резкость после переворота (+ задача 40: золочёные уголки)

Две задачи бэклога одной веткой, потому что обе правят одну и ту же лицевую грань карты дня
на экране «Сегодня» и проверяются одним прогоном на устройстве:
- **42** — карта дня замылена после переворота (две независимые причины);
- **40** — золочёные уголки карты дня: в макете есть, в приложении нет.

Ветка `feat/42-day-card-sharpness`, план `docs/plans/42-day-card-sharpness.md`, скриншоты
`docs/screenshots/42/`.

## Решения (брейншторм 18.08, ответы Артёма по визуальному превью)

1. **Уголки — вариант 2:** уголки на ОБЕИХ гранях карты дня, как в макете (рубашка и лицо;
   design-system §5 «рубашка и лицо в момент ритуала»); ярлычок «можно увеличить» на лице
   сдвигается с инсета 6/6 на **9/9** и садится ВНУТРЬ правого верхнего уголка — уголок «держит»
   его с двух сторон. Отвергнуто: ярлычок поверх уголка (как в макете сейчас), ярлычок под уголком
   (26/6), уголки только на рубашке, убрать уголки из макета.
2. **Исходники карт — все 78 со сканов Wikimedia Commons, ширина 900 px, JPEG.** Комплект
   проверен 18.08: файлы `RWS Tarot NN <Name>.jpg` (22 старших) и `<Suit>NN.jpg` (Cups/Wands/
   Swords/Pents 01–14) — все 78 есть, ~1100×1920 px, public domain, суммарно 70 МБ оригиналов.
   900 px покрывает самую крупную поверхность при 1x — полноэкранный просмотр 390 pt (1170 px
   при 3x, растяжение 1.3 — порог заметности из замеров задачи 36). Отвергнуто: 660 px (только
   карта дня, лайтбокс остаётся мягким), «только причина 1» (растяжение ×2.2 остаётся).
3. **Тон сканов — как есть.** Сканы Commons теплее и желтее нынешних (бумага 1909 года), все 78
   в одном тоне, сочетается с «шампанским золотом». Цветокоррекции нет. 5 уже крупных карт (fool,
   hermit, high-priestess, magician, sun — из другого источника, 440–750 px) заменяются вместе
   со всеми: комплект один.
4. Формат — JPEG (WebP дал бы −5 МБ, но потребовал бы правки конвейера и 78 строк поля `image`
   в `cards.json`; оставлен как рычаг на будущее). Два размера thumb/full — не нужны:
   `expo-image` по умолчанию декодирует под размер вью (`allowDownscaling: true`, документация
   SDK 54), сетка справочника память не раздует.

## Цель

После переворота карта дня чёткая — и в момент завершения анимации, и при холодном старте с уже
открытой картой; все 78 изображений колоды заменены на сканы 900 px, растяжения ×2.2 больше нет
нигде (карта дня 218 pt @3x = 654 px < 900). Карта дня несёт золочёные уголки на обеих гранях
по макету, ярлычок «увеличить» вложен в уголок.

## Что делаем

### Часть А1 — осиротевший 3D-слой лицевой грани (`app/(tabs)/index.tsx`)

Диагноз задачи 36 (спека 36, «Правки по лайв-проверке», п. 1): reanimated накладывает
`perspective`/`rotateY`/`backfaceVisibility` на нативное представление императивно со стороны
UI-потока; после переворота лицо остаётся с `rotateY: 360deg` в 3D-контексте и рисуется через
offscreen-текстуру — мягко. Перестать передавать стиль недостаточно, свойства надо ПЕРЕЗАПИСАТЬ
тем же каналом. Приём — из `src/components/SpreadCard.tsx` один в один:

- shared value `settledSV = useSharedValue(!!drawn)`: при холодном старте с уже открытой картой
  лицо сразу «доехавшее» (иначе `flip = 1` держит его в 3D с первого кадра — та же мягкость,
  просто без анимации перед ней);
- `onDraw`: `settledSV.value = false` ПЕРЕД `withTiming`, в колбэке `withTiming`
  `(finished) => { if (finished) settledSV.value = true; }` — на UI-потоке, без `runOnJS`;
- эффект сброса (`!drawn` — DEV-сброс, смена даты): `settledSV.value = false` рядом с `flip = 0`;
- воркл `frontStyle`: если `settledSV.value` — `{ transform: [{ translateY: bob.value }],
  backfaceVisibility: 'visible' }` (покачивание остаётся: 2D-сдвиг 3D-контекст не создаёт);
  иначе — прежняя тройка `translateY + perspective + rotateY` и `backfaceVisibility: 'hidden'`.
  Скачка не будет: на `flip = 1` `rotateY` стоит на 360°, визуально это identity.
- Рубашку (`backStyle`) не трогаем: после переворота она невидима (rotateY 180 + hidden), при
  сбросе карты дня нужна снова, поэтому в отличие от `SpreadCard` из дерева не убирается.
- `CardLightbox` не трогаем: там карта в 3D по замыслу (параллакс от гироскопа непрерывно меняет
  `rotateX/rotateY`), снять слой нельзя; резкость просмотра поднимут новые исходники (часть А2).

### Часть А2 — исходники карт 900 px (`scripts/fetch_card_scans.py`, `assets/cards/*.jpg`)

Новый скрипт конвейера (Python, Pillow — уже используется скриптами репозитория):

- **Маппинг** 78 id → имя файла Commons: старшие — явная таблица (`fool` → `RWS Tarot 00 Fool`,
  … `world` → `RWS Tarot 21 World`; `strength` → `RWS Tarot 08 Strength`, `judgement` →
  `RWS Tarot 20 Judgement`, `wheel-of-fortune` → `RWS Tarot 10 Wheel of Fortune`, `hanged-man` →
  `RWS Tarot 12 Hanged Man`, `high-priestess` → `RWS Tarot 02 High Priestess`); младшие — по
  шаблону `c01` → `Cups01`, `w` → `Wands`, `s` → `Swords`, `p` → `Pents`.
- **Скачивание** через API Commons (`prop=imageinfo&iiprop=url` → прямой URL оригинала) с явным
  `User-Agent` (без него Commons отдаёт 403), последовательно, с паузой 0.3 с; кэш оригиналов
  в `.cache/rws-commons/` (папка в `.gitignore`), повторный запуск ничего не скачивает заново.
- **Кадрирование по чёрной рамке рисунка**: сканы — физические карты с кремовым полем и
  скруглёнными углами (поле 3–6 % с каждой стороны, слегка несимметричное). Рамка ищется
  по яркости: средняя яркость столбца по центральной полосе 30–70 % высоты (и строки — по
  30–70 % ширины); первый/последний индекс со средней < 110 — граница рамки. Кадр — рамка плюс
  поле 1.2 % ширины скана с каждой стороны (у нынешних ассетов рамка стоит у самого края;
  1.2 % оставляет тонкое поле, чтобы бордер `frame` приложения не резал рамку рисунка).
  Проверено 18.08 на трёх картах: пропорция кадра 1.71–1.73 — совпадает с `CARD_H = CARD_W × 1.72`
  и `518/300` онбординга.
- **Страховки**: найденная рамка обязана лежать в 1.5–9 % от каждого края и давать пропорцию
  кадра 1.68–1.76 — иначе карта печатается в отчёт с пометкой FAIL, файл НЕ пишется, скрипт
  завершается кодом 1 после обработки всех (странный скан не может молча уехать в ассеты).
- **Уменьшение и запись**: LANCZOS до ширины 900 (высота по пропорции), `JPEG quality=78,
  optimize=True, progressive=True`, RGB, без EXIF → `assets/cards/<id>.jpg` (имена и расширение
  прежние — `cardImages.ts`, `gen_card_images.py`, поле `image` в `cards.json` не меняются).
  Замер 18.08: ~350 КБ на карту, **~27 МБ на 78** (сейчас 3.6).
- **Отчёт**: таблица `id · источник (w×h) · рамка (l,t,r,b) · кадр (w×h, пропорция) · выход КБ`
  + итог МБ; **контакт-лист** 78 миниатюр (13×6, ~150 px шириной каждая) →
  `docs/screenshots/42/contact-sheet.jpg` — по нему кадр проверяется глазами разом.
- Аргументы: `--only id[,id…]` (перекадровать одну карту), `--width` (900), `--quality` (78),
  `--dry-run` (найти рамки и напечатать отчёт, ничего не писать). Идемпотентен.
- **Контракт-тест** `src/lib/__tests__/cardAssets.test.ts`: для каждой из 78 карт файл
  `assets/cards/<id>.jpg` существует, начинается с `FF D8`, ширина из SOF-заголовка ровно 900,
  пропорция h/w в [1.68, 1.76]. Парсер SOF — 15 строк без библиотек. Тест обязан быть КРАСНЫМ
  до замены ассетов (73 карты шириной 300) — это и есть его проверка на честность.

### Часть Б — золочёные уголки (задача 40)

- Новый общий компонент `src/components/CardCorners.tsx`: абсолютная обёртка на всю грань
  (`pointerEvents: 'none'` в стиле), четыре `Svg` 20×20 из `react-native-svg` (уже в проекте —
  `CardBackSurface`), инсет 4 от углов, поворот 0 / 90 / 180 / 270° (tl / tr / br / bl — как
  `.cnr` эталона), внутри `viewBox 0 0 24 24`: `Path d="M2 14 V6 a4 4 0 0 1 4-4 h8"` обводкой
  `accent` 1.1 без заливки + `Circle cx=2 cy=17 r=1` заливкой `accent`. Цвет — из `useTheme()`.
- Ставится РОВНО в два места (design-system §5: «золочёные уголки — ТОЛЬКО на карте дня»):
  1. рубашка карты дня — `CardBack` получает проп `corners?: boolean` (по умолчанию `false`);
     уголки рисуются ПОСЛЕ внутренней рамки и ДО эмблемы (как в разметке эталона). Карта дня
     передаёт `corners`; `CardLightbox` (рубашка в полёте — открывается и с героя страницы карты)
     и `EmptyState` не передают — там уголков быть не должно;
  2. лицевая грань карты дня — `<CardCorners />` после `Image` и блика, ПЕРЕД `CornerBadge`.
- `CornerBadge` на лице карты дня получает `style={{ top: 9, right: 9 }}` (константа
  `BADGE_INSET_IN_CORNER = 9` рядом с прочими константами экрана; в остальных местах бейдж
  остаётся 6/6 — герой страницы карты и сетка не трогаются).
- Макет `docs/design-reference.html`: одно правило CSS `.face.front .st2{top:9px;right:9px}` —
  ярлычок на лице карты дня в макете тоже уезжает внутрь уголка (сейчас перекрывает его;
  расхождение зафиксировано флагом 6а-0 в спеке 39).

## Что НЕ делаем

- Не трогаем `CardLightbox` (3D по замыслу), `SpreadCard` (уже вылечен), сетку, героя.
- Не меняем формат/имена файлов, `cardImages.ts`, `gen_card_images.py`, `cards.json`.
- Не делаем WebP, два размера, цветокоррекцию, «Источники» на экране «О приложении» (public domain,
  атрибуции не требует; «О колоде» уже называет Памелу Колман Смит).
- Уголки нигде, кроме двух граней карты дня; `EmptyState` и рубашка лайтбокса без уголков.
- **Побочная находка — в бэклог, не чиним здесь:** импорт бэкапа, в котором есть СЕГОДНЯШНЯЯ
  карта дня, при смонтированном табе «Сегодня» оставляет на экране рубашку — `flip` поднимается
  только в `onDraw`, эффект по `drawn` обрабатывает лишь сброс. Тап по такой «рубашке» открывает
  лайтбокс (drawn истинно). Проявляется только при импорте бэкапа того же дня.

## Проверка

- **6а (веб, 390×844, обе темы, скриншоты в `docs/screenshots/42/`):** «Сегодня» до переворота
  (рубашка с четырьмя уголками поверх внутренней рамки) и после (лицо с уголками, ярлычок 9/9
  внутри правого верхнего уголка) — сверить с макетом и с превью брейншторма. Резкость в вебе
  видна частично (dpr 1.5–2): снять фрагмент карты дня крупно до/после замены ассетов.
- **6б (веб):** тап по рубашке → переворот → тап по лицу → лайтбокс открывается с ярлычка;
  DEV-сброс карты → рубашка с уголками; светлая тема; консоль без новых ошибок/предупреждений
  (`props.pointerEvents is deprecated` — известный чужой, спека 39). Контакт-лист 78 миниатюр
  просмотрен: ни одного обрезанного рисунка, ни одного кремового поля шире тонкой полоски.
- **6в (устройство — единственный судья причины 1):** после переворота ПОСЛЕДНЯЯ карта чёткая
  без единого перерендера (не уходить с таба, не открывать ничего); холодный старт с уже открытой
  картой — чёткая; свернуть/развернуть — чёткая; переворот, блик, покачивание, салют, лайтбокс
  с карты дня (полёт, зум, свайп) — как раньше; уголки видны на обеих гранях в обеих темах;
  DEV-сброс → рубашка → переворот заново — чёткая.
