# Спека 14 — Полноэкранный просмотр карты («взять карту в руки»)

Статус: на согласовании у Артёма. После «ок» — детальный план в `docs/plans/14-fullscreen-card.md`
(задача 07+: ветка `feat/14-fullscreen-card`, merge после лайв-проверки).

Решения брейншторма 14.08 (согласованы с Артёмом):
- **Объём — весь §15 motion-spec в одной ветке**, коммиты по подпунктам; параллакс — последним
  коммитом, и если DeviceMotion на устройстве закапризничает, он выносится хвостом, а ядро мерджится.
- **Ассеты не трогаем**: зум ×3 на текущих сканах (~350px) будет мыльноват — известное ограничение,
  замена изображений на 2000px+ (motion-spec «Изображения») — отдельная задача после.

## Цель

Тап по изображению карты открывает её на весь экран поверх интерфейса — рассмотреть рисунок
Памелы Колман Смит в деталях. Ощущение «взял карту со стола и повернул в руке»: полёт из текущей
позиции с полным оборотом через рубашку, затем pinch-zoom, панорамирование и параллакс от наклона
телефона. Поведение — product-spec §3, анимация — motion-spec §15, макет — `.lightbox`
в design-reference.html (отрисован, дорисовки не нужны).

## Входные точки (обе в этой задаче)

1. **Страница карты** — тап по герою (`HeroImage` в `app/card/[id].tsx`; onPress у него сейчас нет).
2. **«Сегодня», карта дня ПОСЛЕ переворота** — тап по открытой карте (`app/(tabs)/index.tsx`;
   сейчас тап после переворота — no-op: `onDraw` выходит по `if (drawn) return`, конфликта нет.
   До переворота тап продолжает открывать карту дня, просмотр недоступен).

НЕ входные точки: сетка справочника (тап там ведёт на страницу карты), расклады (интерактив —
этап 5), онбординг.

## Что делаем

**Открытие (650мс, cubic-bezier(.3,.7,.3,1)):** позиция изображения меряется в момент тапа
(`measureInWindow`, тип `Rect` из `src/lib/cardTransition.ts` уже есть); копия карты летит
из этой позиции в центр экрана с ростом scale ~0.3→1 и ПОЛНЫМ оборотом `rotateY 360°→0` —
на середине полёта видна рубашка (фон `radial-gradient` из макета `.lbback`, эмблема ✶).
Параллельно scrim `rgba(4,5,14,.88)` + blur 10 (значения `.lightbox` макета). Хаптика Light
на старте, Soft на «посадке». Статус-бар скрывается на время просмотра.
⚠️ Флаг по правилу 6а-0: макет говорит 680мс (`lbspin .68s`), motion-spec §15 — 650мс.
Расхождение 30мс; делаем по motion-spec (650), макет не правим — на глаз неразличимо.

**Посадка:** блик-глейр пробегает по карте один раз (задержка 120мс после остановки, 900мс;
геометрия — `.lbglare` макета: полоса 112°, translateX −140%→140%).

**Геометрия карты:** макет 238×410 при раме ~350px → на устройстве ширина **265**, аспект 0.58
(как все карты), радиус 16, рамка 1px `frame`, тень `0 30px 80px rgba(0,0,0,.65)` пропом
`boxShadow`. Подпись внизу «НАЖМИТЕ, ЧТОБЫ ЗАКРЫТЬ» (Overline 9→10px, letterSpacing 2.5,
`muted`), ✕ — кружок 32×32 сверху-справа (18,18), бордер `line`, цвет `muted`.

**Просмотр:**
- **Pinch-zoom ×1..×3** + панорамирование при зуме >1 (границы — край картинки не уходит
  от края экрана внутрь); за пределами диапазона — упругое сопротивление, отпустил — пружина
  к границе.
- **Двойной тап** = ×2 в точку касания; двойной тап при зуме >1 = сброс к ×1 (пружиной).
- **Параллакс от гироскопа** (только устройство): карта следует за наклоном — `rotateX/rotateY`
  до ±6°, пружина damping 20, `expo-sensors` DeviceMotion 30Hz; блик смещается противофазно.
  На вебе сенсора нет — вместо параллакса медленное idle-качание как в макете (`lbidle`: 5с,
  ±2.5°/±1.5°). При reduce motion — ни того, ни другого.
- Перевёрнутая карта показывается ПРЯМОЙ (рассматриваем рисунок, а не положение).
- Кольца и фон под просмотром не анимируются (фокус и батарея — motion-spec §15).

**Закрытие:** тап по фону или по карте (одиночный, с ожиданием двойного ~250мс), свайп вниз
(карта следует за пальцем: translateY + поворот 2°, порог 120px — дальше улетает на место),
или ✕. Анимация — обратный ПОЛУоборот (180° через рубашку, 380мс cubic-in) с полётом на
исходную позицию. При зуме >1 свайп-вниз отключён (конфликт с панорамированием) — сначала
двойной тап/pinch к ×1 либо тап/✕.

**Reduce motion:** открытие/закрытие — простой fade без полёта и оборота, без глейра,
без параллакса/качания. Зум и панорамирование работают (это управление, не декор).

## Что НЕ делаем

- Не меняем изображения карт (решение выше) и не грузим отдельный «full»-размер.
- Никакого шаринга/сохранения картинки, никаких подписей с названием карты внутри просмотра —
  в макете только подсказка о закрытии.
- Не трогаем существующий перелёт сетка→страница карты (`cardTransition.ts`) — только
  переиспользуем тип `Rect`.
- Просмотр не попадает в history/навигацию: это оверлей, а не маршрут (кнопка «назад» Android —
  закрывает просмотр, не экран; в вебе URL не меняется).

## Технические решения

- **Оверлей — RN `Modal`** (transparent, statusBarTranslucent): накрывает нативную шапку стека
  и таб-бар без вмешательства в корневой layout; координаты `measureInWindow` совпадают
  с системой координат модалки. Общий компонент `src/components/CardLightbox.tsx`, локальное
  состояние на каждом экране-хозяине (глобальный стор не нужен).
- **Пакеты (`npx expo install`, оба есть в Expo Go SDK 54):** `react-native-gesture-handler`
  (pinch/pan/double-tap; требует `GestureHandlerRootView` в корне — правка `app/_layout.tsx`),
  `expo-sensors` (DeviceMotion). ⚠️ Меняется package.json → нужен npm install и перезапуск
  `npx expo start --tunnel`.
- **Чистый модуль `src/lib/lightbox.ts` с юнит-тестами:** clamp зума, границы панорамирования
  (по размерам картинки/экрана и текущему зуму), пересчёт точки двойного тапа в translate,
  правило «какие жесты активны при каком зуме» (свайп-вниз только при ×1). Тесты — в том же
  коммите, что и жесты (testing-strategy).
- Хаптика — через существующий `src/lib/haptics.ts`.

## Ограничения веб-проверки (заранее, чтобы не принять за баги)

- Хаптика и гироскоп в вебе не существуют: параллакс проверяется ТОЛЬКО на iPhone (6в),
  в вебе вместо него idle-качание.
- Pinch в браузере без тачскрина не сэмулировать — веб проверяет открытие/закрытие, двойной
  тап и панорамирование; pinch — только 6в.
- `Modal` + reanimated на вебе рендерятся, но нативная скорость полёта — судья устройство.
