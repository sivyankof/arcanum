# 56 · Сверка приложения с макетом после задач 50–54 (плановый аудит «раз в ~5 задач»)

Статус: **спека готова (23.08), ждёт «ок» Артёма**. Правило бэклога («Правила синхронизации доков»):
раз в ~5 задач сверять `design-reference.html` с реальным приложением. С задачи 50 закрыты 51, 53а,
54, 28п — аудита не было ни разу за проект; перед релизом — последняя точка, где расхождения ещё
дёшевы. Задача в `main`; найденные дефекты чинятся тут же, если ≤30 строк и без спорных решений,
остальное — задачами в бэклог с флагом 6а-0 («макет говорит X, спека Y»).

## Цель

Пары «экран приложения ↔ вью макета» отсняты в одном масштабе в обеих темах, прочитаны по чек-листу
`docs/ui-verification.md` §6а, и по каждой паре записан вердикт: совпадает / расхождение (чинить здесь)
/ расхождение (задача в бэклог) / расхождение макета со спекой (дорисовка, Cowork). Плюс один полный
проход 6б (прокликивание) по табам и основным маршрутам с чистой консолью.

## Решения
- **Д1. Скриншоты — скриптом, не руками.** `scripts/shoot_56.js` (Playwright из кэша npx, рецепт
  в `AGENTS.md`): вьюпорт 390×844, сид состояния через `goto → evaluate → reload` (форму сида
  брать из `scripts/check_53_web.js`, не сочинять), обе темы через стор (`settings.theme` — ключ
  смотреть в сиде соседнего сценария), язык ru. Макет: `file:///…/docs/design-reference.html`,
  `page.evaluate(() => show('v-…'))` + `document.getElementById('sc').dataset.mode = 'dark'|'light'`,
  скриншот `#sc` (350×750 — масштаб приведён к 390 шириной при сравнении глазами, не пиксель-в-пиксель:
  макет и RN-web рендерят шрифты по-разному, урок задачи 01). Папка `docs/screenshots/56/`:
  `<pair>-app-dark.png`, `<pair>-app-light.png`, `<pair>-mock-dark.png`, `<pair>-mock-light.png`.
- **Д2. Пары (16).** Порядок — как в приложении:

  | пара | приложение | макет | сид/состояние |
  |---|---|---|---|
  | today | `/` (tabs/index) | `v-today` | карта дня открыта и закрыта — два кадра |
  | course | `/course` | `v-course` | прогресс М1 частично, free |
  | cards | `/cards` | `v-cards` | фильтр «Все», 3–5 изученных |
  | spreads | `/spreads` | `v-spreads` | free, лунная панель вне окна |
  | profile | `/profile` | `v-profile` | аркан рождения задан, серия 5 |
  | detail | `/card/fool` | `v-detail` | верх + вкладка сферы (два кадра) |
  | lesson | `/lesson/m1l1` | `v-lesson` | теория → вопрос → итог (три кадра) |
  | trainer | `/review` | `v-trainer` | toMeaning лицом, toCard рубашкой (два кадра) |
  | moon | `/moon` | `v-moon` | текущий месяц |
  | moonspread | `/spreads/new-moon` (id — из `spreads.json`) | `v-moonspread` | окно открыто DEV-строкой |
  | spread3 | `/spreads/three-cards` (id уточнить) | `v-spread3` | до и после раскладки (два кадра) |

  | onboarding | `/onboarding` | `v-ob` | шаги 1–3 (три кадра; `profile.onboarded=false`) |
  | paywall | `/paywall` | `v-paywall` | состояние А (не куплено) и Б (куплено) |
  | settings | `/settings` | `v-settings` | пуши включены |
  | about | `/about` | `v-about` | — |

  Без пары в макете (сверять только с design-system.md и product-spec): `note/[date]` (запись
  дневника), `spread/[ts]` (сохранённый расклад). `v-quest`, `v-widget` — v2/EAS, не снимаем.
- **Д3. Вердикт — по чек-листу §6а, восемь пунктов на пару** (композиция, фон, типографика, цвета
  пипеткой ±5 %, отступы, рамки карт, обе темы, анимации — последний по Playwright-замеру только там,
  где движение есть). Таблица в отчёте: `пара · пункт · ожидание (макет/спека) · факт · вердикт`.
  ⚠️ 6а-0: прежде чем чинить по макету — проверить, не противоречит ли макет product-spec/
  design-system; если противоречит — чинить по спеке, расхождение макета — строкой в раздел
  «дорисовки Cowork» отчёта. Известные принятые отличия НЕ считать находками (список в CLAUDE.md:
  место плашки «ПРЕМИУМ» в шапке модуля, «назад» из лунного расклада → Расклады, контраст чипа
  мастерства, отсутствие дисклеймера в `v-onboarding` макета — уже в хвостах).
- **Д4. Порог «чиним здесь»**: правка ≤30 строк, без новых компонентов, без изменения поведения,
  без спорного решения (цвет/отступ/размер по design-system). Иначе — задача в бэклог с номером,
  скриншотами и цитатой спеки. Сквозное правило: перед правкой стиля грепнуть, не общий ли это
  компонент (DRY по всему проекту) — править в компоненте, а не в экране.
- **Д5. 6б один раз целиком**: пять табов, табы сфер карты, фильтры справочника, один урок до итога,
  одна сессия тренажёра до итога, один расклад до сохранения, смена темы и языка в профиле
  (ru→en→es→pt→ru), пейвол открыть/закрыть — консоль без красных; warnings списком.

## Что делаем
1. `scripts/shoot_56.js` — скрипт съёмки (и красный прогон: намеренно неверный селектор/маршрут
   обязан упасть, а не отснять пустоту; проверка «скриншот не пустой» — по размеру файла или по
   тому, что на странице есть ожидаемый заголовок).
2. Съёмка всех пар в обеих темах → `docs/screenshots/56/`.
3. Чтение пар по чек-листу, таблица вердиктов в отчёте (в конце этой спеки).
4. Правки «чиним здесь» — по одной на коммит, каждая: design-system.md значение → код в общем
   компоненте/экране → пересъёмка пары → строка в таблице «исправлено».
5. Бэклог: задачи на то, что не влезло в порог (с номерами 58+), и список дорисовок макета
   (одним промтом Cowork `docs/prompts/56-mockup-tails.md`).
6. 6б-проход, отчёт консоли.
7. Документы: backlog (56 `[x]` после лайва), changelog, CLAUDE.md статус; ui-verification.md —
   если чек-лист устарел (в нём «8 раскладов» — сейчас 10, «RU↔EN» — 4 языка), поправить.

## Что НЕ делаем
- Не перерисовываем макет сами (дорисовки — Cowork по промту).
- Не меняем поведение/логику ради совпадения с макетом — только визуал по design-system.
- Не трогаем анимации без замера (motion-spec правится отдельной задачей, если найдётся расхождение).
- Не снимаем `v-quest`/`v-widget`.
