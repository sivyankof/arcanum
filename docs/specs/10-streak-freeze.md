# Спека 10 · Заморозка серии

Статус: реализована, веб-проверка 6а/6б и лайв-проверка на iPhone пройдены 14.08.2026 ✓ · Правила механики: logic-spec §2 · Эталон третьей статы:
docs/design-reference.html, профиль (`.statrow` → `.statbox` «ЗАМОРОЗКА ❄») · Значения: docs/design-system.md

## Цель

Пропуск одного дня перестаёт сжигать серию: раз в месяц пользователь бесплатно получает
заморозку, она тратится сама, серия выживает, человек узнаёт об этом из пуша и строки на
«Сегодня». Профиль получает третью стату «ЗАМОРОЗКА» (хвост задачи 16 — ряд уже рассчитан
на три коробки).

## Решения (согласованы с Артёмом 14.08)

1. **Сообщение о спасении** — строка под рядом пилюль на «Сегодня», висит весь день спасения
   (переживает перезапуск). Не тост: после перезапуска объяснение «почему снежинок стало
   меньше» должно оставаться на месте.
2. **Стартовый баланс** — 1 заморозка сразу: и у новой установки, и у существующих
   пользователей после обновления (совпадает с «1» в макете профиля).
3. **Пуш «серию спасла заморозка»** — при любой длине спасённой серии: он не добавляет шума,
   а заменяет обычный утренний пуш того же времени на более точный текст.
4. **Вечерний пуш «серия под угрозой» (20:00) не меняется** при наличии заморозки: серия
   и правда под угрозой — заморозка спасёт только при возврате завтра, а пропуск двух дней
   убьёт серию в любом случае.

## Механика (logic-spec §2, уточнения фиксируются этой спекой)

- **Начисление.** +1 заморозка 1-го числа месяца, накопление максимум 2 (`FREEZE_MAX`).
  Фоновых задач у офлайн-приложения нет, поэтому начисление ленивое: при первом открытии
  приложения в новом месяце (гидрация стора + возврат из фона — `useAppActive`; переход
  через полночь 1-го числа с приложением на экране догонит следующая активация). Пропущено
  несколько месяцев → доначисляется по одному за каждый, с потолком 2.
- **Трата.** Событие серии — только открытие карты дня (как раньше). При открытии:
  - `lastDrawDate == вчера` → `streak + 1` (как раньше);
  - `lastDrawDate == позавчера` **и** `freezes > 0` → `streak + 1`, `freezes − 1` —
    пропущенный день укрыт заморозкой, в счёт серии он не входит (5 → пропуск → 6);
  - иначе → `streak = 1`, заморозки не тратятся (пропуск 2+ дней спасать нечем — logic-spec §2).
  Трата не зависит от длины серии — правило простое и предсказуемое.
- **XP не начисляется** за спасение — только обычные +5 за карту дня.

## Что делаем

### 1. Чистый модуль `src/lib/streak.ts` (новый) + тесты

- `FREEZE_MAX = 2`.
- `advanceStreak({streak, lastDrawDate, freezes}, todayISO)` → `{streak, freezes, freezeSpent}` —
  правила из «Механики». Вся арифметика серии уезжает сюда из `drawToday` (стор только
  применяет результат — как `completeLessonProgress`).
- `grantFreezes({freezes, freezeMonth}, todayISO)` → `{freezes, freezeMonth}`:
  `freezeMonth === null` → инициализация текущим месяцем БЕЗ начисления (стартовая 1 уже
  «за этот месяц»); тот же месяц → без изменений; новый месяц → `min(2, freezes + прошло_месяцев)`.
- Тест-кейсы (`__tests__/streak.test.ts`): подряд; пропуск 1 дня с заморозкой (5→6, 1→0);
  пропуск 1 дня без заморозки (→1); пропуск 2 дней с заморозкой (→1, заморозка цела);
  первый draw (`lastDrawDate: null`); инициализация месяца; тот же месяц; +1 через месяц;
  потолок 2; пропуск 3 месяцев с 0 → 2.

### 2. Стор `src/store/useApp.ts` — persist version **7**

- Новые ключи ВЕРХНЕГО уровня (поверхностное слияние дольёт дефолты само, ловушка 06а
  не бьёт): `freezes: 1`, `freezeMonth: null`, `freezeSpentDate: null`.
- `drawToday` → через `advanceStreak`; при `freezeSpent` пишет `freezeSpentDate = сегодня`.
- Новый экшен `syncFreezeGrant()` — применяет `grantFreezes`, зовётся из `onRehydrateStorage`
  (рядом с installSeed) и по возврату из фона (`useAppActive` в `app/_layout.tsx`).
- DEV `resetToday`: если `freezeSpentDate === сегодня` — вернуть заморозку и очистить поле
  (иначе при отладке заморозка утекает).

### 3. Пуш «серию спасла заморозка» — `src/lib/pushPlan.ts`

- Новый вид `'freeze'`, фразы `push.freeze_saved`, время — слот утреннего пуша.
  Ставится ВМЕСТО утреннего пуша своего дня (не добавляется к нему).
- День под план «пользователь больше не открыл приложение» (как весь pushPlan):
  - карта сегодня открыта → freeze-пуш на **послезавтра** (завтра — обычный утренний);
  - карта не открыта, `lastDrawDate == вчера` → freeze-пуш на **завтра**;
  - `lastDrawDate` старше → серию к утру уже не спасти, freeze-пуш не ставится.
  Условия: `freezes > 0` и `streak ≥ 1`. Несёт `n = streak` (для `{days}`).
- `PlanInput` += `freezes`, `lastDrawDate`; `planInputFromStore` — новые параметры
  (обновить `usePushScheduler` и DEV-план в `app/settings.tsx`).
- `PRIORITY`: `['streak', 'evening', 'freeze', 'morning', 'comeback']` (на практике freeze
  один в своём дне — порядок нужен обрезке `capPerDay` формально).
- `src/lib/pushes.ts`: `TITLE_KEY.freeze = 'push.titleFreeze'` (веб-адаптер `pushes.web.ts`
  заголовков не собирает — проверить и не трогать без нужды). `pushBody` уже умеет `{days}`.
- Тесты pushPlan: все три случая размещения; freeze заменяет утренний, а не дублирует его;
  `freezes: 0` → freeze-пуша нет.
- ⚠️ **В САМ день спасения (`lastDrawDate == позавчера`, карта сегодня ещё не открыта) freeze-пуш
  не планируется** — по построению: вид `'freeze'` присваивается ТОЛЬКО дням цикла `d = 1..3`
  (будущим относительно `now`), а пуш на сегодня, пока `!drawn`, всегда безусловно `'morning'`
  (строка 118). Второе следствие того же построения: freeze-пуш, уже стоявший в очереди на
  сегодня (поставлен вчерашним пересчётом, когда сегодня было «завтра» и условие `lastDrawDate ==
  вчера` выполнялось), при СЕГОДНЯШНЕМ пересчёте (открыл приложение до утреннего слота, карту
  ещё не тронул) деградирует в обычный утренний — `now` сдвинулся на день, `lastDrawDate` для
  него уже «позавчера», и условие `d === 1` больше не совпадает с freeze-условием. Оба случая —
  осознанное поведение плана, не дефект: экран «Сегодня» в этот момент и так уже показывал бы
  приглашение открыть карту, второй, более точный текст в самый день спасения не нужен.

### 4. UI

- **«Сегодня»** (`app/(tabs)/index.tsx`): при `freezeSpentDate === сегодня` — строка под
  рядом пилюль, внутри того же блока `FadeUp` (index 2): по центру, `flexDirection: row`,
  gap 6, marginTop 10; `Ionicons name="snow"` 12px цветом `accent`; текст 12px цветом `muted` —
  `pickPhrase('freeze.saved', дата, lang)`. Макета для строки нет — расхождение осознанное,
  композиция по образцу строки луны (`.moonrow`: по центру, muted).
- **Профиль** (`app/(tabs)/profile.tsx`): третья коробка
  `<StatBox value={freezes} label={tr('profile.freeze')} icon="snow" />`. Снежинка — иконкой
  `Ionicons`, не эмодзи из макета (правило задачи 16), цвет accent как у огонька — палитра
  «Небесное золото», холодный синий токен не вводим.
- **Настройки** (`app/settings.tsx`), под `__DEV__`: строка «Пропустить вчера» —
  `lastDrawDate = позавчера` + удалить сегодняшнюю запись из history. Без неё заморозку
  не проверить ни в вебе, ни на лайв-проверке (пришлось бы ждать реальные сутки).
  Повторный прогон после траты единственной заморозки проверяет и ветку сброса.

### 5. Тексты

- `content/phrases.json`: `push.freeze_saved` (2–3 варианта ru/en, допустим `{days}`)
  и `freeze.saved` для строки на «Сегодня» (2–3 варианта, БЕЗ эмодзи — снежинку рисует
  иконка рядом). Тон — content-guide; пометить редактору на вычитку.
- `src/lib/i18n.ts`: `push.titleFreeze` (ru «Серия спасена ❄» / en «Streak saved ❄»),
  `profile.freeze` (ru «ЗАМОРОЗКА» / en «FREEZE»).

## Что НЕ делаем

- Покупка/начисление заморозок сверх бесплатной (Premium — master-plan, монетизация).
- Изменение «протухшей» серии на экранах: пилюля и стата показывают сохранённое значение
  до следующего открытия карты — существующее поведение, задача его не трогает.
- Вехи серии (3/7/14/… — ачивки и оценка в сторе) — отдельные пункты master-plan.
- Изменение вечернего пуша 20:00 (решение 4) и любых других видов пушей.
- История трат заморозок, экраны/попапы объяснения механики.
