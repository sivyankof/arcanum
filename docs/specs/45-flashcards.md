Статус: спека согласована 19.08 (брейншторм с Артёмом, решения ниже). Реализация в ДВЕ части
одной ветки `feat/45-flashcards`:

  тестами и DEV-диалогом на устройстве, мержится в main без лайв-проверки экранов (прецедент 28а:

- **45б — экраны** (после дорисовки макета, см. «Расхождения с макетом»): карточка «Повторение»
  в шапке курса, экран тренажёра `app/review.tsx`, результат, пустые состояния. Свой план,
  веб-проверка 6а/6б и лайв-проверка Артёма — как у любой UI-задачи.

## Решения (брейншторм 19.08, ответы Артёма)

| Вопрос | Решение |
|---|---|
| Формат тренировки | **Флип + самооценка** (классика Anki): лицо-вопрос → тап → оборот-ответ → кнопки оценки. Викторина с вариантами и «оба режима» отклонены (викторина по изученному — расширение позже, master-plan п. 12). |
| Вход | **Таб «Курс», карточка «Повторение» над путём** (как Practice в Duolingo). Справочник и «Сегодня» отклонены: справочник — справочник, «Сегодня» — ритуал. Совпадает с вопросом 1 Cowork («нарисован вход с Курса»). |
| Колода | **Только карты из пройденных уроков** (`learnedCardIds`). Все 78 и «плюс карты дня» отклонены: встреча ≠ изучение, бейдж «Изучено ✓» стал бы двусмысленным. |
| XP | **+1 за каждую вспомненную карту** (`XP_REVIEW = 1`). Потолок естественный: оценённая карта уходит на дни. Задача 22 сама называла флеш-карты будущим источником XP. Вопрос 4 Cowork. |
| Кнопки оценки | **Три**: «Не помню / Помню / Легко» (оценки 0 / 2 / 3). Макет рисует четыре — правится (см. расхождения). Род безличный (content-guide): «Не вспомнила» из макета не берём. |
| Интервал на кнопках | **Не показываем** («Легко · 6 дн» как в Anki) — тон приложения ритуал, а не отчётность (то же решение, что про графики рефлексии). Вопрос 2 Cowork. |
| Сессия | **Порциями по 10** (вопрос 3 Cowork). |

## Цель

- После пройденных уроков у пользователя появляется ежедневная причина вернуться в курс: карточка
  «Повторение · N карт ждут» → короткая сессия ≤10 карт с переворотом и самооценкой → интервалы
  растут по SM-2, забытое возвращается.
- Всё офлайн, все тексты — `keywords` и `general` из `cards.json`; ни одной строки контента
  в коде не выдумываем.
- Логика целиком чистая и под тестами; экраны — тонкий слой над ней.

## Что делаем

### А. Чистые модули (всё под юнит-тестами)

**`src/lib/srs.ts`** — ПЕРЕПИСАТЬ (старая версия: `dueAt` timestamp, `cardId` внутри состояния,
без тестов, нигде не вызывается):
- `type SrsGrade = 0 | 1 | 2 | 3` — 0 «не помню», 1 «с трудом» (в UI v1 кнопки нет, оставлен
  для будущего режима-викторины), 2 «помню», 3 «легко».
- `interface SrsState { reps: number; intervalDays: number; ease: number; due: string }` —
  `due` = ЛОКАЛЬНАЯ дата `YYYY-MM-DD` (как `lastDrawDate`), НЕ timestamp: оценил в 23:00 →
  «завтра» = следующий календарный день, а не 23:00 завтра, иначе утром очередь пуста, а вечером
  полна. `cardId` в состоянии не хранится — он ключ словаря.
- Константы: `EASE_START = 2.5`, `EASE_MIN = 1.3`, `EASE_MAX = 5`, `MAX_INTERVAL_DAYS = 365`.
- `reviewState(prev: SrsState | undefined, grade: SrsGrade, todayISO: string): SrsState` — SM-2:
  `q = [1, 3, 4, 5][grade]`; при `q < 3`: `reps = 0`, `intervalDays = 0`, `due = today` (карта
  остаётся к повторению сегодня и возвращается в конец сессии); при `q ≥ 3`: `reps + 1`,
  интервал `1 → 6 → round(prev × ease)`, потолок 365; `ease' = clamp(ease + (0.1 − (5−q)·(0.08
  + (5−q)·0.02)), 1.3, 5)` — обновляется при ЛЮБОЙ оценке (оригинальный SM-2): q=5 → +0.10,
  q=4 → 0, q=3 → −0.14, q=1 → −0.54. `prev === undefined` (новая карта) стартует от
  `{reps: 0, intervalDays: 0, ease: 2.5}`. Легко у новой карты даёт тот же 1 день, что и
  «помню», — отличие только в ease (SM-2 без easy-bonus, YAGNI).
- `isDue(s, todayISO) = s.due <= todayISO` (ISO сравнивается строкой).
- Тест-кейсы: новая → 2 → due завтра, reps 1; → 2 → +6 дней; → 2 → round(6 × 2.5) = 15; ease по
  всем четырём оценкам; потолки 365 и 5 / пол 1.3; 0 после длинного интервала → reps 0, due =
  сегодня, ease упал; `isDue` на вчера/сегодня/завтра; переход через месяц и год у `due`.

**`src/lib/review.ts`** (новый) — сборка сессии и сводка, без импортов react/expo:
- `SESSION_MAX = 10`, `NEW_PER_DAY = 10`.
- `type Direction = 'toMeaning' | 'toCard'`; `interface SessionItem { cardId; direction; isNew }`;
  `interface ReviewDay { date: string; newCount: number }` — сколько НОВЫХ карт введено за день;
  `REVIEW_DAY_DEFAULT = { date: '', newCount: 0 }`, счётчик действителен только если
  `date === today` (иначе читается как 0).
- `deckOrder(course, progress): string[]` — `[...learnedCardIds(course, progress)]`: порядок
  курса (Set хранит порядок вставки — карты первых уроков первыми).
- `reviewSummary(deck, srs, todayISO, day): { deckSize; due; newAvailable; dueTomorrow }` —
  `due` = карты колоды с состоянием и `isDue`; `newAvailable` = min(карты колоды БЕЗ состояния,
  `NEW_PER_DAY − newCount за сегодня`), не меньше 0; `dueTomorrow` = карты с состоянием и
  `due <= завтра` (показывается только в состоянии «всё повторено», где просроченных нет, поэтому
  равен «ровно завтра»). Состояния карт, выпавших из колоды (DEV-сброс курса), не считаются.
- `buildSession(deck, srs, todayISO, day, rng): SessionItem[]` — просроченные по `due` ↑, при
  равенстве по порядку колоды, первые ≤ `SESSION_MAX`; остаток слотов — новые в порядке колоды,
  не больше `newAvailable`; итоговый список тасуется Фишером–Йетсом (`rng` — параметр, для
  тестов); направление: новая карта всегда `toMeaning` (сначала показать образ), повторяемая —
  `rng() < 0.5 ? 'toMeaning' : 'toCard'`.
- `applyGrade(queue: SessionItem[], grade): { queue; passed }` — снимает голову; `grade === 0`
  → тот же элемент в конец очереди (карта повторяется, пока не будет вспомнена); `passed =
  grade >= 1`.
- `sessionStats(log: { cardId; grade }[]): { cards; firstTry; xp }` — `cards` = уникальных карт,
  `firstTry` = карт, чья ПЕРВАЯ оценка ≥ 1, `xp` = число событий «оценка ≥ 1 карты, которая до
  этой оценки была к повторению» (см. правило XP ниже) — используется экраном результата и
  тестом-инвариантом «xp экрана = xp стора».
- `promptSentence(text: string): string` — первое предложение `general` для оборота/подсказки:
  срез по первому `.`/`!`/`?`/`…` с пробелом или концом строки после; если срез короче 20 знаков
  («Дурак.») — берём до второго; потолок 160 знаков с «…». Под тестами (`«Т. е.»` в корпусе
  нет — проверяется контракт-тестом по `cards.json`: у каждой карты первое предложение
  `general.ru/en` не короче 20 и не длиннее 160 знаков после среза).
- Общий `shuffle(arr, rng)` — если в `spread.ts` Фишер–Йетс инлайн, вынести и переиспользовать
  (правило DRY), `dealSpread` переводится на него.
- Тест-кейсы `review`: пустая колода → пустая сессия и сводка нулей; 12 просроченных → 10 самых
  старых; 3 просроченных + 20 новых → 3 + 7 новых, `newAvailable` учитывает `newCount` сегодня и
  игнорирует вчерашний; `newCount = 10` → новых 0; сидированный rng → детерминированный порядок
  и направления; новые всегда `toMeaning`; `applyGrade(0)` возвращает карту в хвост, `2` — нет;
  `sessionStats` на логе «0, 2» одной карты = cards 1, firstTry 0, xp 1; `dueTomorrow` при
  пустом due; `promptSentence` на «Дурак. Карта начала пути.», на «…» и на тексте без точки.

**`src/lib/xp.ts`** — `XP_REVIEW = 1`.

### Б. Стор, бэкап, DEV

**`src/store/useApp.ts`** — persist **version 10** (`SCHEMA_VERSION` в `backup.ts` — 9 → 10):
- поля `srs: Record<string, SrsState>` (ключ — `cardId`) и `reviewDay: ReviewDay` — оба ключи
  ВЕРХНЕГО уровня, дефолты доливаются поверхностным слиянием сами, `migrate` не меняется.
  ⚠️ `reviewDay` — вложенный объект: следующая задача, добавляющая поле ВНУТРЬ него, обязана
  поднять версию и дописать слияние руками (ловушка 06а).
- `reviewCard(cardId, grade): number` — `prev = srs[cardId]`; `wasDue = prev === undefined ||
  isDue(prev, today)`; `srs[cardId] = reviewState(prev, grade, today)`; если `prev === undefined`
  — `reviewDay = { date: today, newCount: (date === today ? newCount : 0) + 1 }`; XP: `+XP_REVIEW`
  если `grade >= 1 && wasDue`, иначе 0; возвращает начисленное. Правило XP сформулировано без
  понятия «сессия» нарочно: карта, провалённая (due = сегодня) и затем вспомненная, даёт +1;
  вспомненная повторно в тот же день (due уже завтра+) — 0; накрутка невозможна.
- `resetSrs()` (DEV) — `srs = {}`, `reviewDay = REVIEW_DAY_DEFAULT`.
- `devAgeSrs()` (DEV) — каждому `due` минус 1 день (`daysAgoISO(1, parseISODate(due))`) и
  `reviewDay = REVIEW_DAY_DEFAULT` — иначе «ждут завтра» и дневной лимит новых на устройстве
  проверяются только календарём (та же роль, что у `devSkipYesterday`).
- `resetCourse` (DEV) `srs` НЕ трогает — колода вычисляется, лишние состояния безвредны;
  для чистого листа рядом лежит `resetSrs`.

**`src/lib/backup.ts`** — `srs` и `reviewDay` в `BackupState`/`PERSIST_DEFAULTS` (тип-контроль
стора этого потребует сам); `validState`: `srs` — объект, ≤ 78 ключей, каждый ключ есть в
`cardById`, каждое значение `{reps: count, intervalDays: 0..365, ease: число 1.3..5, due: ISO-день}`;
`reviewDay`: `date` — `''` или ISO-день, `newCount` — count ≤ 78. Старый бэкап (schemaVersion 9)
без этих ключей валиден — доливается дефолтами (уже так устроено). Тесты: файл v9 принимается,
`srs` с чужим `cardId`/`ease 1.0`/`interval 400` — `corrupt`.

**`app/settings.tsx`** (под `__DEV__`, три `SettingsRow` рядом с DEV-строками курса):
- «Очередь повторения» → `ConfirmDialog` (`confirmTone 'accent'`, одна кнопка) с текстом

  сегодня C» — тот же приём, что «План пушей».

- «Сбросить повторение» → `resetSrs`.

**`src/lib/i18n.ts`** — в 45а только ключи DEV-строк (`settings.devReviewQueue`,

### В. Экраны (45б — по спеке ниже и по макету `v-trainer` после дорисовки)

**Карточка «Повторение» в шапке таба «Курс»** — между заголовком «Курс»/`Rule` и первым модулем,
внутри `FadeUp index={1}` вместе с первым модулем (без нового шага каскада). Панель по
design-system §5 (radius, паддинг как у `ModuleHeader`), Overline «ПОВТОРЕНИЕ», строка состояния,
справа иконка Ionicons `sync-outline` (или по макету). Состояния:
- колода пуста (ни одного пройденного урока с картами) — карточка **не показывается вовсе**;
- `due > 0` — «N карт ждут» (Display-строка), тап → `/review`;
- `due = 0`, `newAvailable > 0` — «Новых карт: N», тап → `/review`;
- `due = 0`, `newAvailable = 0` — «Всё повторено ✓ · завтра: M» цветом `success`, НЕ тап.

**Экран тренажёра `app/review.tsx`** — корневой стек ПОД ГАРДОМ онбординга (урок 09: маршрут
обязан быть вписан в `_layout.tsx`), прозрачная нативная шапка с подписью «Курс» на кнопке назад
(как у урока), «назад» без подтверждения (каждая оценка уже в сторе, `useLeaveGuard` не нужен).
Композиция по макету: Overline «ПОВТОРЕНИЕ · ИНТЕРВАЛЬНЫЙ МЕТОД» → «Тренажёр» → `Rule` → счётчик
«К ПОВТОРЕНИЮ · N» (длина очереди; при «не помню» не уменьшается — карта вернётся) → карта в
`ringwrap` 190×330 → плашка названия → панель «ЗНАЧЕНИЕ» → ряд из ТРЁХ кнопок оценки.
Сессия — `buildSession(...)` один раз при монтировании (`rng = Math.random`), очередь —
состояние экрана; переход к следующей карте после оценки, повторный тап по кнопке до перерисовки
игнорируется (busy-guard, как у экспорта/импорта).
- Направление `toMeaning` («карта → значение»): карта лежит **лицом вверх** с начала (образ и
  название на плашке — вопрос), панель «ЗНАЧЕНИЕ» скрыта, под картой подпись «ВСПОМНИТЕ ЗНАЧЕНИЕ ·
  НАЖМИТЕ»; тап по карте (или по подписи) → панель появляется fade 350 мс (как пояснение
  викторины) с 4 `keywords` золотыми чипами + `promptSentence(general)` + строка-ссылка «Страница
  карты →» + три кнопки. Переворота в этом направлении нет — акцент экрана остаётся один.
- Направление `toCard` («значение → карта»): **рубашка**, в зоне эмблемы — 4 `keywords` столбиком
  + `promptSentence(general)` (без названия!) + подпись «ВСПОМНИТЕ КАРТУ · НАЖМИТЕ»; тап →
  3D-переворот (`SpreadCard`-механика, 500 мс) → образ + название на плашке + та же панель
  «ЗНАЧЕНИЕ» + кнопки. Значения берутся через `blockText(general, lang)`: при `todo` — только
  чипы (`keywords` у всех 78 карт вычитаны, «Текст готовится» на флеш-карте не бывает).
- Кнопки: «Не помню» (`danger`), «Помню» (`text`), «Легко» (`success`) — три равные, бордер
  `line`, radius 12, текст 10/700 (design-system §5, правится с четырёх на три). Хаптика у всех трёх — Light
  (самооценка «не помню» — не ошибка, Error-вибрация наказывала бы честность). Тап →
  `reviewCard` → `applyGrade` → следующая карта; лог сессии для результата.
- Пустое состояние (открыли без карт к повторению — глубокая ссылка или после «Ещё»): рубашка-
  пунктир ✶ + «Повторять пока нечего — пройдите урок, и карты появятся здесь.» + CTA «К курсу»
  (текст макета) — если колода пуста; «Всё повторено ✓ · завтра: M» + CTA «К курсу» — если колода
  есть, а очередь пуста.
- **Результат** — панель в стиле `LessonResult` (общая часть выносится, если разметка совпадёт
  на 2+ места: заголовок, счётчик XP, CTA): «Повторено N · с первого раза K · +X XP» (счётчик
  катится, как у урока), CTA «Готово» (→ назад в курс), под ней «Ещё N» — если `reviewSummary`
  после сессии показывает `due > 0 || newAvailable > 0` (новая сессия на том же экране). Конфетти
  нет (motion-spec: 1–2 акцентных анимации на экран, здесь это переворот).

**Профиль/статы** — не меняются (см. «Не делаем»).
