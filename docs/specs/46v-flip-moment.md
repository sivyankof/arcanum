# Спека 46в — «момент переворота»: карты пройденного урока раскрываются в справочнике

Статус: спека написана 21.08 (брейншторм с Артёмом: скролл к волне — да; дизайн одобрен).
Постановка — хвост (е) записи 46 бэклога; параметры анимации дорисованы в макет 20.08
и подтверждены Артёмом как источник для motion-spec (решение 26). Запись — motion-spec §17.
Ветка: `feat/46v-flip-moment`.

## Цель

Пройденный урок сейчас меняет справочник молча: карты урока просто оказываются яркими при
следующем заходе (таб держится смонтированным, и переключение `dimmed → learned` отыгрывает
в невидимом экране). После задачи у этого появления есть момент: при первом заходе на «Карты»
после урока сетка встаёт на новые карты, и они раскрываются из приглушённых волной —
маленькая награда, видимая глазами.

## Что делаем

### 1. Очередь новых карт — `src/lib/revealQueue.ts` (новый модуль)

Транзиентный модуль-синглтон (прецедент — `cardTransition.ts`): `queueReveal(ids)` дописывает
ids в очередь (без дублей), `takeReveal()` отдаёт содержимое и очищает. Ничего не персистится:
перезапуск приложения очередь теряет — сознательно, «момент» сиюминутен.

Там же чистая функция порядка волны:

```
revealOrder(rows: TarotCard[][], ids: Set<string>, cap = REVEAL_CAP): Map<string, number>
```

— обходит ячейки в порядке сетки и раздаёт присутствующим в `ids` ступеньки стаггера 0..cap-1;
карты сверх `cap` (8) в карту не попадают — появляются сразу в конечном виде (motion-spec §4).
Карты, скрытые фильтром/поиском, в `rows` отсутствуют и ступенек не получают.

⚠️ Механизм отличается от буквы бэклога («диф `learned` между фокусами») осознанно: табы
ленивые, «Карты» монтируются при первом заходе — на холодном старте «Сегодня → Курс → урок →
Карты» снимок инициализировался бы уже выросшим `learned`, и волны не было бы ровно на главном
сценарии. Поэтому «какие карты новые» знает `completeLesson`, а «когда играть» — фокус вкладки,
как и предписывал бэклог.

### 2. Стор — `completeLesson` кладёт впервые изученные в очередь

В `useApp.ts` экшен `completeLesson` до записи прогресса берёт `learnedCardIds` от старого
`lessonsProgress`, после — от нового; разница уходит в `queueReveal`. Урок-повторение (все
карты уже изучены) и уроки М6 без карт дают пустую разницу — очередь не трогается.
Persist **не меняется** (version остаётся 10): очередь живёт вне стора.

### 3. Ячейка — `CardCell` учится раскрываться

Новый проп `reveal?: number` (ступенька стаггера; не задан — поведения нет). Картинка
оборачивается в `Animated.View` ПОСТОЯННО (условная обёртка перемонтировала бы `Image` —
скелетон мигнул бы), стиль нейтрален без `reveal`. С `reveal`:

- opacity: 0.55 → 1, transform scale: 0.965 → 1.02 → 1;
- 520 мс на всё, кривая `Easing.bezier(.2,.9,.3,1.05)` К КАЖДОМУ отрезку (как CSS применяет
  timing-function между кадрами @keyframes): `withSequence(withTiming(60% значений, 312 мс),
  withTiming(конечных, 208 мс))`;
- задержка `withDelay(reveal * 70)`;
- `ReduceMotion.System`.

Проп `dimmed` при этом не ставится (карта уже изучена) — стартовые 0.55 держит сама анимация.
Бейдж «ИЗУЧЕНО ✓» и полоски мастерства не анимируются — появляются сразу (эталон анимирует
только `.im`). Риска «осиротевших 3D-пропов» (уроки 36/42) нет: трансформация 2D (scale),
конечные значения нейтральны, стиль с обёртки не снимается.

### 4. Экран — `cards.tsx`: фокус → скролл → волна

`useFocusEffect`: если `takeReveal()` непуст — построить `revealOrder` по текущим `rows`,
положить в state, прокрутить список к ряду первой новой карты **без анимации**
(`scrollToIndex({animated: false, viewPosition: 0.25})`; ряды разновысокие — названия
переносятся на 1–2 строки, поэтому обязателен `onScrollToIndexFailed` с оценкой offset
и повтором). Через ~1.2 с (520 + 7×70 ≈ 1010 мс + запас) state очищается — иначе ряд,
смонтированный FlatList позже при прокрутке, отыграл бы волну заново.

Скролл — разовое осознанное исключение из правила «позиция скролла между табами сохраняется»
(motion-spec §4): решение Артёма 21.08, волна за кадром — не награда.

Известное наложение: в первых 4 рядах поверх волны играет «возврат» FadeUp (0.6 → 1 за 180 мс),
прозрачности перемножаются первые 180 мс. Ожидается незаметным; проверить на веб-прогоне,
если видно — пропускать FadeUp-повтор при активной волне.

### 5. DEV-строка — `app/settings.tsx`

«Момент переворота» под `__DEV__`: кладёт в очередь ВСЕ изученные карты — заодно проверяется
потолок каскада (волна у первых 8, остальные сразу яркие). Без неё каждый прогон лайв-проверки
требовал бы проходить урок заново; аналог кнопки-демо в макете.

## Что НЕ делаем

- Никакого 3D/FlipCard: макет рисует opacity+scale, Артём подтвердил параметры макета (реш. 26).
- Не персистим очередь и не реагируем на изменение стора (волна в невидимом экране).
- Не повторяем волну: очередь потребляется при первом фокусе; фильтр/поиск, спрятавший новые
  карты, съедает волну молча (редкий случай, усложнять не стоит).
- Не анимируем бейдж, полоски мастерства и ряды сверх первых 8 новых карт.
- Не трогаем `setLessonDone` (DEV-переключатель прогресса): у него есть обратный ход
  (`done: false`), и волна от DEV-галочек — шум; для проверки есть своя DEV-строка.

|---|---|---|
| Длительность | 520 мс | макет `.gc.revealing .im`, реш. 26 |

## План (шаги = проверяемые правки)

1. `src/lib/revealQueue.ts` + юнит-тесты (`revealOrder`: раздача ступенек в порядке сетки,
   потолок 8, отсутствующие в rows ids без ступенек; очередь: дозапись без дублей, take очищает).
2. `useApp.ts`: diff в `completeLesson` → `queueReveal`. Тест: завершение урока с новыми
   картами кладёт ровно их; повторное завершение — ничего.
3. `CardCell.tsx`: проп `reveal`, постоянная обёртка, анимация. (Компоненты юнитами не кроем —
   testing-strategy п. 2, проверяет веб-прогон.)
4. `cards.tsx`: фокус-эффект, скролл, очистка. `npx tsc --noEmit` после каждого шага.
5. `app/settings.tsx`: DEV-строка.
6. Веб-проверка 6а/6б (скриншоты в `docs/screenshots/46v/`, обе темы 390×844; сценарий сначала
   красный на коде без волны), лайв-проверка Артёма (стаггер, скролл, отсутствие повтора).

## Критерии приёмки («готово, когда…»)

- [ ] Пройден урок с новыми картами → заход на «Карты»: сетка стоит на ряду первой новой
      карты, карты урока раскрываются волной 520 мс / stagger 70 в порядке сетки.
- [ ] Повторный заход — волны нет; карты в конечном виде.
- [ ] Холодный сценарий (Карты ещё не открывались за сессию) — волна играет.
- [ ] Урок «Повторение» / урок без карт — волны нет.
- [ ] Больше 8 новых карт (DEV) — анимируются первые 8, остальные сразу яркие.
- [ ] Консоль веба чистая; `npx tsc --noEmit` и `npm test` зелёные.
- [ ] Persist version не менялась (10), бэкап-контракт цел.
