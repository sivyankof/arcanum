## Зачем — это уже стоило нам корпуса

Сейчас статус блока один на все языки: `{ru: "…", en: "…", status: "reviewed"}`. Из этого
15.08 вышел задокументированный инцидент (CLAUDE.md, задача 31): **английский канон не читал
никто и никогда**. Статус `reviewed`, проставленный редактором 13.08, означал «русский вычитан»,
и это молча распространилось на английский — 44 правки из 110 в заходе А пришлись именно на него,
включая неканоничные имена карт (тексты звали Силу `Strength`, а Суд `Judgement`, тогда как
заголовок страницы берёт `name.en` — `Fortitude` и `The Last Judgment`; пользователь видел два
разных имени одной карты на одном экране).

То есть дефект схемы уже один раз реализовался на двух языках. С четырьмя он реализуется трижды:
испанский и португальский унаследуют `reviewed` от русского в тот момент, когда их никто не читал.
Это ровно тот класс, который проект ловит правилом «если проверка не краснеет на сломанном
состоянии — она декорация»: статус, не различающий языки, не может покраснеть на невычитанном
языке.

Второй довод — момент. **Сегодня весь контент находится ровно в одном статусе `reviewed`**
(958 блоков карт, 32 теории, 32 викторины, 5 staging-файлов; ни одного `todo`, `draft` или
`final`). Миграция смешанных состояний не нужна: надо переложить одно значение в новую форму.
После заливки первого перевода это перестанет быть правдой навсегда.

## Развилка 1 — форма схемы

**Вариант A (рекомендую): `status` становится словарём по языку рядом с текстами.**

```jsonc
"love": {
  "ru": "…", "en": "…",
  "status": { "ru": "reviewed", "en": "reviewed" }   // es/pt отсутствуют = todo
}
```

В типах — `Partial<Record<Lang, BlockStatus>>`, отсутствующий язык читается как `todo`.
Плюсы: один источник правды рядом с текстом; дифф правки видно в том же месте, где текст;
миграция механическая (одно значение → две записи); файл растёт умеренно (пустые языки
не хранятся). Минус: `cards.json` становится чуть шумнее в дифах.

**Вариант B: отдельный файл-манифест статусов** (`content/status.json`: адрес блока → статусы
по языкам). Плюс: контентные файлы не шумят, workflow-метаданные отделены от контента.
Минус решающий: это ровно то двойное хранение, на котором проект уже обжёгся с викторинами —
адреса блоков придётся держать синхронными с `cards.json` руками, а рассинхрон будет молчаливым.

**Вариант C: оставить скаляр `status` для канона (ru+en), добавить `statusEs`/`statusPt`.**
Дешевле всех в реализации и хуже всех по сути: консервирует ровно ту дыру, из-за которой
английский никто не читал. Раз мы платим за миграцию, платить надо один раз.

## Развилка 2 — что показывать пользователю

Здесь главная тонкость, и она не про хранение, а про чтение. Текст берётся через
`inLang(блок, lang)`, который **молча падает на английский**, если языка нет. Значит после
миграции вопрос «показывать текст или заглушку» перестаёт иметь однозначный ответ: испанец видит
английский текст, и проверять надо статус НЕ испанского, а того языка, который реально показан.

Предлагаю: `inLang` дополняется функцией, возвращающей вместе с текстом язык, из которого он
взят (`{text, lang}`), а проверка `todo` смотрит статус ЭТОГО языка. Тогда правило остаётся
прежним — «показываем то, что готово», — и работает на фолбэке.

⚠️ Иначе получится один из двух дефектов: либо испанец увидит «Текст готовится» поверх готового
английского текста (проверяли статус es), либо увидит черновик (проверяли статус en, а показали es).

## Развилка 3 — курс

У урока уже ДВЕ независимые оси статуса (теория и викторина). Язык добавляет третью: 2×4 = 8
значений на урок при полном раскрытии. Плюс staging-файлы, где статус один на весь файл сразу.

Вопрос: доводить ли пер-языковый статус до staging-файлов викторин, или там достаточно единого
(они по построению пишутся волной на один язык)? Моё предложение — доводить: рассинхрон схем
между staging и собранным файлом воспроизведёт ловушку двойного хранения на новом уровне.

## Решения Артёма (19.08)

Все четыре развилки закрыты, по всем — рекомендованный вариант; периметр взят максимальный.

1. **Форма схемы — вариант A.** `status` блока становится словарём по языку и живёт рядом
   с текстами: `{"ru": "…", "en": "…", "status": {"ru": "reviewed", "en": "reviewed"}}`.
   Отсутствующий язык читается как `todo`.
2. **Фолбэк — статус ФАКТИЧЕСКИ показанного языка.** Испанец, которому `inLang` отдал
   английский текст, видит его при `status.en != todo`; заглушка «Текст готовится» появляется
   только когда не готов тот язык, который реально попал на экран.
3. **Периметр — максимальный:** пер-языковый статус доводится и до staging-файлов викторин
   (`content/quiz-m*.json`), и до `keywords`/`search` карты, у которых статуса не было вовсе.
4. **Стартовые значения миграции:** `ru: reviewed`, `en: reviewed`; `es`/`pt` отсутствуют = `todo`.

### Решения, принятые в рамках согласованного (не требуют отдельного ответа)

**4а. Слова витрины и поиска получают ОДИН статус на карту — `wordsStatus`, а не два.**
`name`, `keywords` и `search` заливаются переводом атомарно, одним куском (бэклог 28, п. 5:
появись `name.es` без `keywords.es`, источник поиска станет смешанным языком — `presentLang`
выберет испанский по названию, а слова придут английскими и порежутся испанскими окончаниями).
Раз три поля живут и умирают вместе, статус у них общий; два поля дали бы состояние
«название переведено, слова нет», которое схема обязана не допускать, а не описывать.

⚠️ **Оговорка по `wordsStatus.en`.** Ставлю `reviewed` по общему правилу решения 4, но честнее
сказать прямо: слова вычитывались редактором 12.08 (задача 04г), и это была вычитка РУССКИХ
слов; заходы 31/35/37 читали английский корпус текстов, а не `keywords`/`search`. Если хочешь
строгости — скажи, и `wordsStatus.en` станет `draft` одной строкой миграции; на поведение
приложения это не влияет (слова показываются без проверки статуса, статус здесь нужен только
отчёту готовности и workflow).

**2а. Каскада фолбэка у статуса НЕТ.** Смотрим статус ровно того языка, чей текст показан, и
на этом останавливаемся. Состояние «испанский текст есть, но его статус `todo`» (то есть
показали бы заглушку поверх готового английского) в бандл не попадёт — его ловит контракт-тест
связкой «у языка есть текст ⟺ его статус не `todo`». Правило простое и проверяемое; каскад
пришлось бы объяснять на каждом читателе.

**2б. Пустых ключей у неканоничных языков быть не должно.** `presentLang` считает язык
присутствующим по `!== undefined`, поэтому `"es": ""` — не «пусто, возьми английский», а
«испанский есть и он пустой»: пользователь получил бы пустое место вместо готового английского
текста. Отсутствие ключа и пустая строка здесь значат РАЗНОЕ, и конвейеру запрещено создавать
`es`/`pt` заглушками. Отдельный контракт-тест. (У канона `ru`/`en` пустая строка при `todo`
остаётся законной — так устроены недописанные блоки.)

### Что нашла проверка (а не ревью)

⚠️ **`build_cards.py` и миграция клали `wordsStatus` в РАЗНЫЕ места карты.** Скрипт сборки
ставит ключ после `search`, миграция дописывала в конец. Содержимое идентичное, поэтому ни
тесты, ни tsc, ни отчёт готовности этого не видели — а первый же будущий прогон `build_cards.py`
выдал бы дифф на 312 строк чистой перестановки, в котором настоящая правка утонула бы.
Найдено только потому, что скрипт удалось запустить по-настоящему (см. ниже). Исправлено;
проверено сравнением ХЕШЕЙ: вывод миграции и вывод `build_cards.py` теперь побайтово совпадают.

⚠️ **`build_cards.py` удалось проверить прогоном, хотя исходника tarot-api в системе нет.**
Соблазн был написать «проверено чтением» — для скрипта, который однажды уже стёр 624 блока,
это не проверка. Исходник восстановлен ИЗ САМОГО `cards.json`: поля `source.waite_*`, `name.en`,
`suit`, `number` — ровно то, что скрипт из источника и читает. 78 карт, прогон настоящий.

⚠️ **Дымовая проверка была зелёной на сломанном коде — то есть декорацией.** Сломал `statusIn`
ровно той ошибкой, от которой защищает решение 2 (спрашивать статус ВЫБРАННОГО языка вместо
показанного) — испанская страница схлопнулась с 1283 знаков до 246, а проверка отрапортовала
«ПРОЙДЕНО». Две причины, обе поучительные:
- **строка заглушки была выдумана**: я искал «Text coming soon», а `card.soon` в `i18n.ts` —
  «Text in progress». Счётчик заглушек не мог быть ненулевым НИКОГДА;
- **признак «английский текст виден» ловил название карты**, которое статусом не закрыто вовсе
  и остаётся на экране, даже когда все блоки значений превратились в заглушки.
Судьёй сделан ОБЪЁМ видимого текста рядом с русским эталоном той же страницы. После правки
проверка краснеет двумя независимыми сигналами. Общее правило, стоящее за обоими промахами:
**строку-признак берут из исходника, а не из памяти, и признак должен зависеть ровно от того,
что проверяешь.**

⚠️ Мелочи браузерного прогона, стоившие трёх ложных заходов: `onboarded` живёт ВНУТРИ `profile`,
и сид без него уводит любой прямой маршрут на `/onboarding` (страница карты при этом «пустая»,
а не сломанная); ярлыки вкладок сфер — «Общее/Любовь/Работа/Финансы/Здоровье», тогда как ключи
`sphereLove` и т.п. («В любви») — это заголовки панелей, и клик по придуманному наугад ярлыку
падает по таймауту 30 с; лента вкладок прокручивается, дальним вкладкам нужен
`scrollIntoViewIfNeeded`.

### Открытый вопрос редактору (не блокирует)

`wordsStatus.en` выставлен `reviewed` по общему правилу решения 4, но слова вычитывались
редактором 12.08 — и это была вычитка РУССКИХ слов; заходы 31/35/37 читали английские ТЕКСТЫ,

предложенная альтернатива («станет `draft` одной строкой миграции») тоже была мертва: миграция
заводит `wordsStatus` только `if "wordsStatus" not in card`, и после отработавшего прогона смена
константы ни на что не влияет. Общий урок: **рецепт, записанный в спеку, надо выполнить хотя бы
один раз** — иначе он документирует намерение, а не возможность.

## Волна фиксов финального ревью ветки (19.08, до лайв-проверки)

Ветку читало финальное ревью пятью независимыми срезами (данные и миграция, типы и чтение,
скрипты конвейера, честность тестов, доки против кода), каждая находка проверялась отдельным
агентом-скептиком с задачей ОПРОВЕРГНУТЬ. Из 15 находок подтвердилось 11, опровергнуто 4.
Тестов после волны — **1181 в 32 сьютах** (было 1085).

⚠️ **Главная: `set_status.py` выдавал статус языку, у которого нет ни знака текста.** `bump()`
считает отсутствующий ключ языка равным `todo`, поэтому `set_status.py draft --lang es` на
непереведённом корпусе проставлял испанский статус ВСЕМ 1100 единицам, после чего
`content_stats.py` — единственный артефакт, ради которого задача и делалась, — рапортовал
«es: готово 100%» при нуле испанских знаков. То есть задача, снимавшая дефект «статус, не
различающий языки», воспроизвела его на новом уровне: теперь статус не различал «переведено»
и «пусто». Четвёртое подтверждение правила проекта: **правка, снимающая дефект, склонна вносить
дефект того же класса.** Лечение: `bump()` получил `has_text(lang)` и молча не двигает статус
языку без текста, а пропущенное называет числом; у слов карты «есть текст» означает все три
поля сразу (`name` + `keywords` + `search`), у викторины — каждый вопрос целиком.

⚠️ **Проверка, которая целилась ровно в этот дефект, промахнулась и была декорацией.** План
(шаг 4 задачи 2) прямо называл «главной проверкой» строку `set_status.py final --from reviewed
--lang es --dry-run` → ожидание 0, и она проходила. Но дыра открывается только при `--from todo`,
а там `src = reviewed` — проверка не могла покраснеть НИКОГДА. Урок острее обычного: мало
написать проверку «на тот самый случай», надо убедиться, что её вход действительно попадает
в опасную ветку.

⚠️ **`build_cards.py` терял `name.es`/`name.pt`, сохраняя `keywords.es`, `search.es` и
`wordsStatus.es`.** Скрипт переносит из прежней сборки контент и слова, а `name` СОБИРАЕТ ЗАНОВО
из источника (ru — из таблиц скрипта, en — из tarot-api), который про es/pt не знает. Пока
языков два, это безобидно; задача 28а ввела `wordsStatus` с обещанием «name + keywords + search —
одна атомарная единица» — и единственный скрипт, перезаписывающий `cards.json`, это обещание
нарушал: две трети единицы переживали пересборку, а треть исчезала. Цена — испанский заголовок
карты пропадает, а `presentLang` продолжает выбирать источник поиска по названию. Исправлено
переносом неканоничных ключей `name`; проверено прогоном с залитым `name.es` (пережил).

⚠️ **`set_status.py` не записывал staging-файл викторины, если `course.json` уже на целевом
статусе.** Счётчик `total` собирался только из `course.json`, staging-файлы в него не входили —
и при `total == 0` срабатывал ранний выход, печатая «Нечего менять», хотя сдвиг в памяти уже
был сделан. То есть обещание AGENTS.md «викторинам статус правится в ДВУХ местах» не выполнялось
ровно в том случае, ради которого оно написано: при рассинхроне staging и собранного файла.
Следующий `merge_quiz.py` откатывал бы статус назад. Воспроизведено и закрыто.

⚠️ **Контракт неканоничных языков был ОДНОСТОРОННИМ.** Для канона тест проверял эквивалентность
«есть текст ⟺ статус не todo» и краснел на любом расхождении; для es/pt он начинался с
`if (text === undefined) continue`, то есть проверял только направление «текст ⇒ статус».
Обратное — «в статусе что-то записано ⇒ текст есть» — не проверял никто, и потому главная
находка выше проходила все 1085 тестов зелёными. Теперь эквивалентность и для es/pt.

⚠️ **Атомарность `wordsStatus` была только обещанием в комментарии.** Решение 4а объявляет
состояние «название переведено, слова нет» тем, «которое схема обязана НЕ ДОПУСКАТЬ», но тест
проверял у `wordsStatus` лишь канон. Карта с `name.es` без `search.es` проходила весь прогон.
Добавлена проверка «либо все три поля, либо ни одного» плюс связка со статусом; краснеет.

⚠️ **Статусы `course.json` не покрывал ни один тест.** Периметр спеки включает 32 теории и
32 `quizStatus`, но контракт был написан только для `cards.json`. Эксперимент ревьюера: возврат
`theory.status` и `quizStatus` к старой строковой форме — ровно та регрессия, которую отчёт выше
называет главной, — оставлял `npm test` полностью зелёным. Добавлен контракт статусов курса
(форма, канон, согласованность по неканоничным языкам).

⚠️ **`content_stats.py` округлял до «готово 100%» при 954 из 958** (обычное `:.0%`), а приёмка
локализации по Definition of Done формулируется именно как «100% блоков имеют es/pt». Плюс
статус вне workflow (опечатка вроде `reviwed`) не попадал ни в один столбец, но оставался
в знаменателе — столбцы молча переставали сходиться с заявленным «958 единиц». Теперь 100 %
печатается только при полном совпадении, а «вне workflow» выносится отдельным предупреждением.

⚠️ **Форма статуса нигде не валидировалась.** Единица со статусом старой строковой формы
(ручная правка, разрешение конфликта в параллельной сессии) молча выпадала из workflow

что `merge_quiz.py` придирчиво валидирует каждое поле каждого вопроса. Теперь все три говорят
по-русски и называют адрес.

⚠️ **Рецепт из спеки не выполнялся ни разу и не работал.** «Открытый вопрос редактору» предлагал
команду отката `set_status.py draft --from reviewed …`, а скрипт отвечал «не движение вперёд
по workflow» с кодом 1; вторая предложенная альтернатива (сменить константу миграции) после
отработавшего прогона тоже мертва. Добавлен явный `--allow-back`, команда проверена прогоном.
Урок: **рецепт, записанный в спеку, надо выполнить хотя бы один раз** — иначе он документирует
намерение, а не возможность.
