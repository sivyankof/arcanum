Заведено 19.08. Основание — задача 28 бэклога: «пер-языковый статус в схеме контента … решить

## Зачем — это уже стоило нам корпуса

Сейчас статус блока один на все языки: `{ru: "…", en: "…", status: "reviewed"}`. Из этого
15.08 вышел задокументированный инцидент (CLAUDE.md, задача 31): **английский канон не читал
никто и никогда**. Статус `reviewed`, проставленный редактором 13.08, означал «русский вычитан»,
и это молча распространилось на английский — 44 правки из 110 в заходе А пришлись именно на него,
включая неканоничные имена карт (тексты звали Силу `Strength`, а Суд `Judgement`, тогда как
заголовок страницы берёт `name.en` — `Fortitude` и `The Last Judgment`; пользователь видел два
разных имени одной карты на одном экране).

То есть дефект схемы уже один раз реализовался на двух языках. С четырьмя он реализуется трижды:
испанский и португальский унаследуют `reviewed` от русского в тот момент, когда их никто не читал.
Это ровно тот класс, который проект ловит правилом «если проверка не краснеет на сломанном
состоянии — она декорация»: статус, не различающий языки, не может покраснеть на невычитанном
языке.

Второй довод — момент. **Сегодня весь контент находится ровно в одном статусе `reviewed`**
(958 блоков карт, 32 теории, 32 викторины, 5 staging-файлов; ни одного `todo`, `draft` или
`final`). Миграция смешанных состояний не нужна: надо переложить одно значение в новую форму.
После заливки первого перевода это перестанет быть правдой навсегда.

## Что есть сейчас (инвентаризация 19.08)

**Статус живёт в трёх файлах на трёх разных уровнях гранулярности:**

| Где | Поле | Гранулярность | Сколько |
|---|---|---|---|
| `content/cards.json` | `content.<блок>.status` | блок карты | 958 (78×12 + 22 `birth_path`) |
| `content/course.json` | `lesson.theory.status` | теория урока | 32 |
| `content/course.json` | `lesson.quizStatus` | ВСЯ викторина урока (5 вопросов) | 32 |
| `content/quiz-m*.json` | `status` файла | ВЕСЬ файл (несколько уроков) | 5 |

**Статуса нет вовсе** у `spreads.json`, `composition.json`, `phrases.json` (они двуязычные
с рождения) и у полей `keywords`/`search` карты — последнее уже отмечено в бэклоге как слепое
пятно `content_stats.py`.

**Код читает статус в трёх местах**, и всем трём важно только «todo или нет»:
`src/lib/spread.ts:49` (`cardMeaning`), `app/card/[id].tsx:233` (`blockOf`),
`app/(tabs)/index.tsx:409` (`hasText` у карты дня).

**Два потребителя контента статус игнорируют — по конструкции, а не по недосмотру:**
`app/onboarding.tsx:203` показывает `birth_path` по факту существования блока, а
`src/lib/lesson.ts:53` (`lessonPlayable`) судит урок по непустоте `theory.ru`, и это
зафиксировано решением в плане 27 («проверка по `theory?.ru` — оставить: канон»).

**Скрипты:** `set_status.py` (единственный двигает статус вперёд; `--only cards|theory|quiz`),
`merge_quiz.py` (копирует статус ФАЙЛА каждому уроку), `build_cards.py` (создаёт недостающие
блоки с `status: todo`), `add_birth_path.py` (вставляет с `draft`), `content_stats.py` (считает
готовность, но ТОЛЬКО по `cards.json`), `check_canon.py`/`check_edits.py` (статус не читают вовсе).

**Тесты:** первым сломается `src/lib/__tests__/cardsContent.test.ts` — он утверждает жёсткую
связку «`todo` → оба языка пустые, иначе → оба непустые». При раздельных статусах законное
состояние «ru: reviewed с текстом, es: todo без текста» этот тест провалит. Это не беда,
а именно то место, которое обязано измениться вместе со схемой.

⚠️ **Уже существующая ловушка, которую нельзя воспроизвести на новой схеме:** статус викторины
хранится ФИЗИЧЕСКИ ДВАЖДЫ — в staging-файле и в собранном `course.json`, — и `set_status.py`
синхронизирует оба вручную, иначе следующий прогон `merge_quiz.py` откатывает статус назад.
Любая новая схема обязана лечь на оба хранилища одним движением.

## Развилка 1 — форма схемы

**Вариант A (рекомендую): `status` становится словарём по языку рядом с текстами.**

```jsonc
"love": {
  "ru": "…", "en": "…",
  "status": { "ru": "reviewed", "en": "reviewed" }   // es/pt отсутствуют = todo
}
```

В типах — `Partial<Record<Lang, BlockStatus>>`, отсутствующий язык читается как `todo`.
Плюсы: один источник правды рядом с текстом; дифф правки видно в том же месте, где текст;
миграция механическая (одно значение → две записи); файл растёт умеренно (пустые языки
не хранятся). Минус: `cards.json` становится чуть шумнее в дифах.

**Вариант B: отдельный файл-манифест статусов** (`content/status.json`: адрес блока → статусы
по языкам). Плюс: контентные файлы не шумят, workflow-метаданные отделены от контента.
Минус решающий: это ровно то двойное хранение, на котором проект уже обжёгся с викторинами —
адреса блоков придётся держать синхронными с `cards.json` руками, а рассинхрон будет молчаливым.

**Вариант C: оставить скаляр `status` для канона (ru+en), добавить `statusEs`/`statusPt`.**
Дешевле всех в реализации и хуже всех по сути: консервирует ровно ту дыру, из-за которой
английский никто не читал. Раз мы платим за миграцию, платить надо один раз.

## Развилка 2 — что показывать пользователю

Здесь главная тонкость, и она не про хранение, а про чтение. Текст берётся через
`inLang(блок, lang)`, который **молча падает на английский**, если языка нет. Значит после
миграции вопрос «показывать текст или заглушку» перестаёт иметь однозначный ответ: испанец видит
английский текст, и проверять надо статус НЕ испанского, а того языка, который реально показан.

Предлагаю: `inLang` дополняется функцией, возвращающей вместе с текстом язык, из которого он
взят (`{text, lang}`), а проверка `todo` смотрит статус ЭТОГО языка. Тогда правило остаётся
прежним — «показываем то, что готово», — и работает на фолбэке.

⚠️ Иначе получится один из двух дефектов: либо испанец увидит «Текст готовится» поверх готового
английского текста (проверяли статус es), либо увидит черновик (проверяли статус en, а показали es).

## Развилка 3 — курс

У урока уже ДВЕ независимые оси статуса (теория и викторина). Язык добавляет третью: 2×4 = 8
значений на урок при полном раскрытии. Плюс staging-файлы, где статус один на весь файл сразу.

Вопрос: доводить ли пер-языковый статус до staging-файлов викторин, или там достаточно единого
(они по построению пишутся волной на один язык)? Моё предложение — доводить: рассинхрон схем
между staging и собранным файлом воспроизведёт ловушку двойного хранения на новом уровне.

## Что решить (нужен ваш ответ)

1. **Форма схемы** — вариант A (словарь по языку рядом с текстом), B (отдельный манифест)
   или C (скаляр + поля для новых языков)? Рекомендую A.

## Предварительный план (после согласования, не раньше)

Порядок продиктован тем, что данные и скрипты должны меняться одним коммитом, иначе следующий
прогон конвейера откатит схему назад.

1. Типы: `BlockStatus` остаётся, `CardContentBlock.status` → `Partial<Record<Lang, BlockStatus>>`;
   хелпер чтения статуса с дефолтом `todo`. `Localized<T>` НЕ трогаем — статус живёт рядом с ним,
   а не внутри: иначе сломаются все места, где `Localized` используется без статуса (`name`,
   `keywords`, `title`, `q`, `options`, весь `spreads.json`/`composition.json`/`phrases.json`).
2. Скрипт миграции данных (одноразовый, идемпотентный): `status: "X"` → `{"ru": "X", "en": "X"}`
   во всех трёх местах хранения сразу.
3. Конвейер: `set_status.py` получает `--lang` (по умолчанию — все канонические), `merge_quiz.py`
   переносит словарь целиком, `build_cards.py`/`add_birth_path.py` создают блоки с пустым
   словарём, `content_stats.py` считает готовность ПО ЯЗЫКАМ (и заодно начинает видеть
   `course.json`, чего не умеет сейчас).
4. Чтение: `inLang` + функция «текст и его язык», три места UI переходят на статус показанного
   языка.
5. Тесты: `cardsContent.test.ts` переписывается под новую связку («у языка есть текст ⟺ его
   статус не `todo`»), добавляется тест миграции и тест фолбэка.
6. Доки: `content-guide.md` (workflow статусов по языкам), `logic-spec.md`, `localization-plan.md`
   (L-5 сейчас обещает выставить один статус на блок — переформулировать), CLAUDE.md.
   Заодно поправить фактическую неточность: доки ссылаются на `npm run content:stats`,
   которого в `package.json` нет — скрипт запускается как `python scripts/content_stats.py`.
