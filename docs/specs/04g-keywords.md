# Спека 04г · Ключевые слова карт: витрина и поиск

Статус: на согласовании · Дата: 11.08.2026 · Задача: `docs/backlog.md` → 04г

## Зачем

Поиск в справочнике (задача 04) умеет искать по `keywords`, но искать почти нечего:

| Факт (замер 11.08 по `content/cards.json`) | Значение |
|---|---|
| Карт с непустым `keywords` | 22 из 78 (только старшие арканы, ровно по 4 слова) |
| Карт с пустым `keywords` | **56** (все младшие арканы) |
| Уникальных слов во всей колоде | 85 ru / 86 en |
| Бытовые запросы «любовь», «деньги», «работа», «здоровье», «измена», «развод», «переезд», «одиночество», «беременность», «ссора» | **0 карт каждый** |

Новичок помнит смысл, а не имя карты (product-spec §3) — сейчас он не найдёт ничего. Вторая
проблема тише, но заметнее в интерфейсе: `keywords` рендерятся золотыми чипами под названием
карты (`app/card/[id].tsx:218`), и у 56 младших арканов там **пустое место**.

## Ключевое решение: два поля вместо одного

У ключевых слов две несовместимые работы. Витрине нужны 4 красивых канонических слова (столько
в макете, `.kws span` у Дурака). Поиску нужны житейские формулировки, которыми люди печатают —
«расставание», «долги», «выгорание», — и они не должны висеть чипами под названием: приложение
про рефлексию, а не про предсказание (content-guide, «Тон»). Поэтому поля разводим:

```json
"keywords": { "ru": [4 слова],  "en": [4 слова] },     // витрина: чипы, страница карты и лента расклада
"search":   { "ru": [8–12 слов], "en": [8–12 слов] }   // служебное: только поиск, в UI не появляется никогда
```

Отвергнутые варианты: одно поле на 6–8 видимых слов (чипов вдвое больше макетных, бытовые слова
лезут в интерфейс) и одно поле с показом первых четырёх (порядок массива становится невидимой
логикой — редактор обязан помнить, что слова 5–8 не видны).

## Что делаем

1. **`keywords` для 56 младших арканов** — по 4 канонических слова школы Уэйта, ru + en.
   22 старших не трогаем: они уже заполнены и вычитаны.
2. **`search` для всех 78 карт** — 8–12 слов, ru + en, по правилам ниже.
3. **Поиск учитывает `search`** — `matchesQuery` проверяет название, `keywords` и `search`.
4. **`build_cards.py` перестаёт затирать контент** — см. «Мина в конвейере».
5. **Документация** — правила подбора в content-guide (это редполитика, а не разовая инструкция).

## Что НЕ делаем

- Не трогаем тексты 8 контент-блоков — их вычитывает редактор отдельной волной.
- Не показываем `search` нигде в интерфейсе. Ни чипами, ни подсказками, ни автодополнением.
- Не делаем морфологический поиск: «деньгами» по-прежнему не найдёт «деньги». Это **задача 04з**
  (префиксное сравнение в `cardSearch`), она согласована отдельно и идёт следом.
- Не добавляем `status` к ключевым словам: статусный workflow живёт у контент-блоков, а слова
  вычитываются одним проходом целиком.

## Правила подбора слов (редполитика)

**`keywords` — витрина.** Ровно 4 слова, существительные или короткие именные группы
(«внутренняя сила»), строчными. Канон школы Уэйта, прямое положение карты. Тон — как у старших
арканов, которые уже написаны: не эзотерический жаргон, а человеческие слова.

**`search` — как ищут люди.** 8–12 слов на карту:

- **житейские ситуации**, в которых к карте приходят: «расставание», «переезд», «новая работа»,
  «долги», «выгорание», «ссора», «учёба», «переговоры»;
- **смыслы перевёрнутой карты** — у Дьявола «освобождение», у Башни «давно назревало»;
- **синонимы канонических слов**: к «изобилию» — «достаток», «щедрость».

Форма слова: именительный падеж, единственное число (или множественное, если так говорят:
«деньги», «долги»). Синонимы — да, падежные формы одного слова — нет: это работа задачи 04з.

**Запрещено в `search`:** медицинские диагнозы и лечение (health-блоки уже под этим правилом —
риск при ревью сторов), беременность, смерть близких, любые обещания сбычи («выигрыш»,
«он вернётся»). Порог качества: слово, подходящее больше чем 8 картам, бесполезно — оно вернёт
пол-колоды. «Любовь» ставим только там, где это ядро смысла (Влюблённые, Двойка Кубков,
Десятка Кубков, Императрица), а не каждой карте, где чувства упоминаются.

**EN — не подстрочник.** Английский набор пишется как самостоятельные запросы носителя:
«breakup», «burnout», «job hunting», «moving house». Совпадение по числу слов с русским
не требуется, требуется совпадение по смыслу.

Образец планки (Пятёрка Пентаклей):

```json
"keywords": { "ru": ["нужда", "исключённость", "поддержка рядом", "трудная полоса"] },
"search":   { "ru": ["безденежье", "долги", "потеря работы", "одиночество", "стыд",
                     "просить помощи", "чёрная полоса", "бедность", "поддержка", "восстановление"] }
```

## Мина в конвейере (найдено при разборе задачи)

`scripts/build_cards.py` собирает `cards.json` **с нуля**: `content` — 8 блоков со статусом `todo`
и пустым текстом, `keywords` младших — `[]`. Один запуск стирает 624 draft-блока и всю работу
по этой задаче. Сейчас скрипт падает раньше (нет `/tmp/tarot-api`), но AGENTS.md предлагает его
как штатную команду.

Чиним: скрипт читает существующий `cards.json`, если он есть, и переносит `keywords`, `search`
и `content` в новую сборку по `id`; из источника обновляются только `name`, `image`, `source`.
Словарь `KW` в скрипте остаётся запасным вариантом для карты, которой в файле ещё нет.

## Отчёт о выполнении (11.08)

**Наполнение.** 78 карт: `keywords` 312 слов (4 × 78), `search` 643 ru и столько же по норме en,
794 уникальных ru-слова против 85 до задачи. Заливка — разовым скриптом с валидацией; дубли
между витриной и поиском вычищены автоматически (412 штук: почти весь первый черновик `search`
повторял `keywords`, особенно в EN, после чистки пришлось дописать 249 слов).

**Контрольные запросы** — все 27 в норме 1–8 карт, ни одного пустого:
«любовь» → 5 карт, «деньги» → 3, «работа» → 5, «здоровье» → 6, «расставание» → 2 (Смерть,
Пятёрка Кубков), «переезд» → 2, «выгорание» → 1, «одиночество» → 3, «ссора» → 3, «учёба» → 2;
EN: «love» → 6, «money» → 4, «job» → 6, «breakup» → 3, «burnout» → 1, «betrayal» → 2.

**Слово «здоровье» добавлено вопреки первой редакции спеки.** Проверка показала 0 карт по этому
запросу: правило «без медицины» я применил слишком широко и вычистил саму сферу жизни, у которой
в приложении есть вкладка. Слово стоит у 6 карт (Императрица, Сила, Умеренность, Звезда, Солнце,
Четвёрка Мечей). Диагнозы и лечение по-прежнему исключены.

**Известное ограничение (уходит с задачей 04з).** Два слова дают широкую выдачу: «рост» — 11 карт,
«дом» — 9. Причина не в контенте, а в подстрочном поиске: «рост» находится внутри «щедрость»,
«мудрость», «скорость», «хитрость», «простота»; «дом» — внутри «рядом». Префиксное сравнение
из 04з это чинит, потому что считает совпадение от начала слова.

**Конвейер.** `build_cards.py` переведён на слияние. Проверено прогоном на собранном из текущих
данных источнике: `keywords`, `search` и `content` всех 78 карт после прогона идентичны исходным
(0 расхождений), прочие поля тоже не изменились; `cards.json` в конце теста восстановлен из копии.

**Тесты.** `npx tsc --noEmit` чистый. `npm test` — 5 сьютов, 63 теста (было 55): добавлены 4 теста
поиска по `search` и 4 инварианта наполнения, включая «синонимы не дублируют витрину» и «житейские
запросы находят 1–8 карт».

**Веб-проверка 6а/6б** (390×844, обе темы, скриншоты в `docs/screenshots/04g/`): у младших арканов
под названием появились 4 чипа — раньше там было пусто; проверены Пятёрка Пентаклей и Девятка
Пентаклей (самые длинные формулировки: «самодостаточность», «заслуженный комфорт») — чипы
переносятся на 3 строки, герой не разъезжается, парение картинки не сбилось. Скрытые слова
в интерфейс не просочились: в тексте страницы нет ни «безденежье», ни «долги». Поиск из
справочника: «расставание» → Смерть + Пятёрка Кубков, «выгорание» → Десятка Жезлов. Консоль:
0 ошибок, из предупреждений — только известное `props.pointerEvents is deprecated` из библиотеки.

**Осталось:** вычитка редактором (слова написаны черновиком) и лайв-проверка на iPhone.
