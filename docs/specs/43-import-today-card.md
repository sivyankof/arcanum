# Спека 43 — карта дня после импорта бэкапа с сегодняшней записью

Статус: спека и план написаны 18.08 (сессия планирования); реализация — отдельной сессией.
Мелкая задача (правка одного файла, ~15 строк) — идёт в `main` без ветки, спека согласована
с Артёмом до кода. Заведена 18.08 при спеке 42.

## Цель

Импорт бэкапа, в котором есть запись карты дня за СЕГОДНЯ, при смонтированном табе «Сегодня»
оставляет на экране рубашку: в сторе карта уже есть, а лицо не повернулось. Тап по рубашке
открывает лайтбокс (ветка `if (drawn)` в `onDraw`), подсказка «Нажмите, чтобы открыть» пропала,
блока «Значение дня» нет. Лечится только перезапуском приложения. После задачи: сразу после
импорта экран «Сегодня» показывает открытую карту и текст под ней — то же состояние, что при
входе на таб с уже открытой картой.

## Причина (разбор по коду `app/(tabs)/index.tsx`)

- `drawn = useApp((s) => s.todayDraw())` — сегодняшняя запись из `history`.
- Shared values `flip` / `settledSV` / `plateIn` / `meanIn` инициализируются от `drawn`
  **при монтировании** (открыли приложение с открытой картой → стартуем сразу с 1).
- Эффект по `[drawn, …]` обрабатывает ТОЛЬКО ветку `!drawn` (сброс/новый день → рубашка).
- Переход «рубашка → лицо» делает исключительно `onDraw`: `flip.value = withTiming(1, …)`,
  `plateIn/meanIn = reveal(…)`, затем `drawToday(...)`.
- Таб «Сегодня» — начальный таб, он смонтирован всегда, пока открыт `app/settings.tsx`
  (настройки пушатся ПОВЕРХ табов). `restoreBackup(state)` кладёт в стор `history` с сегодняшней
  записью → `drawn` становится истинным **без `onDraw`** → `flip` остаётся 0, `settledSV` false,
  `plateIn/meanIn` 0. Ни один эффект переход «false → true» не обрабатывает.
- Обратный случай (импорт бэкапа БЕЗ сегодняшней записи при открытой карте) уже работает:
  ветка `!drawn` возвращает рубашку.

Единственный источник перехода «false → true» помимо тапа — `restoreBackup`
(`drawToday` вызывается только из `onDraw`, проверено grep). Но эффект пишется как общее правило
«карта появилась в сторе без тапа», а не как ветка про импорт.

## Что делаем

1. Существующий эффект сброса расширяется до эффекта «состояние карты следует за стором»:
   - `!isDrawn` → рубашка (как сейчас: `flip=0`, `settledSV=false`, `plateIn=0`, `meanIn=0`);
   - `isDrawn` и переход случился **тапом** → ничего не делать: переворот и всплывание ведёт `onDraw`;
   - `isDrawn` и переход случился **без тапа** (импорт) → сразу конечное состояние без анимации:
     `flip=1`, `settledSV=true` (воркл `frontStyle` тут же снимает 3D-пропы — резкость, спека 42),
     `plateIn=1`, `meanIn=1`.
2. Признак «открыто тапом» — `React.useRef(false)`, который `onDraw` поднимает непосредственно
   перед `drawToday(card.id, false)`, а эффект сбрасывает, когда его прочитал.
3. Зависимость эффекта — **булев** `isDrawn = !!drawn`, а не объект `drawn`: сегодняшняя запись
   меняет идентичность при `setOutcome`/`setNote` (новый объект в `history`), и эффект по объекту
   перезапускался бы при каждом ответе рефлексии; по булеву он срабатывает только на переходах.
   Для ветки `!isDrawn` это ничего не меняет (`undefined` идентичности не меняет).
4. Блик (`glare`) отдельно трогать не нужно: его эффект висит на `drawn` и после импорта
   запускает цикл сам. Покачивание `bob` от `drawn` не зависит.
5. Флаг сбрасывается ТАКЖЕ в ветке `!isDrawn`. Он поднимается до записи в стор, а `drawToday`
   умеет ничего не записать (ранний `return` при `lastDrawDate === сегодня`) — тогда `isDrawn`
   не изменится, эффект не сработает и флаг останется поднятым до следующего перехода, съев его.
   Штатными путями такой рассинхрон недостижим (`resetToday` двигает `lastDrawDate` вместе
   с `history`), но зависший флаг воспроизводил бы ровно чинимый баг, а строка сброса стоит ноль.
6. Случай «импорт бэкапа с ДРУГОЙ картой за сегодня, когда карта уже открыта» правкой не
   покрывается намеренно: `isDrawn` остаётся `true`, эффект не срабатывает — и не должен.
   Лицо уже показано, меняется только `card` (картинка) и текст под ней. Анимировать нечего.

### Прецедент: `SpreadCard` уже устроен так же

`src/components/SpreadCard.tsx` (задача 36, проверен на устройстве) держит РОВНО ту же тройку
веток в одном эффекте: `!open` → рубашка; `open && !animateFlip` → сразу конечное состояние
(`flip=1`, `settledSV=true`) без анимации; `open && animateFlip` → `withTiming`. То есть
«открыть с анимацией» и «показать уже открытым» там давно разведены, и карта дня — единственное
место, где это разведение отсутствовало. Правка не изобретает приём, а доносит его до экрана,
который его не получил.

Разница одна: у `SpreadCard` признак «с анимацией или без» приходит пропом `animateFlip` от
родителя, а у карты дня родителя нет — источник истины стор, поэтому признак приходится держать
`ref`-флагом, который поднимает `onDraw`.

⚠️ Соблазн пойти дальше и перенести саму анимацию переворота из `onDraw` в эффект (тогда
структура совпала бы со `SpreadCard` буквально) — **отклонён**: `onDraw` кроме переворота ведёт
хаптику, искры, салют серии и прелюдию пушей, связанные по времени с `FLIP_MS`, а экран
«Сегодня» — эталон, проверенный на устройстве. Цена такой перестановки — риск на эталонном
экране ради стилистического единообразия; выгода нулевая, поведение то же.

Целевой код (ориентир для реализации; комментарии — на русском, как везде):

```tsx
const isDrawn = !!drawn;
// открытие тапом: переворот и всплывание текста ведёт onDraw, эффекту ниже вмешиваться нельзя —
// иначе он перебил бы идущий withTiming конечным значением
const drawnByTap = React.useRef(false);

// состояние карты следует за стором. Зависимость — булев isDrawn, а не объект drawn:
// setOutcome/setNote меняют идентичность сегодняшней записи, и по объекту эффект
// перезапускался бы при каждом ответе рефлексии; по булеву — только на переходах
React.useEffect(() => {
  if (!isDrawn) {
    // сброс карты дня или новый день — рубашка снова впереди, текст спрятан
    drawnByTap.current = false; // подвисший флаг (см. ниже) не должен пережить сброс
    flip.value = 0;
    settledSV.value = false; // лицу вернуть 3D-переворот
    plateIn.value = 0;
    meanIn.value = 0;
    return;
  }
  if (drawnByTap.current) {
    drawnByTap.current = false;
    return;
  }
  // карта дня появилась в сторе БЕЗ тапа — импорт бэкапа с сегодняшней записью при
  // смонтированном табе (спека 43): сразу конечное состояние без анимации, как при входе
  // на таб с уже открытой картой (см. инициализацию shared values выше). settledSV=true —
  // воркл frontStyle снимает 3D-пропы, иначе лицо осталось бы в 3D-контексте (мыло, спека 42)
  flip.value = 1;
  settledSV.value = true;
  plateIn.value = 1;
  meanIn.value = 1;
}, [isDrawn, flip, settledSV, plateIn, meanIn]);
```

и в `onDraw` одной строкой перед записью в стор:

```tsx
    drawnByTap.current = true; // эффект по isDrawn не должен перебивать анимацию (спека 43)
    drawToday(card.id, false);
```

## Что НЕ делаем

- **Не анимируем переворот при импорте.** Всплывание текста и переворот «положены только
  переходу рубашка → лицо тапом» (комментарий у инициализации shared values); при входе на таб
  с уже открытой картой анимации нет — импорт приводит к тому же состоянию тем же способом.
  К тому же в момент импорта таб «Сегодня» не виден (сверху экран настроек) — анимировать не для кого.
- Не трогаем хаптику, искры, салют серии, прелюдию пушей — это события тапа, импорт их не порождает.
- Не защищаемся от импорта во время идущего переворота: физически невозможно, настройки
  открываются с профиля, тап по карте дня — на другом табе.
- Не чиним попутно замеченное: эффект блика по объекту `drawn` перезапускает цикл блика после
  `setOutcome`/`setNote` (блик гаснет и через 500 мс идёт заново). Косметика, вне задачи —
  запись в бэклог отдельным пунктом (см. план, шаг 5).
- Persist version не меняется (схема стора не трогается) — правило «следующая задача, меняющая
  схему, поднимает до 10» остаётся в силе.
- Юнит-теста нет: чистой логики за пределами React-эффекта не появилось (одно булево условие),
  а компонентных тестов в проекте нет. Страж — сценарий веб-проверки ниже, прогнанный СНАЧАЛА
  на текущем коде (обязан показать рубашку), потом на исправленном.

### Красный прогон: проверка проверена

Сценарий прогонялся ДО правки и обязан был упасть — иначе он не проверяет ничего (правило
проекта, выведенное в hf-02: «если тест не краснеет на сломанном коде — он не тест, а декорация»).
На исходном коде сценарий 1 упал именно там, где предсказывала спека:

| Замер | Сломанный код | Исправленный код |
|---|---|---|
| `transform` обёртки лица | `matrix3d(-1, 0, 0, 0, …)` — это `rotateY(180deg)` с `perspective` | `matrix(1, 0, 0, 1, 0, -0.007)` — только покачивание |
| `backfaceVisibility` лица | `hidden` | `visible` |
| `opacity` блока «ЗНАЧЕНИЕ ДНЯ» | `0` | `1` |
| подсказка «НАЖМИ, ЧТОБЫ ОТКРЫТЬ» | отсутствует | отсутствует |

Последняя строка — причина, по которой баг выглядел так странно: подсказка берётся из `drawn`
и пропадала сразу, поэтому пользователь видел рубашку БЕЗ приглашения её открыть, а тап уводил
в полноэкранный просмотр рубашки. Сценарии-регрессы 2–5 на сломанном коде были зелёными — то есть
проверка ловит именно этот дефект, а не «что-нибудь».

### Уроки веб-проверки (пригодятся следующим задачам этого экрана)

⚠️ **Признак «слой в 3D-контексте» на вебе читается формой матрицы**: браузер сворачивает
`perspective` + `rotateY` в `matrix3d(…)` из 16 чисел, а плоское покачивание оставляет `matrix(…)`
из 6. То есть весь класс дефектов «осиротевшие 3D-пропы» (спека 42) на вебе проверяется одним
сравнением префикса строки — без скриншотов и без глаза. На устройстве это по-прежнему судит
только пункт 6в: веб покажет, что слой вышел из 3D-контекста, но не покажет, насколько резкой
стала картинка.

⚠️ **Бесконечная анимация покоя ломает `.click()` Playwright**: карта дня качается ±6 px всегда,
поэтому ожидание «стабильности» bounding box не выполняется никогда и клик падает по таймауту
30 с. Лечится `click({ force: true })` — видимость проверяется отдельно, force снимает только
проверку неподвижности. Это касается любого элемента этого экрана и герой-картинки страницы карты.

⚠️ **`devReflect: true` сам по себе блок рефлексии не показывает** — `reflectionVisible()` требует
ещё и `settings.reflectionOn`: DEV-флаг обходит только проверку часа, а не тумблер. Сценарий,
сеющий один флаг, молча не находит кнопок ответа.

⚠️ Лицо и рубашка различаются в DOM по наличию `<img>`: у рубашки его нет вовсе (SVG-эмблема),
у лица ровно один, причём обе грани в дереве ВСЕГДА — разница только в трансформации. Оверлей
просмотра ищется по цвету скрима `rgba(4,5,14,0.88)` (`SCRIM` в `CardLightbox.tsx`), который
нарочно НЕ равен `rgba(0,0,0,0.4)` углового ярлычка (спека 39), а кнопка закрытия — по
`aria-label` (react-native-web превращает в него `accessibilityLabel`).

### Что найдено по ходу и вынесено наружу

- **Задача 44 в бэклоге**: эффект блика висит на ОБЪЕКТЕ `drawn`, поэтому ответ рефлексии или
  заметка перезапускают блик (он гаснет и через 500 мс идёт заново). Чинится той же зависимостью
  `isDrawn`, что введена здесь; в 43 не тронуто как выходящее за постановку.
- **Класс бага закрыт целиком**: перебраны все `useSharedValue`, инициализированные от внешних
