# Спека 36 — расклады: интерактив «разложить» (этап 5 плана)

Статус: спека и план согласованы 15.08 (брейншторм с Артёмом, решения ниже). Реализация —
сессия на Opus 5, код по шагам плана отдаётся sonnet-сабагентам; ветка `feat/36-spreads`,
merge после лайв-проверки. Детальный план — `docs/plans/36-spreads.md`.

Последняя большая фича v1: сегодня таб «Расклады» — только список из 8 панелей, тап никуда
не ведёт. Поведение целиком описано в product-spec §4, алгоритмы — в logic-spec §1а/§1б/§4/§7,
макет — `v-spread3` («Три карты», полный цикл) и `v-spread10` («Кельтский крест», лента).
Задача — единственное условие заморозки строк UI для задачи 28 (переводы).

## Решения (брейншторм 15.08, ответы Артёма)

| Вопрос | Решение |
|---|---|
| Лента 7–10 карт: где текст значения | **Сразу под строкой** — после открытия строка получает имя + ключевые слова (макет), а под ними в той же панели абзац `general`/`reversed` (product-spec п.4). Тап по открытой строке → страница карты. Аккордеон и «только имя» отклонены. |
| Шаг «Настрой» | **По product-spec: отдельный шаг с CTA «Разложить карты»** — вопрос → кнопка → хаптика + рубашки каскадом. Вопрос при этом ФИКСИРУЕТСЯ (задан ДО карт — расклад честный). Макет рисует рубашки сразу без кнопки → флаг дорисовки. |
| Навигация и черновик | **Вложенный стек внутри таба «Расклады»** (`app/(tabs)/spreads/_layout.tsx` + `index.tsx` + `[id].tsx`): таб-бар остаётся (как `.nav` под `v-spread3` в макете), между табами ходить можно, экран таба не размонтируется — черновик = состояние экрана, ничего не персистится. Просмотр сохранённого из дневника — **отдельный тонкий маршрут корневого стека** `app/spread/[ts].tsx` (иначе тап в профиле переключал бы таб, а «назад» вёл бы в список раскладов, не в дневник). Оба маршрута рендерят один компонент `SpreadScreen` (`mode: 'play' \| 'view'`). Корневой стек для всего (таб-бар скрыт) и черновик в zustand — отклонены (первое против product-spec, второе YAGNI). |
| Остальное (заложено без вопросов, Артём согласился) | мини-схема позиций в списке (product-spec 🔨); «Карта дня» → таб «Сегодня»; PREMIUM без шторки; над лентой 7–10 ряд ячеек прогресса (макет + design-system); переворот 500 мс для ≤5 (product-spec, макет — fade → флаг); +5 XP при «Сохранить»; `SpreadDraw` с `ts` и без `position`; «Разложить заново» = чистый лист включая вопрос; просмотр — только чтение; дневник — единая лента дня + расклада. |

## Цель

- Тап по раскладу в списке открывает полный цикл: настрой с вопросом → тасование → открытие карт
  тапом в любом порядке → значения → «Состав расклада» без ИИ → «Сохранить в дневник» / «Уйти без
  сохранения?» → «Сохранено ✓» + «Разложить заново».
- Сохранённый расклад живёт в дневнике профиля второй записью-строкой и открывается в режиме
  просмотра.
- Всё офлайн, все тексты — из `cards.json`, `spreads.json`, `composition.json`; ни одной строки
  контента не выдумываем в коде.

## Что делаем

### А. Данные и чистые модули (всё под юнит-тестами)

**`src/lib/content.ts`** — тип `Spread` (`id, free, cards, name: Localized, description: Localized,
positions: Localized[]`), `spreads: Spread[]` вместо `any[]`, `spreadById: Map`.

**`src/lib/spread.ts`** (новый):
- `DrawnCard = { cardId: string; reversed: boolean }`;
  `SpreadDraw = { ts: number; date: string; spreadId: string; cards: DrawnCard[]; question?: string;
  note?: string }` — `ts` (мс, момент тасования) = идентификатор записи (двух раскладов в один день
  может быть сколько угодно), `date` — локальный день тасования (`localDateISO`), `cards` в порядке
  позиций `spreads.json` (поле `position` из старой записи logic-spec избыточно — logic-spec §1а
  правится в этой задаче).
- `SPREADS_MAX = 100` (logic-spec §7), `QUESTION_MAX = 200`, заметка — `NOTE_MAX` из journal.ts.
- `dealSpread(count, rng = Math.random): DrawnCard[]` — Fisher–Yates по всем 78 id, первые `count`;
  каждой `reversed = rng() < REVERSED_P` (0.30). `rng` — параметр ради тестов.
- `normalizeText(text, max)` — общий «trim + slice» (journal.ts: `normalizeNote` становится его частным
  случаем; правило DRY).
- Тест-кейсы: 1000 тасований «Кельтский крест» — ни одного дубля внутри расклада; доля reversed
  по 10 000 картам — 30 % ± 3 п.п.; `rng = () => 0.5` → все прямые, `() => 0.1` → все перевёрнутые;
  сидированный rng → детерминированный результат.

**`src/lib/composition.ts`** (новый) — офлайн-состав по logic-spec §1б, ТОЧНЫЕ пороги:
- вход — `DrawnCard[]` (карты берутся из `cardById`); `n` = число карт;
- **1. majors:** `m` — старших; срабатывает при `2·m ≥ n` → `{x: m, n}`;
- **2. suit:** младших `k ≥ 2`; счёт по мастям, лидер `best` **единственный** (нет ничьей) и
  `best ≥ 2` и `2·best ≥ k` → ключ `suit.<масть>`; при ничьей масти не срабатывает;
- **3. reversed:** `r` перевёрнутых, `2·r ≥ n`;
- **4. ranks:** только младшие; группы — `aces` (номер 1), `tens` (10), `courts` (11–14, все вместе —
  «люди и роли»), `generic` по каждому номеру 2–9. Кандидаты — группы с числом ≥ 2; берётся ОДНА
  (правило одно — наблюдение одно): с наибольшим счётом, при равенстве — порядок aces → tens →
  courts → generic по возрастанию номера; `{x: count}` (+ `rank` — номер для generic);
- наблюдения = все сработавшие из 1–4 в этом порядке (1–4 штуки); ничего не сработало → одно `neutral`.
  ⚠️ logic-spec обещает «2–4»; по правилам может выйти и одно — «Преобладают Кубки» + нейтральная
  «состав ровный» противоречили бы друг другу, поэтому не добиваем; logic-spec §1б уточняется.
- `analyzeSpread(cards): Observation[]` (`{key, vars}`) и `compositionTexts(obs, dateISO, lang): string[]` —
  текст варианта выбирается `fnv1a32(`${dateISO}:${key}`) % variants.length` (logic-spec §9), плейсхолдеры
  `{x}`, `{n}`, `{rank}` подставляются после выбора; имя номинала — `rankNames[номер]` из
  `composition.json` через `inLang`.
- Выбор варианта — ОБЩИЙ с `pickPhrase`: из `phrases.ts` выделяется `pickVariant(variants, seedKey,
  lang, vars)`, `pickPhrase` строится на нём (сейчас `pickPhrase` читает только phrases.json).
- Тест-кейсы (по картам колоды):
  1. Императрица, Справедливость↺, Дурак → `[majors {3,3}]`;
  2. Двойка Кубков, Пятёрка Кубков↺, Туз Мечей → `[suit.cups]`;
  3. 10 карт: 5 старших, Тройка/Пятёрка/Семёрка Жезлов, Двойка/Четвёрка Кубков, 5 перевёрнутых →
     `[majors {5,10}, suit.wands, reversed]`;
  4. Туз Жезлов, Туз Кубков, Тройка Мечей, Паж Пентаклей, Рыцарь Жезлов → `[ranks.aces {2}]`
     (aces и courts по 2 — побеждает aces по порядку; suit не срабатывает: 2 Жезлов из 5 младших);
  5. Двойка Жезлов, Двойка Кубков, Луна → `[ranks.generic {2, rank: 2}]`;
  6. Дурак, Тройка Жезлов, Семёрка Кубков → `[neutral]`;
  7. Пятёрка Кубков, Пятёрка Мечей, Пятёрка Жезлов, Луна, Солнце → majors 2·2 < 5 нет; suit: три
     младших по одной на масть — нет; ranks.generic {3, rank: 5} → `[ranks.generic]`;
  8. детерминизм: одна дата + один ключ → 100 вызовов один текст; текст без остатков `{`.
- Ключи наблюдений — строки, текст не хардкодится (`composition.json` редактируется женой как контент).

**`content/composition.json`** (контент, правки механические + две редакторские):
- `ranks.aces/tens/courts/generic` приводятся к форме `{ variants: [...] }`, как остальные ключи;
- добавляется таблица `rankNames`: `{"2": {ru: "Двойка", en: "Two"}, … "9": {ru: "Девятка", en: "Nine"}}`;
- ⚠️ числительные (класс бага hf-02 / 06а): `{x}` у aces/tens/generic ≤ 4 (в колоде 4 туза, 4 десятки,
  4 карты номинала) — формы «{x} туза», «{x} десятки», «{x} раза» верны для 2–4; **courts может дать
  2–10** → «{x} придворные карты» ломается с 5 → ru переписать в безопасную форму
  («Придворных карт в раскладе — {x}: вокруг вашего вопроса много людей и ролей. Чья роль здесь
  главная?»); `majors` «{x} из {n} карт» верно для всех n;
- опечатка «о устойчивости» → «об устойчивости» (pentacles, вариант 2);
- изменённые/новые фразы — статус «ждут вычитки редактора» (как `phrases.json` в задаче 10), список
  в отчёте спеки.

**`src/lib/spreadLayout.ts`** (новый) — геометрия раскладов, ОДИН источник для мини-схемы в списке
и для доски ≤5 карт на экране:
- `SPREAD_LAYOUTS: Record<spreadId, {x, y}[]>` — координаты позиций в дробных единицах «карта + зазор»
  (x вправо, y вниз), по одной точке на позицию в порядке `spreads.json`. Значения переведены из макета
  (`SPS[].pos`, шаг колонки 19 px = ячейка 13 + 6, шаг ряда 22 = 20 + 2):
  `card-of-day` (0,0); `three-card`, `situation-action-outcome` (0,0)(1,0)(2,0);
  `month-ahead` (0,0)(1,0)(2,0)(3,0); `relationship` Вы (0,0.5) · Партнёр (2,0.5) · Соединяет (1,0) ·
  Мешает (1,1) · Куда (1,2); `choice` Вы (1,2) · A даст (0.2,0) · A цена (0.2,1) · B даст (1.8,0) ·
  B цена (1.8,1); `horseshoe` и `celtic-cross` — макетные `pos` / 19 и / 22 с округлением до сотых
  (используются только мини-схемой: на экране у 7–10 карт лента).
- `miniCells(spreadId): {left, top}[]` — px в коробке макета `.diag` 52×64: `left = x·19`, `top = y·22`,
  ячейка 13×20 (для ≤5 совпадает с макетом ТОЧНО: 0/19/38 и 0/22/44).
- `boardLayout(spreadId, availWidth): {cardW, cardH, width, height, cells: {left, top}[]}` — карта
  88×150, зазор 10, полоса подписи под картой `LABEL_H = 48` (позиция до 2 строк 8.5px + имя карты);
  шаг колонки `cardW + 10`, шаг ряда `cardH + LABEL_H`; если ширина доски > `availWidth` — карта
  уменьшается с сохранением пропорции 88:150 (четыре в ряд на 390-экране: 78×133). Доска центрируется.
- `isBoard(spread) = spread.cards ≤ 5` — доска; 7–10 — лента.
- Тесты: `three-card` при 342 → 88×150, ширина 284; `month-ahead` при 342 → 78×133; `relationship`
  → 284 × (2·198 + 150 + 48); `choice` → ширина 1.8·98 + 88; контракт: у КАЖДОГО расклада из
  `spreads.json` есть раскладка ровно на `cards` точек, `positions.length === cards`.

### Замеры, которые стоит помнить

⚠️ **Контраст `muted` на светлой теме — свойство темы, а не дефект этой задачи.** «Нажмите,
чтобы открыть» (12px) и счётчик прогресса (10.5px) дают **2.48:1** при норме 4.5:1 для мелкого
текста. Но ровно те же 2.48:1 дают тексты, существовавшие ДО задачи 36: описание расклада
в списке (10px) и overline «ПРАКТИКА» (9.5px). То есть цифра относится к токену `muted`
на светлой теме во всём приложении — это тот самый кандидат в отдельную задачу, который записала
задача 25. Мерить контраст надо программно: на скриншоте «бледновато» и «не проходит норму»
неразличимы.

1. **Подписи на досках обрезаются по ширине карты.** Ширина колонки подписи равна ширине карты
   (88px), позиция ограничена двумя строками, имя карты — одной. На «На отношения» обрезаны
   «ПАРТНЁР В ЭТИХ ОТНОШЕНИЯХ» и «КУДА ДВИЖУТСЯ ОТНОШЕНИЯ»; в режиме просмотра обрезаются
   и имена карт («Умеренность (…»). Это предписано спекой («до 2 строк», `LABEL_H = 48`),
   и геометрически всё корректно — ряды не наезжают. Но читаемость страдает у 3 раскладов из 8.
   Решение за Артёмом: оставить как есть, дать третью строку (тогда `LABEL_H` → ~60, доска
   станет выше, наезда не возникнет) или сократить названия позиций в `spreads.json` (контент,
   решение редактора).
2. **`FadeUp index` у строк ленты — 2, а не 1, как обещает спека выше.** Спека писалась до того,
   как ячейки прогресса получили свой `FadeUp index={1}`; при одинаковом индексе оба блока
   стартовали бы одновременно и каскада не было бы вовсе. Право за кодом, спека здесь устарела.
3. **Правило мини-схемы уточнено против плана — и затем переписано ещё раз, уже по замечанию
   владельца.** План описывал простое `left = x·19, top = y·22`. При нём «На месяц» вылезал
   за коробку на 18px (правый край 57 + 13 при ширине 52), а однорядные схемы стояли в верхнем
   углу вместо центра макета. Веб-проверка 16.08 (выше) это ещё не ловила — она сверяла
   с макетом, а не с коробкой. Владелец, посмотрев ветку, указал на то же самое с другой стороны:
   подкова и кельтский крест налезают на название расклада под коробкой. Итоговое правило —
   одно для всех восьми раскладов, без деления на однорядные/многорядные: не влезающая в коробку
   схема масштабируется ЦЕЛИКОМ одним коэффициентом (шаг и ячейка вместе, одна ось не может
   сжаться сильнее другой) и центрируется по фактическому размаху. Подробности и числа —
   в новом подразделе «Правки по замечаниям владельца» ниже и в design-system.md.

### Правки по замечаниям владельца (16 августа, коммиты 4598f2c…091e168)

Владелец посмотрел ветку до лайв-проверки и указал на два визуальных дефекта, которых веб-проверка
6а/6б выше не поймала (оба — вопрос сверки с коробкой/пропорцией, а не с макетом или логикой).

1. **Рубашка карты дня — «жёлтая область» и жёсткая горизонтальная граница на светлой теме.**
   Причина: у `<Svg>` в `src/components/CardBackSurface.tsx` не были заданы размеры, поэтому его
   собственный вьюпорт оставался дефолтным 300×150, и градиент рубашки покрывал только верхнюю
   полосу карты дня (218×376) — остальное дорисовывалось однотонной заливкой. Дефект существовал
   ДО задачи 36 (строка перенесена из `CardBack.tsx` без изменений), на тёмной теме не виден
   (цвета рубашки близки к фону), а на картах расклада (88×150) и мини-картах ленты (34×56)
   не проявлялся вовсе — оба размера целиком помещаются в 300×150. Задача 36 не вносила
   регресс, только сделала дефект видимым чаще (карта дня открывается в потоке настроя). Правка —
   явные размеры `<Svg>`.
2. **Мини-схемы подковы и кельтского креста налезали на название расклада, «Выбор из двух» стоял
   со сдвигом.** Три коммита правок, в порядке: (а) единое правило центровки вместо «однорядная
   центрируется, многорядная — нет»; (б) центровка по фактическому размаху `maxX−minX`, а не
   от нуля — «Выбор из двух» (`minX = 0.2`) на промежуточной версии стоял со сдвинутыми полями
   6/3 вместо честных 4/5; (в) масштабирование ЦЕЛИКОМ (шаг и ячейка одним коэффициентом), а не
   только шага — первая версия сжимала шаг подковы до 13 при интервале между соседними точками
   дуги ~4px, ячейки 13×20 наехали друг на друга на 9px, и вместо веера получился комок. Финальное
   правило и числа — design-system.md, абзац «Мини-схема в списке раскладов»; реализация —
   `miniCells` в `src/lib/spreadLayout.ts`.

⚠️ **Урок: ни один из существовавших инвариантов мини-схемы не поймал промежуточную ошибку (в)
шага 2.** До этой правки тестами были закрыты «схема влезает в коробку» и «схема отцентрирована» —
оба оставались зелёными на схлопнутом веере подковы, потому что схлопнутые ячейки всё ещё умещались
в коробку и центр масс не сдвигался. Поймать её мог только третий инвариант — «форма раскладки
не искажается» (отношение фактических шагов колонки/ряда равно базовому, одна ось не сжимается
сильнее другой) — он и добавлен вслед за фиксом. Это ровно тот класс, который в проекте называют
«тест-декорация»: проверки были, но мимо сути дефекта.

### Что не проверялось вебом в принципе

Хаптика (Heavy при тасовании, Light при открытии, Success при сохранении), 3D-переворот 500 мс,
