# Спека 49 — уровни мастерства карты (чип на странице карты + полоски в справочнике)

Статус: спека на согласовании. Этап 4 (master-plan §3.1 п. 13), хвост (а) задачи 46.
Ветка `feat/49-mastery`. Детальный план — `docs/plans/49-mastery.md` (задача идёт в ветке).
Реализация — на Opus (решение Артёма 21.08; спека и план — Fable).

## Решения

Артём, 20.08 (вопросы 14–16 по дорисовкам) и 21.08 (сегменты):

1. **Ступени по интервалу SM-2**, пороги как в макете: НОВАЯ (нет записи) · ЗНАКОМАЯ (1–5 дней) ·
   УВЕРЕННАЯ (6–20) · МАСТЕР (21+).
2. **Показ в двух местах**: чип на странице карты + полоски в ячейке справочника.
   Полоски можно снять на лайве, если сетка окажется перегруженной.
3. **В тренажёре после оценки ступень НЕ показывать** (кандидат на потом: только при росте ступени).
4. **Сегменты 1/2/3/4**: НОВАЯ подсвечивает 1 сегмент из 4, ЗНАКОМАЯ — 2, УВЕРЕННАЯ — 3,
   МАСТЕР — 4. Демо макета (0/1/3/4 у чипа, произвольные значения у полосок) приводится
   к этому правилу — расхождение макета со спекой решено по 6а-0, макет правится.

## Цель

У изученной карты видно, насколько прочно она сидит в памяти. Данные уже есть — `srs[cardId]`
из тренажёра (задача 45); задача только ВЫВОДИТ их: чистая функция + два места показа.
Ничего не хранится, persist version 10 НЕ меняется.

## Что делаем

### А. Чистый модуль `src/lib/mastery.ts` (+ тесты)

```ts
export type MasteryLevel = 1 | 2 | 3 | 4;
/** i18n-суффиксы ступеней по уровню: mastery.new / familiar / confident / master */
export const MASTERY_KEYS: Record<MasteryLevel, string>;
/** Ступень ИЗУЧЕННОЙ карты (изученность проверяет вызывающий — learnedCardIds). */
export function masteryLevel(s: SrsState | undefined): MasteryLevel;
```

Правило: записи нет → **1** (НОВАЯ — изучена уроком, ещё не повторялась);
`intervalDays` 0–5 → **2** (ЗНАКОМАЯ); 6–20 → **3** (УВЕРЕННАЯ); 21+ → **4** (МАСТЕР).

Два осознанных решения:

- **Порог «1–5» расширен нулём.** «Не помню» сбрасывает `intervalDays` в 0 (srs.ts) — без нуля
  карта после провала выпадала бы из шкалы вовсе.
- **Ступень падает при провале** — МАСТЕР после «не помню» становится ЗНАКОМАЯ, не НОВАЯ
  (запись есть, карта в работе) и не остаётся МАСТЕРОМ (SM-2 честно говорит: знание потеряно).

Изученность функция НЕ проверяет: у обоих экранов множество `learnedCardIds` уже есть,
а тащить в чистый модуль курс и прогресс — лишняя связность. Неизученная карта не имеет
ступени по определению — вызывающий не зовёт функцию для неё.

Юнит-тесты на все границы: `undefined` → 1; `intervalDays` 0, 1, 5 → 2; 6, 20 → 3;
21, 365 → 4 (кейс на каждую границу, а не «по одному на ступень»).

### Б. Чип `src/components/MasteryChip.tsx` + страница карты

Компонент по `.mastery` макета: 4 точки 4×4 (radius 2, зазор 2) + ярлык ступени.
Геометрия: inline-flex, gap 5, границa 1px, radius 12, паддинг 3/9; ярлык 8.5/ls 1.5/700 капсом.
Точки цветом текста ступени: включённая — opacity 1, выключенная — 0.3; включено ровно
`level` точек (решение 4).

Цвета по ступеням (токены из `theme.ts`, хардкод запрещён):

| Ступень | текст | граница | фон |
|---|---|---|---|
| 1 НОВАЯ | `muted` | `line` | `panel` |
| 2–3 ЗНАКОМАЯ/УВЕРЕННАЯ | `accent` | `frame` | `chipBg` |
| 4 МАСТЕР | `success` | `success` | `successBg` (новый токен) |

Новый токен `successBg = 'rgba(90,160,126,0.12)'` в ОБЕИХ темах (`rgba(90,160,126,.12)`
из макета `.mastery.m4`); контраст ярлыка на светлой теме замерить программно (правило
задач 25/48), при провале нормы — решение с Артёмом по прецеденту 48.

Страница карты (`app/card/[id].tsx`): чип отдельной строкой МЕЖДУ overline «0 · СТАРШИЙ АРКАН»
и строкой названия, отступ сверху 6 (позиция макета, строка 872). Показывается ТОЛЬКО
изученной карте: `learnedCardIds(course, lessonsProgress)` (мемоизировать, как в справочнике) +
`srs` из стора → `masteryLevel(srs[id])`. У неизученной строки нет совсем.

### В. Полоски в ячейке справочника (`CardCell`)

Новый проп `mastery?: MasteryLevel`. Полоски `.mbar` макета: ряд из 4 полосок 8×2
(radius 1, зазор 2), по центру, **между миниатюрой и подписью** (отступ сверху 4).
Включённая полоска — `accent`, opacity 1; выключенная — `muted`, opacity 0.28;
включено `mastery` штук. Проп не задан — полосок нет (высота ячейки без них не меняется).

⚠️ Расхождение с демо макета — осознанное (6а-0): CSS-комментарий макета говорит «полоска
под миниатюрой», а демо-скрипт кладёт её `appendChild`-ом В КОНЕЦ ячейки, под подпись, —
из-за переменной высоты подписей (1–2 строки) полоски в ряду прыгали бы по высоте.
Реализуем по комментарию (под миниатюрой — ровная линия по ряду), демо макета правим так же.

Справочник (`app/(tabs)/cards.tsx`): в рендере ячейки
`mastery={learned.has(c.id) ? masteryLevel(srs[c.id]) : undefined}` — множество `learned`
уже вычисляется для бейджа и приглушения, добавляется только подписка на `srs`.

### Г. i18n — 4 ярлыка × 4 языка

Ключи `mastery.new` / `mastery.familiar` / `mastery.confident` / `mastery.master`, строки
капсом (как `cards.learned` = «ИЗУЧЕНО ✓»):

| | ru | en | es | pt |
|---|---|---|---|---|
| new | НОВАЯ | NEW | NUEVA | NOVA |
| familiar | ЗНАКОМАЯ | FAMILIAR | CONOCIDA | CONHECIDA |
| confident | УВЕРЕННАЯ | CONFIDENT | SEGURA | SEGURA |
| master | МАСТЕР | MASTER | MAESTRA | MESTRA |

Род — женский, согласован со словом «карта» (carta/carta — ж.р. в es/pt; правило безличного
рода читателя не затронуто: ярлык описывает карту, не пользователя). Es/pt пишутся здесь же
(4 коротких UI-слова), помечаются на вычитку Cowork при следующей сессии — прецедент фраз
пушей (`push.freeze_saved`); хвост в бэклог.

### Д. DEV-строка «Мастерство: рассадить ступени» (настройки, `__DEV__`)

Без неё ступени 3–4 недостижимы на лайве раньше чем через 6/21 день. Экшен раскладывает
изученным картам `srs`-записи по кругу: 1-я карта — без записи (НОВАЯ), 2-я — `intervalDays 1`,
3-я — `6`, 4-я — `21`, дальше повтор. `due` — завтра и позже, чтобы очередь тренажёра
не наводнялась; `reps`/`ease` — согласованные правдоподобные значения. Прецеденты:
`devSkipYesterday` (задача 10), DEV-строки повторения (45а).

## Риски и ловушки для имплементера

- **Подписка на `srs` в справочнике** — новая зависимость рендера сетки: каждая оценка
  в тренажёре меняет объект `srs`. Сетка и так перерисовывается по `lessonsProgress`
  (бейджи), но проверить, что `FlatList` не дёргается на каждый тик тренажёра
  (селектор — сам объект, мемоизация рядов уже есть через `toRows`).
- **Чип в строку между overline и названием** — на странице карты overline и название лежат
  в `hx` рядом с героем; чип не должен растягиваться на всю ширину колонки
  (`alignSelf: 'flex-start'` или обёртка-строка — как ляжет по вёрстке).
- **`success` в светлой теме**: токен подбирался под тёмную; на `successBg` в светлой контраст
  ярлыка может не пройти норму — мерить, не оценивать на глаз (урок 25).
- **Полоски и `expo-image`**: между миниатюрой и подписью уже живут скелетон и бейдж
  (абсолютные, внутри `imWrap`) — полоски кладутся ВНЕ `imWrap`, следующим элементом,
  их эти слои не задевают.
- **DEV-экшен пишет в `srs`** — не забыть `due` в будущее, иначе после «рассадки» очередь
  тренажёра покажет 78 карт к повторению и сломает ручную проверку соседней фичи.
- **Веб-прогон**: сид стора через `localStorage` (`goto → evaluate → reload`, НЕ `addInitScript`);
  ярлыки вкладок и маршруты — из исходников, не из памяти (урок 28а).
