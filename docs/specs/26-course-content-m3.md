# Спека 26 (заход 1 из 4): контент М3 «Старшие арканы II: испытания и свет»

Статус: черновик на согласование Артёму. Дата: 14.08.2026.
Задача 26 бэклога, решение 13.08: теория и викторины М3–М6 по схеме М1–М2, по одному модулю
за заход. Этот заход — только М3. М4–М6 — следующие заходы, каждый со своим коммитом-циклом
по этой же спеке (новая спека не нужна, меняется только номер модуля и staging-файл).

## Цель

22 урока курса стоят без текстов — путь обрывается после М2. Наполнить М3 (6 уроков, 14 старших
арканов VIII–XXI), чтобы курс продолжался: движок готов (задача 08), тексты появляются — уроки
сразу играют.

## Что делаем

### 1. Теория — 6 текстов прямо в `content/course.json`

Формат в точности как у М1–М2: поле `theory: {ru, en, status: "draft"}` у каждого урока М3.

- Объём ru ~1700–1900 знаков (диапазон М1–М2: 1697–1927).
- Структура по образцу М2 (эталон — m2l1 «Дурак и Маг»):
  связка с аркой «путешествие Дурака» → карта за картой (что изображено у Уэйта → смысл →
  ключевые слова → сила/риск) → синтез пары/тройки (чему учат вместе) → упражнение
  «Попробуйте сегодня» с конкретным бытовым действием.
- ru и en пишутся сразу оба; en — не подстрочник, глоссарий из content-guide
  (Strength/Hermit/Wheel of Fortune…, названия как в cards.json).
- Согласованность: смыслы карт не противоречат текстам значений в `content/cards.json`
  (general/symbolism) и чипам `keywords` — сверять при написании.
- Тон — content-guide: на «вы», тепло, без эзотерического жаргона, про рефлексию,
  НЕ про предсказание. Трудные карты М3 (Смерть, Дьявол, Башня, отчасти Луна) — бережно:
  назвать трудность честно + дать опору и выход. «Сбылось» и обещания сбычи запрещены.

Уроки и карты (из course.json, состав не меняем):

### 2. Викторины — 30 вопросов в новом staging-файле `content/quiz-m3.json`

- Схема файла та же, что у quiz-m1-m2.json: `{_comment, status: "draft", lessons: [{lessonId,
  questions: [5 шт.]}]}`; вопрос: `type single|card`, ровно 3 варианта, `correct` 0..2,
  `q`/`options`/`explain` двуязычные, у card — `cardId` из колоды.
- По образцу М2: 1–2 card-вопроса на урок (изображение над вопросом, «узнай карту»),
  остальные single на понимание теории.
- Пояснения `explain` — БЕЗ утвердительных зачинов («Верно!», «Да!», «Именно!»):
  показываются после любого ответа, префикс «Верно. / Не совсем.» добавляет код (задача 21).
  Формулировка подходит под оба исхода.
- Правильные ответы распределены по индексам (контракт-тест: не всё на одном индексе).

### 3. Код-правка: скрипты учатся работать с несколькими staging-файлами

Решение Артёма 14.08: файл на модуль + глоб (для М4–М6 скрипты трогать уже не придётся).

- `scripts/merge_quiz.py`: константа `QUIZ` → перебор всех `content/quiz-*.json`;
  каждый файл несёт свой `status`, уроки каждого файла получают его в `quizStatus`.
  Валидация и формат записи не меняются.
- `scripts/set_status.py`: часть `quiz` двигает статус во ВСЕХ `content/quiz-*.json`
  (у каждого файла статус свой — reviewed у М1–М2 не откатывается и не перескакивает).
- `src/lib/__tests__/courseContent.test.ts`: контракт расширяется на m3
  (16 уроков, те же проверки схемы) — в том же коммите, что и контент.

## Что НЕ делаем

- М4–М6 — следующие заходы (по модулю за раз, решение 13.08).
- Не трогаем состав уроков, названия, `cards`, флаг `free` — только добавляем `theory`/`quiz`.
- Не меняем движок урока, типы `QuizType`/`QuizQuestion`, схему стора (persist не трогается).
- Не двигаем статусы дальше draft — reviewed ставит только редактор после вычитки.
- Тексты значений карт (cards.json) не правим ни словом.
