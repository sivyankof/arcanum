# Спека 16 · Профиль = эталон

Статус: спека на согласовании · Эталон: docs/design-reference.html (`#v-profile`) ·
Значения: docs/design-system.md («Панель уровня (профиль)») · Логика: docs/logic-spec.md §4 (XP), §5 (аркан), §7 (persist)

## Цель

Шапка профиля становится эмоциональным «путём» из эталона: overline «ВАШ ПУТЬ» + имя,
карточка уровня с XP-полосой, карточка аркана рождения. Сюда же хвост задачи 09: кто пропустил
дату рождения в онбординге — получает в профиле приглашение указать её (product-spec §0 это
обещает, а места для предложения до сих пор нет). Дневник (низ экрана) не трогаем — он готов
задачами 05/06а.

## Разведка: что уже есть (ничего из этого заново не пишем)

- Данные: `profile` (name?, birthDate?, birthArcanaId?, onboarded), `xp`, `streak`, `history` — в сторе.
- `levelFromXp(xp)` → {level, progress} (`src/lib/xp.ts`); титулы `level.t1..t6` и строка
  `level.line` («Уровень {{n}} · {{title}}») — в i18n.
- `Rule` (разделитель ✦), `ProgressBar` + `PROGRESS_EASE` (полоса с градиентом accent→accent2),
  `cardNumeral(card)` (римские номера старших), `cardById`/`cardImages`, `DatePicker` +
  `DatePicker.web.tsx`, `PressableScale`, `FadeUp` — готовые компоненты/хелперы.
- Страница карты уже показывает чип «✦ ВАШ АРКАН РОЖДЕНИЯ» (задача 09) и понимает параметр
  `from` для подписи «назад» (`BACK_TITLES` в `app/card/[id].tsx`).
- Шестерёнка настроек в правом верхнем углу — уже есть, не трогаем.

## Решения брейншторма (рассмотрено и выбрано)

1. **Третья стата «ЗАМОРОЗКА ❄» — НЕ делаем.** Механики заморозки нет (задача 10 не начата),
   показывать «0» или выдуманное «1» — врать на лайв-проверке. Оставляем две статы (СЕРИЯ 🔥,
   КАРТ ДНЯ); третью коробку добавит задача 10 — приписка к ней уже есть в постановке 16
   в backlog. Расхождение с макетом осознанное и временное.
   Альтернатива «показать 0 заранее» отклонена: пустая стата без механики вызывает вопросы,
   а данные всё равно появятся только с задачей 10.
2. **Полоса уровня — по макету: доля = xp / порог следующего уровня.** В макете подпись
   «340 / 500 XP» и заливка 68% согласованы (340/500). Вариант «доля внутри уровня» (как у
   XpPill на «Сегодня») дал бы полосу, спорящую с цифрами рядом («500/750 XP» при пустой
   полосе). Семантики двух полос сознательно разные: пилюля без цифр показывает путь внутри
   уровня, карточка с цифрами — общий счёт к порогу; противоречия пользователь не видит,
   обе отвечают «сколько до следующего уровня». Зафиксировано здесь, чтобы ревью не «чинило».
3. **Имя не указано** (в онбординге имя опционально) → на месте имени заголовок «Профиль»
   (существующий ключ `profile.title`), overline «ВАШ ПУТЬ» остаётся. Ничего не выдумываем.
4. **Дата рождения не указана** → вместо карточки аркана — карточка-приглашение с пунктирной
   рамкой (паттерн «можно заполнить» от NotePlate): Overline «АРКАН РОЖДЕНИЯ» + строка-CTA
   «Указать дату рождения». Тап → `DatePicker` (готовый, из онбординга). Выбор даты → экшен
   стора `setBirthDate` → карточка тут же становится обычной карточкой аркана.
   В макете пустого состояния карточки аркана НЕТ — это осознанная дорисовка по паттернам
   приложения; записать в backlog как задачу дорисовки макета (правило 6а-0).
5. **Persist version НЕ поднимаем.** `setBirthDate` заполняет СУЩЕСТВУЮЩИЕ опциональные поля
   `profile.birthDate`/`profile.birthArcanaId` (тип `Profile` не меняется, новых ключей схемы
   нет). Предупреждение backlog про версию 7 касается добавления НОВЫХ полей внутрь `profile` —
   здесь этого не происходит. Явно фиксируем, чтобы ревью не требовало миграцию.
6. **Редактирование имени/даты в настройках — НЕ здесь** (product-spec §5 упоминает строку
   «Имя и дата рождения» на экране настроек): отдельная задача, в backlog она уже подразумевается
   постановкой настроек; профиль по задаче 16 только ПРЕДЛАГАЕТ дату тем, у кого её нет.

## Что делаем

Порядок блоков сверху вниз (эталон `#v-profile`), всё в `ListHeaderComponent` существующего FlatList:

1. **Шапка**: Overline «ВАШ ПУТЬ» (класс `.date`: 9.5px, letterSpacing 3.5, muted, uppercase,
   по центру) → имя (класс `.h2`: fonts.display 28, head, по центру, marginTop 3) → `<Rule />`.
   Без имени вместо него — `profile.title` («Профиль»). Шестерёнка остаётся как есть.
2. **Карточка уровня** — новый компонент `src/components/LevelCard.tsx` (класс `.lvlcard`):
   панель `t.panel`, рамка `t.line`, radius 15, padding 13×15, marginTop 14. Строка: слева
   «Уровень N · Титул» (fonts.display 16, вес 600, head — существующий ключ `level.line`),
   справа по базовой линии «X / Y XP» (10px, вес 700, muted), где X = весь xp, Y = порог
   следующего уровня. Под строкой — `ProgressBar` (высота 7, radius 4, marginTop 8), заливка
   xp/Y, анимация заполнения при появлении: задержка 400мс, ход 1400мс, `PROGRESS_EASE`
   (эталон `fill2 1.4s .4s cubic-bezier(.25,1.2,.4,1)`). Как у XpPill, анимация по монтированию:
   возврат на таб полосу не переигрывает.
   Данные: в `src/lib/xp.ts` добавить экспорт `nextLevelXp(level)` (порог следующего уровня,
   та же таблица THRESHOLDS/STEP_AFTER) + юнит-тесты в существующий сьют xp.
3. **Статы** — существующий ряд, привести к макету (класс `.statbox`): цифра fonts.display 24
   (сейчас 30), подпись 8.5px letterSpacing 2 muted; подпись серии — «СЕРИЯ 🔥» (добавить
   эмодзи в ключ `profile.streak`, en «STREAK 🔥»). Коробок ДВЕ (решение 1).
4. **Карточка аркана рождения** — новый компонент `src/components/BirthArcanaCard.tsx`
   (класс `.barc`): панель `t.panel`, рамка `t.frame` (⚠️ не line — как у макета), radius 15,
   padding 12×14, marginTop 14, в ряд с gap 12: изображение карты ширина 44 (radius 6, рамка
   frame, свечение `boxShadow: 0 6px 18px t.glow` — тень по прямоугольнику, проп boxShadow);
   справа Overline «АРКАН РОЖДЕНИЯ» (8.5px, letterSpacing 2, accent) + «VIII · Сила»
   (fonts.display 17, head; `cardNumeral(card)` + `card.name[lang]`).
   Тап (PressableScale + hapticTap) → страница карты: `router.push('/card/[id]', {id, from: 'profile'})`;
   в `BACK_TITLES` страницы карты добавить `profile: 'card.backProfile'` (подпись «Профиль» уже есть).
   **Пустое состояние** (решение 4): та же геометрия, рамка пунктиром `t.line`, без изображения:
   Overline «АРКАН РОЖДЕНИЯ» + CTA-строка «Указать дату рождения» (13px, text). Тап → `DatePicker`
   (title — тот же ключ CTA); `onPick` → `setBirthDate(iso)`.
5. **Стор**: экшен `setBirthDate(iso: string)` — `profile: {...profile, birthDate: iso,
   birthArcanaId: birthArcanaId(iso)}`. Версия персиста не меняется (решение 5).
6. **Каскад FadeUp** (эталон d1–d4): 0 — шапка; 1 — Rule + карточка уровня; 2 — статы + аркан;
   3 — дневник (навигатор, карточка месяца, чипы); строки записей — ступенькой позже
   (BODY_STEP 3 → 4).
7. **i18n**: `profile.overline` («ВАШ ПУТЬ» / «YOUR PATH»), `profile.arcana` («АРКАН РОЖДЕНИЯ» /
   «BIRTH ARCANA»), `profile.arcanaCta` («Указать дату рождения» / «Add your birth date»),
   `profile.xpOf` («{{xp}} / {{next}} XP» — без плюрализации, «XP» инвариант), правка
   `profile.streak`. Оба языка сразу.

## Что НЕ делаем

- Третья стата «заморозка» — задача 10 (решение 1).
- Редактирование имени и даты в настройках — отдельная задача (решение 6).
- Дневник, навигатор месяцев, чипы, строки — готовы (05/06а), не трогаем.
- Ачивки, экспорт дневника, обратная связь — свои задачи (11–13).
- Изменения XpPill на «Сегодня» — семантика её полосы остаётся прежней (решение 2).

## Критерии приёмки («готово, когда…»)

- [ ] Шапка: «ВАШ ПУТЬ» + имя из профиля + разделитель ✦; без имени — «Профиль»; шестерёнка на месте.
- [ ] Карточка уровня: настоящие уровень/титул/XP из стора; «X / Y XP» и полоса согласованы
      (доля = X/Y); полоса заполняется один раз при появлении с перелётом за цель.
- [ ] Статы: две коробки по размерам макета, «СЕРИЯ 🔥» с эмодзи.
- [ ] Карточка аркана: изображение + «римский номер · название» на языке приложения; рамка frame,
      свечение; тап → страница карты, «назад» подписан «Профиль», на странице виден чип
      «✦ ВАШ АРКАН РОЖДЕНИЯ».
- [ ] Без даты рождения: пунктирная карточка-приглашение; тап → пикер даты; после выбора —
      карточка аркана без перезапуска; выбранная дата видна и в чипе на странице карты.
- [ ] Дневник под новыми блоками работает как раньше (фильтры, месяцы, редактирование сегодняшней).
- [ ] Каскад появления: шапка → уровень → статы/аркан → дневник → строки; возврат на таб —
      только лёгкое проявление (правило FadeUp).
- [ ] `npx tsc --noEmit` чистый; `npm test` зелёный: новые тесты `nextLevelXp` в сьюте xp
      (границы уровней 1→2 50, 4→5 500, 5→6 750, 6→7 1000).
- [ ] Веб-проверка 6а: скриншоты 390×844 обеих тем в `docs/screenshots/16/`, сверка с макетом
      по docs/ui-verification.md; расхождения исправлены или перечислены с причиной
      (ожидаемые: нет третьей статы — решение 1; пустая карточка аркана — дорисовка, решение 4).
- [ ] Прокликивание 6б: аркан → карта → назад; приглашение → пикер → выбор даты; шестерёнка;
      навигатор месяцев и чипы; консоль без ошибок.
- [ ] Лайв-проверка Артёма на iPhone (6в): хаптика тапа по карточке, системное колесо даты
      на русском (проп locale — ловушка 09), свечение карточки аркана.
- [ ] Backlog: задача 16 отмечена; заведена задача дорисовки макета (пустая карточка аркана);
      в задаче 10 приписка «добавить statbox заморозки в профиль» (уже есть в постановке 16 — перенести).
