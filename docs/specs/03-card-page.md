# Спека 03 · Страница карты = эталонный дизайн

Статус: согласована 10.08.2026 · Эталон: docs/design-reference.html (экран #v-detail) · Значения: docs/design-system.md

## Цель

Страница карты (`app/card/[id].tsx`) визуально неотличима от эталона: парящий герой-блок,
вкладки сфер вместо «простыни» из 8 блоков, заголовки блоков с линией-хвостом.

## Решения брейншторма (10.08.2026)

- **Золочёные уголки — НЕ делаем.** В design-reference.html их нет нигде, визуального образца
  не существует; решение Артёма — вычеркнуть из задачи. Упоминание убрать из design-system.md §5
  и из описания задачи 03 в backlog.md (макет дорисовывать не нужно).
- **Вкладки — один блок с подменой текста** (вариант А): текст гаснет → подменяется → проявляется,
  как в эталоне. Не 5 блоков с переключением видимости и не свайп-пейджер.
- **Золотой градиент — в токены**: вкладки станут вторым местом использования после CTA «Сегодня»,
  по правилу переиспользования выносим в theme.ts, хардкод из index.tsx убираем.

## Что делаем

1. **Токены золота** (`src/theme/theme.ts`): экспорт `gold = { gradient: ['#caa45a', '#efd9a2', '#caa45a'],
   text: '#241c0d' }` — вне тем (золото одинаково в обеих). CTA на «Сегодня» (`app/(tabs)/index.tsx`)
   перевести на токены: colors градиента, подложка `#caa45a` → `gold.gradient[0]`, цвет текста → `gold.text`.
   Визуально CTA не меняется.

2. **Компонент `Block`** (`src/components/Block.tsx`, новый): панель по design-system §5 —
   фон panel, бордер line 1px, radius 16 (radius.l), паддинг 16 (spacing.l), marginTop 12.
   Заголовок-Overline: fontSize 9, letterSpacing 2.5, uppercase, цвет accent; справа от него
   линия-хвост (высота 1, flex 1, gap 8, LinearGradient line → прозрачный; прозрачность через
   альфу цвета, как в `Rule` — 'transparent' на iOS даёт серый ореол). Текст: Cormorant 16/24
   (fonts.display), marginTop 7.
   Пропсы: `title`, `text`, `todo?` (текст цветом muted + курсив — для блоков status=todo),
   `contentStyle?` — анимируемый стиль внутренней обёртки (заголовок + текст), нужен блоку сферы
   для fade; сама панель не анимируется. На странице карты — 4 применения; дальше пригодится
   дневнику (задачи 05–06).

3. **Герой-блок** (`app/card/[id].tsx`):
   - **Парение**: изображение мягко покачивается — translateY 0 → −8 → 0, полный цикл 4.5 с,
     ease-in-out, бесконечно (`.hero .im` эталона: `animation: hov 4.5s ease-in-out infinite`,
     `@keyframes hov` — −8px на середине). Reanimated `withRepeat`, `ReduceMotion.System`.
     При открытии из сетки — сперва «перелёт» (350 мс, есть), парение стартует после него;
     при обычном открытии — сразу. Виньетку-свечение не трогаем (уже по эталону, motion-spec ✅).
   - **Название карты**: fontSize 30/34 → **26/32** (design-system §2, Display L «название карты
     на её странице»; в макете h3 = 26). Сейчас стоит размер заголовка экрана — это ошибка.

4. **Вкладки сфер** (`app/card/[id].tsx`):
   - Контейнер под героем: фон panel, бордер line 1px, radius 14, паддинг 4, gap 5, marginTop 18
     (`.tabs` эталона).
   - 5 кнопок: Общее · Любовь · Работа · Финансы · Здоровье. Каждая: flex 1, paddingVertical 8,
     radius 11, текст 10/700 (Manrope через `Txt`), letterSpacing 0.4, цвет muted, по центру.
     Кнопки через `PressableScale` (пружина по motion-spec §5).
   - Активная: золотой градиент, текст `gold.text`, тень glow (эталон `0 4px 12px var(--glow)`).
     ⚠️ УСТАРЕЛО, см. «Правки по замечаниям Артёма» в конце файла: у вкладки и у CTA в эталоне разные
     градиенты (вкладка — `gold.tabGradient`, два стопа), а тень делается пропом `boxShadow`,
     а не старыми `shadow*` (они не работают на Android и в вебе).
   - Тап: `hapticTap()` (Light, motion-spec §8 «фильтры и табы») + переключение сферы.
     Повторный тап по активной — ничего. Начальная вкладка — «Общее»; состояние не персистится,
     при каждом открытии страницы сброс.

5. **Блок сферы под вкладками** (один экземпляр `Block`):
   - Заголовок по активной вкладке: Общее значение / В любви / В работе / В финансах / Для здоровья
     (карта TITLES эталона). Текст — `card.content[сфера]` на текущем языке;
     status=todo → «Текст готовится» курсивом цветом muted (как сейчас).
   - Переключение вкладки: заголовок и текст гаснут (opacity → 0, 130 мс), подмена контента,
     проявление (opacity → 1, 350 мс) — тайминги из JS эталона. Анимируется контент блока,
     не сама панель (высота меняется вместе с текстом без анимации — как в эталоне).

6. **Постоянные блоки** (после блока сферы, всегда видны, порядок по product-spec §3):
   Перевёрнутая → Как карта дня → Символика. Каждый — `Block` с существующими ключами i18n
   (`card.reversed`, `card.day_card`, `card.symbolism`). Блоки general/love/career/finances/health
   из «простыни» удаляются — их контент живёт во вкладках. Итого на странице: вкладки + 4 панели.
   Каскад FadeUp: герой = 0, вкладки = 1, блок сферы = 2, далее 3–5 (соответствует d2–d5 эталона).

7. **i18n** (`src/lib/i18n.ts`, оба языка):
   - Подпись вкладки «Общее»: ru «Общее», en «General» (ключ `card.tabGeneral`; остальные вкладки —
     существующие `card.love/career/finances/health`, они совпадают с подписями).
   - Заголовки блока сферы: для general — существующий `card.general` («Общее значение» / «General
     meaning»); новые ключи `card.sphereLove` / `card.sphereCareer` / `card.sphereFinances` /
     `card.sphereHealth`: ru «В любви», «В работе», «В финансах», «Для здоровья»;
     en «In love», «At work», «In finances», «For health».

8. **Синхронизация доков** (в том же ПР, финальным шагом):
   - design-system.md §5: сделано параллельной сессией (коммит 0af5fbd) — правило сформулировано даже
     точнее: уголки живут ТОЛЬКО на карте дня. Повторно не править.
   - motion-spec.md, анти-чеклист: в исключения бесконечных анимаций добавить парение героя
     страницы карты (сейчас «только карта дня и кольца» — устареет с этой задачей).
   - product-spec.md §3: пометки 🔨 у парения/виньетки/вкладок → сделано.
   - backlog.md: из описания 03 убрать уголки; [x] — только после лайв-проверки.
   - CLAUDE.md «Статус» — после лайв-проверки.

## Результат проверки 6а/6б (10.08.2026, веб, 390×844)

Пройдено, замерено в браузере (скриншоты — `docs/screenshots/03/`):

- Вкладки совпали с эталоном по всем значениям: пилюля radius 14, padding 4, gap 5, marginTop 18,
  фон panel, бордер line; вкладка radius 11; активная — подложка #caa45a под градиентом, текст
  #241c0d, Manrope Bold 10 / letterSpacing 0.4; неактивные — muted.
- Переключение: замер прозрачности блока даёт 0.66 → 0 (≈130 мс) → 0.22 → 1 (≈350 мс). Все 5 сфер
  показывают свой заголовок и свой текст; повторный тап по активной вкладке ничего не меняет.
- Название карты — Cormorant 26/32. Парение измерено: колебание y в пределах ~8px.
- Светлая тема и EN-локаль: вёрстка держится, подписи вкладок не переполняются (макс. 46px в 63px).
- Консоль на чистой загрузке: 0 ошибок. Остаются штатные предупреждения react-native-web
  (`shadow*`, `pointerEvents`, `textShadow*` deprecated) — они были и до задачи, не наши.

Найдено и исправлено по ходу (сверх спеки):

- **Порядок хуков**: `useAnimatedStyle` для fade оказался ниже раннего `return null` — перенесён выше.
- **Шапка экрана карты**: при `headerTransparent: true` фон всё равно наследовался из общих
  `screenOptions` (`headerStyle.backgroundColor = t.bg`) и рисовал непрозрачную полосу 64px поверх
  контента — оверлайн и верх изображения срезались, парение усугубляло. Сброшен в `transparent`,
  `headerShadowVisible: false`, отступ контента 56 → 64.

Расхождения макета и реализации (осознанные, по правилу 6а-0 «спека главнее макета»):

- **Текст значений**: в макете `.block p` — 12.5px системным шрифтом; в приложении Cormorant 16/24,
  как требует design-system §2 (Body serif). Так было и до задачи. Оставлено по спеке.
- **Кнопка «назад»**: в макете — «‹ ВСЕ КАРТЫ», в приложении — системная стрелка. Вне рамок 03,
  занесено в backlog отдельной мелкой задачей.

Не проверяется в вебе (только лайв-проверка на iPhone): хаптика Light на вкладках, перелёт картинки из сетки —
замер показал, что в вебе он не отрабатывает вовсе (кадров промежуточных положений нет; код перехода
задачей 03 не менялся, на устройстве проверялся 09.08). Записано в «известные отличия веба» в CLAUDE.md.

## Правки по замечаниям Артёма после первой лайв-проверки (10.08.2026)

Артём посмотрел сборку на iPhone и в вебе, нашёл 5 расхождений. Все проверены по макету и закрыты.

**1. Кнопка «назад» показывала «‹ (tabs)».** Это системная шапка стека подставляла имя предыдущего
маршрута. В эталоне шапки нет вовсе: кнопка `.backbtn` живёт внутри контента (шеврон 14px + «ВСЕ КАРТЫ»,
11px/700/letterSpacing 1.2, цвет accent). Сделано: `headerShown: false` у экрана карты, своя кнопка
первым элементом контента, отступ сверху вернулся к safeArea + 24 (design-system §3).
Плюс найдено при прокликивании: подпись «ВСЕ КАРТЫ» врала при заходе с экрана «Сегодня» (CTA под
значением карты дня) — возврат уходил на «Сегодня». Теперь маршрут несёт источник (`?from=cards` /
`?from=today`), подпись зависит от него, а при открытии по прямой ссылке (истории нет) кнопка уводит
в справочник через `replace` вместо выброса на корневой экран.

**2. Золото активной вкладки отличалось от макета.** Оказалось, в эталоне у вкладки и у CTA РАЗНЫЕ
градиенты, а мы применили один токен на оба:
`.tabs button.on` — `linear-gradient(120deg,#caa45a,#e9d095)` (два стопа);
`.btn` (CTA) — `linear-gradient(120deg,#caa45a,#efd9a2 50%,#caa45a)` (три стопа).
Оба под 120°, а у нас были горизонтальные — отсюда «менее плавный» жёлтый. Сделано: в `gold` добавлен
`tabGradient` (два стопа) для вкладок, `gradient` (три стопа) остался за CTA, угол у обоих —
диагональ вправо-вниз (`end={{x:1,y:0.6}}`). Замер в браузере: `linear-gradient(105.9deg, #caa45a, #e9d095)` —
угол зависит от пропорций элемента, на узкой вкладке даёт 106° вместо 120°; расхождение визуально
незаметно, точное соответствие потребовало бы пересчёта угла под размер каждой кнопки.

**3. Свечения не было в вебе (и не было бы на Android) — пункт, который стоил дороже всех.**
Причина: из старых пропов `shadowColor/shadowOffset/shadowOpacity/shadowRadius` на Android
поддерживается ТОЛЬКО `shadowColor`, остальные iOS-only (документация RN, раздел Shadow Props),
а react-native-web их депрекейтнул и не рисует. То есть золотое свечение было видно лишь на iPhone.
Сделано: все свечения переведены на проп `boxShadow` (RN 0.76+, новая архитектура — в проекте
`newArchEnabled: true`; работает на iOS, Android 9+ и в вебе). Значения переносятся из CSS макета
один в один, потому что токен `glow` — это ровно `var(--glow)`. Замер в браузере после правки:
герой `rgba(226,189,114,0.35) 0px 18px 40px`, активная вкладка `rgba(226,189,114,0.35) 0px 4px 12px` —
совпадает с эталоном. `elevation` убран, чтобы на Android не было двойной тени.
⚠️ На Android 8 и старше `boxShadow` не поддерживается — тени там не будет (доля таких устройств мала;
minSdk проекта это допускает). Записано как известное ограничение.

**4. Блок «Как карта дня» показывался всегда.** По макету и product-spec он действительно постоянный,
НО параллельная сессия в тот же день уточнила поведение: если открытая карта = сегодняшняя карта дня,
блок поднимается выше вкладок, получает золотую рамку и заголовок «✦ ВАША КАРТА СЕГОДНЯ».
Реализовано: подписка на примитив (`useApp((s) => s.todayDraw()?.cardId)`), компонент `Block` получил
пропы `accentBorder` и `star`; на обычном месте блок в этом случае не дублируется (проверено).

**5. Шрифт текстов значений — РЕШЕНО 10.08: Cormorant.** Подтверждено: в макете `.block p`
не переопределяет семейство и наследует `--sans` (Manrope 12.5), а design-system §2 требует
«Body serif — Cormorant 16–17/25». По двум скриншотам (`docs/screenshots/03/font-cormorant.png`
и `font-manrope.png`) Артём выбрал вариант с засечками. Значит правы спека и текущий код —
в приложении ничего не меняем. Отстаёт МАКЕТ: правку `.block p` → `var(--serif)` 16/1.5
занесли отдельной задачей 04в (Cowork-сессия), чтобы эталон не спорил с design-system.

## Вторая итерация замечаний Артёма (10.08.2026)

**Кнопка «назад» — решение изменено на нативную шапку.** Первый вариант (своя кнопка в контенте,
как в макете) Артёма не устроил: он хочет родное поведение платформы. Вернули системную прозрачную
шапку со стрелкой цвета accent, а подпись у стрелки задаётся на самом экране через `headerBackTitle`
и зависит от источника перехода: «Карты» или «Сегодня» вместо «(tabs)». Кастомная кнопка и её стили
удалены, отступ контента вернулся к `insets.top + 64`.
⚠️ Расхождение с макетом принято осознанно: в эталоне нарисована своя кнопка «‹ ВСЕ КАРТЫ» в контенте.
На Android подпись у стрелки не показывается — это норма платформы, не баг.

**Вибрация при возврате.** На системную кнопку обработчик не повесить, поэтому хаптика вызывается
на событие ухода с экрана (`navigation.addListener('beforeRemove')`) — срабатывает и на кнопке,
и на свайп-жесте назад, что даже полнее исходной задумки.

**Регрессия: квадратная тень вокруг иконки таб-бара.** Возникла из-за перевода ВСЕХ свечений на
`boxShadow`. Оказалось, что в эталоне свечения бывают двух разных типов, и подменять их друг другом нельзя:
- `box-shadow` (тень по прямоугольнику) — карта дня `.face`, CTA `.btn`, герой `.hero .im`,
  активная вкладка `.tabs button.on`. Здесь `boxShadow` — правильный выбор.
- `filter: drop-shadow` (свечение по КОНТУРУ, по альфа-маске) — иконка таба `.nav>div.on svg`
  и эмблема-компас `.emb svg`. Здесь `boxShadow` даёт прямоугольник вокруг иконки — это и увидел Артём.
Платформенная тонкость: `filter: dropShadow` в RN поддерживается только на Android 12+ и в вебе,
на iOS из фильтров есть лишь brightness/opacity. Зато на iOS старые `shadow*`-пропы рисуют тень
именно по альфа-маске слоя. Поэтому появился хелпер `src/theme/glow.ts` (свечение по контуру):
iOS — `shadow*`, остальные платформы — `filter: drop-shadow`. Используется в двух местах.
Правило на будущее: смотреть в эталоне, `box-shadow` там или `drop-shadow`, и не смешивать.
