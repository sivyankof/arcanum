# 59 · Настройки: строки «Имя» и «Дата рождения»

Статус: **спека готова (23.08), ждёт «ок» Артёма**. Найдено аудитом 56: `product-spec.md` §5
перечисляет строки настроек и прямо требует «Имя и дата рождения (редактирование; если дата
не указана — кнопка „рассчитать аркан")». В приложении этой строки нет.

## Что не работает сейчас (проверено по коду 23.08)

- **Имя не редактируется нигде.** Экшена `setName` в сторе нет вовсе (`src/store/useApp.ts`):
  имя пишется один раз онбордингом через `completeOnboarding` → `buildProfile`. Опечатался
  на первом запуске — живёшь с ней. Показывается имя в одном месте: заголовок таба «Профиль»
  (`app/(tabs)/profile.tsx:114`, `name ?? tr('profile.title')`).
- **Дату рождения можно задать один раз и только пока она пустая.** `BirthArcanaCard` без даты
  показывает приглашение и открывает `DatePicker`; с датой — карточка аркана, и её тап уже
  занят переходом на страницу карты (`BirthArcanaCard.tsx:59`). Экшен `setBirthDate` в сторе
  есть и сам пересчитывает `birthArcanaId`.
- Комментарий в шапке `app/settings.tsx` до сих пор гласит «имя и „о приложении" остаются
  на очереди — задачи 12 и 13»: обе задачи давно закрыты, «о приложении» сделано, строка имени
  потерялась вместе с этим комментарием.

## Цель

Имя и дату рождения можно поменять после онбординга — из настроек, без сброса прогресса.

## Решения

- **Д1. Две строки, не одна.** «Имя» и «Дата рождения» отдельными `SettingsRow` между
  «Напоминания» и «Экспорт данных» (порядок строк — `product-spec` §5). Причина: у строки
  настроек справа ровно одно значение, и объединённая строка показала бы только половину
  состояния. Решение Артёма 23.08.
  ⚠️ **6а-0**: `product-spec` §5 записывает это одним пунктом «Имя и дата рождения». Расхождение
  осознанное — эта задача правит формулировку в product-spec, а не подгоняет код под неё.
- **Д2. Значения строк.** Имя → само имя либо `settings.nameEmpty` («Не указано»). Дата →
  `formatFullDate(birthDate, lang)` либо `settings.birthEmpty` («Указать»). Форматирование даты —
  существующий `formatFullDate` из `dates.ts`, тот же, что в онбординге и на карточке аркана.
- **Д3. Ввод имени — новый общий компонент `TextPrompt`.** Диалога с текстовым полем в проекте
  нет: проверено грепом — есть `ConfirmDialog`, `ModalPanel`, `OptionPicker`, `TimePicker`,
  `DatePicker`, а `TextInput` живёт только инлайн (`onboarding.tsx`, `note/[date].tsx`,
  `SpreadFields.tsx`, `SearchField.tsx`). `TextPrompt` = `ModalPanel` + подпись + `TextInput` +
  пара кнопок «Отмена»/«Сохранить» в геометрии `ConfirmDialog` (те же `st.btn`, `radius.m`,
  `paddingVertical: 11`). Пропы: `visible`, `title`, `initial`, `placeholder`, `maxLength`,
  `confirmLabel`, `cancelLabel`, `onSubmit(value)`, `onClose`.
- **Д4. Дата — переиспользуем `DatePicker`.** У него уже есть проп `value: string | null`,
  то есть режим «сменить существующую дату» поддержан. `setBirthDate` пересчитывает
  `birthArcanaId` сам — карточка аркана в профиле обновится следом.
- **Д5. Профиль не трогаем.** Тап карточки аркана остаётся переходом на страницу карты;
  приглашение «рассчитать аркан» на пустой дате остаётся как есть. Второго входа к смене даты
  не делаем — вопрос из бэклога («менять из профиля ИЛИ из настроек») закрыт тем, что тап
  карточки уже занят.
- **Д6. Нормализация имени — общая с онбордингом.** `NAME_MAX = 40` и `normalizeName` живут
  в `src/lib/birthArcana.ts` (там же `Profile` и `buildProfile`), сама нормализация — вызов
  существующего `normalizeText(raw, NAME_MAX)` из `journal.ts`, своего `trim().slice()`
  не пишем. `buildProfile` начинает звать `normalizeName` — сегодня онбординг длину имени
  не ограничивает вовсе, и это та же дыра.
- **Д7. Пустое имя удаляет ключ, а не пишет пустую строку.** `buildProfile` уже так делает
  (`...(trimmed ? { name: trimmed } : {})`); `setName` обязан вести себя так же, иначе
  `profile.name` станет `''` и заголовок профиля покажет пустоту вместо «Профиль».
- **Д8. persist НЕ поднимается.** Поля `name`/`birthDate`/`birthArcanaId` уже объявлены в типе
  `Profile` и лежат в сторе; новых ключей схемы не появляется. `SCHEMA_VERSION` остаётся 11.
- **Д9. Валидатор бэкапа не трогаем.** `isProfile` (`backup.ts:219`) проверяет `orAbsent(v.name, isStr)`
  без ограничения длины. Добавлять туда `NAME_MAX` — значит отвергать целиком бэкап старого
  пользователя с длинным именем; лимит держим на входе (`maxLength` поля + `normalizeName`).

## Что делаем — план по файлам

1. **`src/lib/birthArcana.ts`** — `export const NAME_MAX = 40;` и `export function normalizeName(raw: string)`
   через `normalizeText` из `./journal`; `buildProfile` зовёт `normalizeName` вместо `name.trim()`.
   ⚠️ Проверить, что импорт `journal → birthArcana` не образует цикла (birthArcana сейчас
   импортирует только `./content`).
2. **`src/store/useApp.ts`** — экшен `setName(name: string): void` в интерфейс и в реализацию.
   Пустое имя удаляет ключ: собирать новый объект профиля явно, а не спредом (спред ключ
   не удаляет).
3. **`src/components/TextPrompt.tsx`** — новый компонент по Д3.
4. **`app/settings.tsx`** — две строки после блока «Напоминания»: `SettingsRow` «Имя»
   (иконка `person-outline`) и «Дата рождения» (иконка `calendar-outline`), состояния открытия
   `TextPrompt`/`DatePicker`; шапочный комментарий про «задачи 12 и 13» переписать.
5. **`src/lib/i18n.ts`** — ключи `settings.name`, `settings.nameEmpty`, `settings.namePrompt`,
   `settings.namePlaceholder`, `settings.birthDate`, `settings.birthEmpty` на четырёх языках.
   ⚠️ es/pt пишет сессия → долг вычитки носителем: дописать в периметр волны 57н.
6. **Тесты**:
   - `src/store/__tests__/useApp.test.ts` — `setName`: обычное имя, пробелы по краям, длиннее
     `NAME_MAX`, пустая строка (ключ исчезает), имя не трогает `birthDate`/`birthArcanaId`.
   - `src/lib/__tests__/birthArcana.test.ts` — `buildProfile` обрезает длинное имя и не хранит
     пустое; `normalizeName` в паре с `NAME_MAX`.
   - Полноту новых ключей во всех четырёх языках стережёт существующий контракт `i18nPlurals`.
7. **`docs/product-spec.md` §5** — формулировку строки настроек привести к двум строкам (Д1).
8. **Доки**: backlog, changelog, статус CLAUDE.md, уроки — если найдётся ⚠️.

## Что НЕ делаем

- Не трогаем профиль и `BirthArcanaCard` (Д5).
- Не трогаем онбординг, кроме общей нормализации имени через `buildProfile` (Д6).
- Не поднимаем persist (Д8) и не трогаем валидатор бэкапа (Д9).
- Не добавляем «удалить дату рождения»: в product-spec такого действия нет, а аркан рождения
  после расчёта показывается на профиле и в блоке `birth_path` карты — снятие даты означало бы
  отдельное поведение этих мест.
