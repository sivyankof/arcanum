# Arcanum — обучающее приложение по таро

@AGENTS.md

## Контекст проекта

Приложение для изучения таро (курс как в Duolingo + карта дня + справочник 78 карт + расклады).
Делают Артём (новичок в разработке — объясняй просто, по-русски) и его жена (эксперт-таролог,
главный редактор контента). Полный план: `docs/master-plan.md` — **прочитай его перед крупными задачами**.

## ОБЯЗАТЕЛЬНЫЙ ПРОЦЕСС РАБОТЫ (нарушение = переделка)

Никакого кода «с ходу». Для КАЖДОЙ задачи из docs/backlog.md строго по циклу:

1. **Брейншторм** — используй skill brainstorming из плагина superpowers (если установлен — он
   триггерится сам; если нет — проведи структурный брейншторм вручную): уточни требования,
   рассмотри 2–3 варианта реализации, выбери и обоснуй.
2. **Спека** — запиши в `docs/specs/NN-<имя-задачи>.md`: цель, что именно делаем, что НЕ делаем,
   точные значения из design-system.md, критерии приёмки (чек-лист «готово, когда…»).
   Эталон формата: `docs/specs/01-today-screen.md`.
3. **План** — в той же спеке: шаги по файлам (какой файл, что меняется), порядок, где нужен
   `npm install`. Мелкие шаги: один шаг = одна проверяемая правка.
4. **Согласование** — покажи спеку Артёму, дождись «ок» (для мелких задач <30 строк кода можно пропустить).
5. **Реализация** — по шагам плана, после каждого шага `npx tsc --noEmit`.
6. **Проверка** — трёхуровневая, первые два уровня делаешь САМ, не привлекая Артёма:
   - **6а. Визуальная сверка с макетом (обязательно, каждая UI-задача).** Запусти `npx expo start --web`
     (приложение откроется на http://localhost:8081) и через браузерный MCP (Playwright: если не подключён —
     `claude mcp add playwright -- npx "@playwright/mcp@latest"`) открой ДВА окна: приложение и
     file:///.../docs/design-reference.html. Сделай скриншоты каждого изменённого экрана в размере 390×844
     в ОБЕИХ темах, положи в docs/screenshots/<spec>/, сравни с макетом по чек-листу
     docs/ui-verification.md. Каждое расхождение — либо исправь, либо явно перечисли в отчёте с причиной.
   - **6б. Прокликивание (обязательно).** Пройди по каждому интерактивному элементу изменённых экранов:
     каждая кнопка, таб, фильтр, поле — клик → результат совпадает с ожиданием из спеки; проверь консоль
     браузера на ошибки/warning. Сломанное — чини до зелёного прохода.
   - **6в. Лайв-проверка Артёмом на iPhone (финал).** Только после зелёных 6а+6б. Хаптика, шрифты и
     нативные тени видны только тут — веб им не судья.
   Известные отличия веба от нативного (НЕ считать багами): нет вибрации, системные тени слабее,
   шрифт может грузиться с задержкой.
7. **Синхронизация** — отметь задачу в backlog.md, обнови статус в CLAUDE.md (раздел «Статус»),
   если менялся дизайн — обнови design-system.md. Коммит: `feat: <задача> (spec 0N)`.
8. **Пуш** — после коммита `git push` (если remote ещё не настроен — предложи Артёму создать
   приватный репозиторий на GitHub и настрой origin; без бэкапа в облаке проект живёт в одном
   экземпляре на диске). Задача закрыта только после: лайв-проверка Артёмом на телефоне ✓ + push ✓.

Если Артём просит что-то вне backlog — сначала добавь это в backlog как задачу со спекой, потом делай.

## Жёсткие правила

1. **SDK НЕ обновлять.** Проект на Expo SDK 54, потому что Expo Go в App Store поддерживает только SDK 54
   (политика Expo с мая 2026). Не запускать `expo upgrade`, не менять мажорные версии пакетов.
2. **Язык общения — русский.** Комментарии в коде — тоже русские.
3. После каждой правки код должен проходить `npx tsc --noEmit` без ошибок.
4. Если меняешь `package.json` или `app.json` — явно скажи Артёму: «нужен npm install и перезапуск
   `npx expo start --tunnel`». Обычные правки кода подхватываются Fast Refresh автоматически.
5. **Бэкенда нет и в v1 не будет** — всё офлайн: контент в JSON-бандле, прогресс в AsyncStorage/SQLite.
6. Тексты значений карт **не выдумывать**: их пишет редактор (жена). В коде показывать блоки со
   статусом `todo` как «Текст готовится» (см. `content/cards.json`, статусы: todo → draft → reviewed → final).
7. Git: коммить осмысленными шагами с русскими сообщениями.

## Дизайн — какой файл для чего (ЧИТАТЬ ПЕРЕД ЛЮБОЙ РАБОТОЙ НАД UI)

Направление — **«Небесное золото»**: глубокая ночная синева + шампанское золото, БЕЗ фиолетового.

| Файл | Что это | Когда обращаться |
|---|---|---|
| `docs/product-spec.md` | **Как всё работает**: каждый раздел приложения — элементы, поведение, состояния, граничные случаи | ПЕРВЫМ ДЕЛОМ при любой задаче: сначала пойми поведение здесь, потом смотри вид |
| `docs/design-system.md` | **Все численные значения**: цвета, типографика, отступы, радиусы, тени, спецификации компонентов, состояния, тон текстов | Всегда при создании/правке любого экрана или компонента. При конфликте с кодом — прав этот файл |
| `docs/design-reference.html` | **Визуальный эталон**: интерактивный макет всех экранов (композиция, анимации в CSS с точными параметрами). Читай его код: значения в CSS — источник правды для композиции | Когда делаешь конкретный экран — найди его в макете и сверь композицию; параметры анимаций бери из CSS |
| `docs/motion-spec.md` | **14 анимаций** по приоритетам с параметрами (длительности, кривые, пакеты) + анти-чеклист | Любая работа с анимациями; делать по одному пункту за коммит |
| `src/theme/theme.ts` | **Токены в коде** (обе темы) | Цвета ТОЛЬКО отсюда, хардкод цветов запрещён |
| `docs/master-plan.md` | План проекта: этапы, фичи удержания, монетизация | Перед крупными задачами и при вопросах «зачем/что дальше» |

Порядок работы над UI-задачей: design-system.md (значения) → design-reference.html (композиция экрана)
→ motion-spec.md (если есть движение) → код с токенами из theme.ts → `npx tsc --noEmit`.

## Структура

- `app/` — экраны (expo-router): (tabs)/ = Сегодня, Курс, Карты, Расклады, Профиль; card/[id] — страница карты
- `src/theme/` — токены и useTheme; `src/store/useApp.ts` — Zustand-состояние (тема, язык, серия, история)
- `src/lib/content.ts` — доступ к контенту; `src/lib/cardImages.ts` — АВТОГЕНЕРИРУЕТСЯ (`scripts/gen_card_images.py`), не править руками
- `src/lib/srs.ts` — алгоритм интервальных повторений SM-2 (для флеш-карт, этап 4)
- `content/*.json` — 78 карт / 8 раскладов / курс 6 модулей (двуязычные ru/en)
- `assets/cards/` — 78 изображений Райдер–Уэйт (public domain)

Сделано: каркас 5 табов, карта дня с 3D-переворотом и вибрацией, серия (streak) с персистом,
справочник 78 карт (expo-image с кэшем), страница карты, курс и расклады списками, профиль
(тема/язык + dev-сброс карты дня), i18n ru/en. Проверено на iPhone через Expo Go.

Дизайн подтянут к эталону (спека 11): шрифты Cormorant + Manrope, дата с днём недели, разделитель,
римская цифра у карты, кнопка внутри блока значения, нижнее меню со своими иконками, размытием
и полоской активной вкладки.

**Анимации (`docs/motion-spec.md`):** сделаны пункты 1–8, 10, 12, 13, 14. Осталось два, оба ждут
своих фич: 9 (полоса XP) — движка курса, 11 (пустые состояния) — дневника.

Ловушки SDK, проверенные на живом устройстве:
- `sharedTransitionTag` в Reanimated 4.1.1 нет — перелёт картинки сделан через `measure()`
  (`src/lib/cardTransition.ts`), экран карты открывается с `animation: 'fade'`.
- Бесконечные циклы собирать только через `src/lib/loops.ts`: `withRepeat(withSequence(...))`
  при перезапуске эффекта превращается в вечную «пилу».
- Тень и `overflow: 'hidden'` — всегда на разных View, иначе iOS срежет тень.
- Тени и нативные шрифты в веб-версии не проверяются: react-native-web их не транслирует.
